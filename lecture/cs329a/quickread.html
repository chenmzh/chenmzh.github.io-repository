CS329A / Paper quick reads
第一次读论文先看：速读术语

这页按“问题—机制—证据—边界”压缩论文。下面先解释每张卡会反复使用的词；论文标题、作者和 benchmark 名称保留原文，不把专名误当作概念。

Abstract / evidence level
abstract 是论文摘要；evidence level 标记我们能从摘要、全文或技术报告确认到什么程度。
Task / model / baseline / metric
实验契约四要素：任务、使用的模型、比较基线和衡量结果的指标。
Generator / verifier / selector
generator 产生候选；verifier 检查候选；selector 选择最终输出；三者错误可能不同。
Generation–verification gap
生成器已经产生正确候选，但验证器或选择器没有识别并交付它。
Reward model / oracle
奖励模型给优化用分数；oracle 是假定可信的参考判定器，二者不自动等于真值。
Weak supervision / ensemble / active learning
weak supervision 用间接标签；ensemble 融合多个判断；active learning 优先挑最有信息量的样本。
Coverage / pass@k / selected accuracy
coverage/pass@k 看候选中是否至少成功一次；selected accuracy 是选择器最终交付候选的正确率。
Outcome / process supervision
结果监督只看最终答案；过程监督还检查中间步骤，因此信息更细但标注更贵。
Inference-time / train-time
推理时扩展只增加当前任务预算；训练时扩展会更新参数，目标是跨任务复用。
Trajectory / held-out / OOD
trajectory 是一次运行记录；held-out 是训练未见的留出数据；OOD 是分布外任务。
RAG / retrieval
RAG（检索增强生成）先从外部资料找片段，再把证据交给模型生成答案。
KV cache / TTFT
KV cache 是可复用的注意力键值状态；TTFT 是请求到第一个输出 token 的时间。
Long horizon / checkpoint
长时程任务需要很多连续步骤；checkpoint 保存健康状态，使失败后可以恢复而非从头开始。
Affordance / embodied
affordance 是当前状态下动作的物理可行性；embodied AI 在身体或模拟身体中行动。
Anchor evidence / boundary
锚点证据是本卡唯一重点结果；边界说明该结果不能安全外推到哪里。
best-of-N / Pareto frontier
best-of-N 是生成 N 个候选后选最好者；Pareto 前沿表示准确率和成本等目标的互不支配折中。
MCTS / value function / rollout
MCTS 是蒙特卡洛树搜索；value function 估计节点收益；rollout 是一次展开采样。
SFT / RLAIF / GRPO / PPO
SFT 用示例监督微调；RLAIF 用 AI 反馈强化学习；GRPO、PPO 是策略优化算法，均不等于客观真值。
OOD / zero-shot / self-consistency
OOD 是分布外；zero-shot 是无同类示例；self-consistency 是多次推理后按一致性选答案。
Scaffolding / geometric mean
scaffolding 是外部上下文、工具或人工脚手架；geometric mean 是汇总跨任务比例的几何平均。
Reward / rationale / few-shot
reward 是达标分数；rationale 是中间推理依据；few-shot 是只给少量示例后完成新题。
RLEF / DAPO
RLEF 是利用执行反馈训练代码策略的方法；DAPO 是大规模推理 RL 训练方法。
Decoupled clipping / dynamic sampling
前者分开调节更新约束；后者按训练状态调整样本，而非固定采样。
LLM / ML / code completion
LLM 是大语言模型；ML 是机器学习；code completion 是根据上下文补全代码。
Oracle / agentic retrieval
oracle 是假定可信的参考判定器；agentic retrieval 是智能体根据不确定点主动规划并触发检索。
Long tail / falsifiable prediction
long tail 是少量但严重、易被平均分掩盖的失败；可证伪预测能被具体重复实验推翻。
FLOPs / token / best-of-N
FLOPs 是浮点运算次数；token 是文本计量单元；best-of-N 生成 N 个候选后取最好者。
Pareto frontier
Pareto 前沿表示准确率、延迟和成本等目标的互不支配折中。

Session 02 · Test-time Compute Scaling

Large Language Monkeys

官方 reading · 摘要核验 · 原文 ↗
问题
只让模型尝试一次，会漏掉“其实能生成正确答案”的问题；但多生成后又可能不会选。
先记住
重复采样提升的是候选覆盖率，不自动提升最终 selected accuracy；选择器是第二个瓶颈。
机制
①同一题采样 K 个候选；②用测试、投票或 reward model 选一个；③把“至少一个正确”和“选中正确”分开统计。
实验契约
多任务，包含 coding/formal proof；摘要特别报告 SWE-bench Lite、DeepSeek-Coder-V2-Instruct、K=1 到 250；比较单次、投票、reward model 和可验证选择。
锚点证据
SWE-bench Lite 的特定设置从 15.9%（一次）到 56%（250 次）；这支持“可验证任务适合扩大候选预算”，不是所有任务的普遍倍率。
不可外推
没有可靠 verifier 的任务在数百次后会平台化；更大的 K 还意味着成本、延迟和选择器错误一起增加。
自测
如果 coverage 继续上升但最终准确率不升，你会先改 generator、selector，还是增加 K？为什么？

Archon

官方 reading · 摘要核验 · 原文 ↗
问题
重复采样、修订、不同模型和验证器组合很多，人工凭直觉选 pipeline 容易错过互补组合。
先记住
推理时技巧不是独立加分项；最好的架构依赖任务、模型和 token 预算。
机制
①定义可组合的模型与 inference modules；②在预算内搜索配置；③用准确率—token 成本的 Pareto 结果选架构。
实验契约
instruction-following、reasoning、coding；给定模型池、技巧池和 compute budget；比较搜索出的配置与 frontier model / baseline，指标是任务质量和最大 token 预算。
锚点证据
摘要报告跨任务相对 frontier baseline 的平均改进；最重要的证据不是单个分数，而是搜索能找到不同任务的不同配置。
不可外推
搜索空间、预算和目标 benchmark 改变，最优组合也可能改变；架构搜索本身也有额外成本。
自测
为什么“某技巧单独有效”不能推出“把它和另外两个技巧串起来一定有效”？

Scaling LLM Test-Time Compute Optimally

官方 reading · 摘要核验 · 原文 ↗
问题
固定 FLOPs 时，应该买更大模型，还是让小模型多搜索、多验证、多修订？
先记住
最优推理预算取决于 prompt 难度和基础成功率；“test-time scaling 总是优于 parameter scaling”不是论文结论。
机制
①估计题目难度；②比较 verifier-guided search 与自适应改变响应分布；③按题目分配不同 inference budget。
实验契约
挑战性 prompt、dense process verifier 和自适应 test-time 方法；以固定/匹配 FLOPs 与 best-of-N、较大模型比较，指标为任务准确率和 scaling efficiency。
锚点证据
摘要报告 compute-optimal strategy 相对 best-of-N 的效率提升，以及在部分题目上小模型加推理预算胜过 14× 大模型。
不可外推
收益依赖题目难度、verifier 和基础模型已经“有一点成功率”；模型太弱或 verifier 太差时结论会失效。
自测
为什么要先按题目难度路由预算，而不是所有 prompt 固定采样同样多？

How Do Large Language Monkeys Get Their Power (Laws)?

官方 reading · 摘要核验 · 原文 ↗
问题
单题独立尝试看起来应是指数收益，为什么跨题平均后常被拟合成 power law？
先记住
单题的指数下降和总体的幂律外观可以同时成立，关键是题目之间的成功概率呈重尾分布。
机制
①把每题单次成功率记为 p；②独立采样后单题失败率约为 (1−p)^K；③对很多难度不同的题聚合，极难题拖出幂律尾巴。
实验契约
数学、证明和 multimodal jailbreak 等多次尝试任务；比较 per-problem scaling、aggregate scaling 和成功率分布；核心变量是 attempts K 与 per-task p。
锚点证据
作者用经验分布说明 heavy tail 能解释聚合 power law，并改善 exponent 预测；锚点是分布解释，不是新的 agent pipeline。
不可外推
需要独立尝试、明确的“任一次成功”评价和稳定任务分布；相关采样或改变选择规则会破坏简单推导。
自测
在 p 很低的少数题上增加 K 为什么会主导总体曲线，却不代表每道题都同样受益？

Session 03 · Robust Verification

Shrinking the Generation-Verification Gap with Weak Verifiers

官方 reading · 摘要核验 · 原文 ↗
问题
人类 oracle verifier 太贵，单个 LM judge 又不够准；如何把许多弱 judge 组合起来？
先记住
弱验证器的价值来自互补错误和可靠性加权，不是“多找几个 judge 投票”这么简单。
机制
①收集多个 verifier 输出；②用统计/weak supervision 估计可靠性并归一化；③过滤低质 verifier、加权融合，再用于候选选择。
实验契约
多任务 reasoning/math repeated sampling；generator 生成候选，judge/reward model ensemble 选择；比较 Pass@1、无权/加权组合与轻量 cross-encoder。
锚点证据
摘要报告 ensemble 选择的平均结果及与更强模型的比较；它支持“组合弱信号可逼近强信号”，不支持“judge 越多越可靠”。
不可外推
同源 judge 会共享偏差；校准数据、输出格式和 generator—verifier mismatch 仍可能让 ensemble 自信地选错。
自测
如果三个 verifier 都受同一个错误提示影响，为什么一致性不能算三份独立证据？

Training Verifiers to Solve Math Word Problems

官方 reading · 摘要核验 · 原文 ↗
问题
语言模型生成的数学解答经常只在最后一步出错；能否训练一个模型专门判断候选解是否正确？
先记住
生成器与 verifier 分工能把更多候选转化为更好的最终答案，但 verifier 必须学到真正的正确性。
机制
①用 GSM8K 题目生成多个 completion；②训练 verifier 给 completion 打正确性分数；③测试时按分数重排并提交最高者。
实验契约
GSM8K（约 8.5K 小学数学文字题）；比较 verifier reranking 与直接 fine-tuning；指标是最终数学准确率，重点是随训练数据变化的扩展。
锚点证据
论文报告 verification 显著提升 GSM8K，并比直接微调更能随数据扩展；证据只覆盖这一类数学文字题。
不可外推
答案判定清楚时容易；开放式写作、研究和工具轨迹没有同样强的 oracle，verifier 可能学到表面模式。
自测
候选数量增加但 verifier 不变时，为什么可能只是让错误被更自信地选出来？

Let's Verify Step by Step

官方 reading · 摘要核验 · 原文 ↗
问题
只给最终答案标签会隐藏中间错误；过程监督是否值得付出大量逐步标注成本？
先记住
在 MATH 设置中 process supervision 胜过 outcome supervision，但它不是脱离标注质量和任务的普遍定律。
机制
①给每个 reasoning step 反馈；②训练 process reward model；③在生成/选择时用步级信号提前淘汰错误路径。
实验契约
MATH、过程/结果监督、PRM800K 人类 step-level labels、active learning；比较 process-supervised 与 outcome-supervised 训练，指标是数学测试准确率。
锚点证据
摘要报告代表性 MATH 子集 78% 和 active learning 增益；锚点说明过程标签有用，不说明所有领域都需要人工标注每一步。
不可外推
过程标签可能主观、昂贵或错误；“看起来合理的过程”也不一定保证最终结论正确。
自测
在一个可执行代码任务中，什么 execution feedback 可以替代昂贵的人工过程标签？

Math-Shepherd

官方 reading · 摘要核验 · 原文 ↗
问题
PRM 需要人工逐步标签；能不能自动构造过程监督，并同时用于 reranking 和 RL？
先记住
自动过程奖励降低了标注门槛，但也把最终答案或采样过程的偏差带入 verifier。
机制
①从数学轨迹/最终答案构造 step-wise labels；②训练 Math-Shepherd；③用它重排候选，或把逐步分数送进 PPO。
实验契约
GSM8K、MATH、Mistral-7B 等开源模型；比较 verification 与 step-by-step PPO；指标是数学准确率，预算和伪标签构造决定可比性。
锚点证据
摘要报告 Mistral-7B 的 GSM8K 77.9→84.1、MATH 28.6→33.0 的 PPO 变化，并在 verification 后进一步提升；数字只属于论文设置。
不可外推
自动标签在数学中较容易构造；开放式 agent 任务缺少同等强的答案 oracle，不能直接照搬。
自测
如果伪标签和 generator 共享错误，如何用独立验证集发现 reward hacking？

Session 04 · Tools / Code Feedback

ReAct

官方 reading · 摘要核验 · 原文 ↗
问题
纯 chain-of-thought 会在错误事实上继续推理；纯行动又缺少可解释的计划和异常处理。
先记住
思考轨迹负责计划与更新，工具行动负责获取外部观察；两者交替才形成反馈闭环。
机制
①模型写 reasoning；②发出 API/environment action；③读取 observation；④修正计划并继续，直到 stop。
实验契约
HotpotQA、FEVER、ALFWorld、WebShop；few-shot prompting，Wikipedia/API 或交互环境；与 CoT、模仿/强化学习基线比较成功率和可解释轨迹。
锚点证据
摘要报告 ALFWorld、WebShop 的绝对成功率增益；它证明工具反馈在这些环境有用，不证明任意工具接入都会降低幻觉。
不可外推
API 覆盖、工具错误、权限和 observation 质量决定闭环；错误工具反馈会把模型引向另一条错误轨迹。
自测
一条 ReAct 轨迹中，哪一步提供了模型内部推理没有的证据？

RLEF

官方 reading · 摘要核验 · 原文 ↗
问题
代码模型看到了编译/执行反馈，却常常不会在多步中利用它，反而重新独立采样。
先记住
执行反馈只有被写进策略更新，才会从“诊断文本”变成可学习的迭代能力。
机制
①生成代码；②执行并收集结果；③把反馈纳入下一步轨迹；④用 RL 训练模型提高利用反馈的概率。
实验契约
competitive programming；小/大代码模型、执行环境、独立采样 baseline；指标为任务结果和达到结果所需的样本数。
锚点证据
摘要报告小模型和大模型的新结果及样本数约一个数量级的减少；具体收益依赖反馈可执行且奖励定义正确。
不可外推
编译器错误比开放式需求反馈更清晰；复杂仓库中的测试缺口会使 RL 学到“过测试”而不是修复需求。
自测
如果测试覆盖率很低，RLEF 的奖励会把模型推向什么危险策略？

Constitutional AI

官方 reading · 摘要核验 · 原文 ↗
问题
人工给每个 harmful output 打标签太贵；能否用一组原则让 AI 参与批评、修订和偏好监督？
先记住
它是原则约束下的 self-critique + RLAIF 闭环，不是一个通用、客观的安全 verifier。
机制
①初始模型生成回答；②按 constitution 生成 critique/revision；③SFT 修订回答；④用 AI preference model 做 RLAIF。
实验契约
harmless assistant / harmful query 设置；监督微调 + preference model + RL；比较人工反馈需求、harmlessness 和 evasiveness。
锚点证据
摘要报告较少人工标签下得到 harmless 且不回避的 assistant；证据支持“原则可成为反馈源”，不支持原则本身无偏。
不可外推
constitution、judge 和 reward model 共享价值/模型偏差；对事实性、代码正确性和物理安全不能直接替代外部验证。
自测
如果 AI judge 误解了一条原则，SFT 和 RL 两阶段会怎样放大这个错误？

Session 05 · Planning / Search

SWiRL

官方 reading · 摘要核验 · 原文 ↗
问题
RLHF/RLAIF 常按单步处理，难以训练需要多次思考、工具和环境交互的轨迹。
先记住
把多步轨迹拆成 action 对齐的子轨迹，再筛选和训练，可以为 multi-step RL 提供更细的学习信号。
机制
①生成多步 reasoning/tool-use 轨迹；②按原动作切成 sub-trajectories；③过滤合成数据；④对筛选结果做 RL。
实验契约
GSM8K、HotPotQA、CofCA、MuSiQue、BeerQA；多步工具/问答/数学任务；比较 baseline accuracy，训练任务和跨任务 zero-shot 都被报告。
锚点证据
摘要报告多个任务的相对提升，并称只在 HotPotQA 训练也改善 GSM8K；它支持跨任务迁移的观察，不证明所有 synthetic data 都能迁移。
不可外推
子轨迹边界、过滤器和 reward 设计会影响训练目标；把一条错误长轨迹切得更细不会自动变成正确监督。
自测

问题

锚点证据
摘要报告最多 38.6× 少内存、26.4× 高吞吐和 128k→484k 有效上下文的特定结果；这些数字依赖语料和服务设置。
不可外推
语料更新、删除、隐私、跨 corpus 冲突和 synthetic conversation 偏差都是生产记忆问题。
自测
若原语料更新了，旧 Cartridge 为什么不能自动被当成最新事实？

MemGPT

官方 reading · 摘要核验 · 原文 ↗
问题
LLM context window 有限，长文档和多 session 对话会忘记早期信息。
先记住
把 context 当作分层内存资源，通过 virtual context、换入换出和 interrupt 管理长期信息。
机制
①保留快速 working context；②把不活跃内容移到慢速存储；③模型通过显式 memory 操作换入/换出；④interrupt 管理用户与 agent 控制流。
实验契约
长文档分析、多 session chat；OS-inspired memory tiers、公开代码/数据；指标是超 context 文档处理和长期对话记忆。
锚点证据
摘要报告可分析超过底层窗口的文档并在多 session 中记忆、反思和演化；这里验证的是系统设计，不是 OS 语义等价。
不可外推
分页成功不保证检索到正确记忆；stale、poisoning、隐私删除残留和 context 管理成本仍需测试。
自测
一个 memory manager 如何知道该换出什么，而不是把最近内容误当成最重要内容？

CacheBlend

官方 reading · 摘要核验 · 原文 ↗
问题
RAG 的多个 retrieved chunks 常不是完整 prefix，预计算 KV cache 不能直接拼接而不损失跨块注意力。
先记住
只重算少量关键 token，再把 cache 读取和重算流水线化，可以在质量与 prefill 延迟之间折中。
机制
①离线缓存各知识块 KV；②检索多个块；③选择性重算部分 token 融合 KV；④与 cache retrieval pipeline overlap 后生成。
实验契约
三个开源 LLM、四个 benchmark dataset 的 RAG；比较 full KV recompute 与其他 cache reuse；指标 TTFT、throughput、generation quality。
锚点证据
摘要报告 TTFT 2.2–3.3×、吞吐 2.8–5× 的特定提升且不损生成质量；必须保留硬件和 cache hit 设定。
不可外推
动态知识、cache 过期、跨文档冲突和安全删除会改变实际收益；低延迟不等于答案更正确。
自测
为什么“缓存命中”可以降低延迟，却不能替代对来源时效和冲突的验证？

Session 17 · Long-horizon Evaluation

METR · Measuring AI Ability to Complete Long Software Tasks

官方 reading · 摘要核验 · 论文 ↗ · 说明页 ↗
问题
短 benchmark 分数很难说明 AI 能完成多长的真实任务；需要和人类任务时间对齐的尺度。
先记住
METR 的核心指标是 50% task-completion time horizon，不是 checkpoint 能力或所有 agent 可靠性。
机制
①测人类专家完成任务所需时间；②测模型在任务上的成功率；③找成功率约 50% 的任务时间尺度；④比较模型随时间的 horizon。
实验契约
RE-Bench、HCAST 和新增短任务；人类专家计时、frontier models、工具/软件任务；指标是 human-time horizon 和成功率。
锚点证据
摘要报告特定时期约 50 分钟的 frontier horizon 及历史增长趋势；它支持能力时间尺度比较，不支持“长任务每步独立”的假设。
不可外推
任务外部有效性、模型版本、权限、成功定义和危险能力都需单独审计；本页的 p^T 图是教学合成数据。
自测
一个 agent 任务成功率从 95% 变成 90% 时，为什么长轨迹可交付性会突然恶化？

GDPVal

官方 reading · 摘要核验 · 原文 ↗
问题
问答 benchmark 不能代表模型能否产出真实职业交付物；需要任务质量、速度、成本和监督一起看。
先记住
GDPVal 评估的是一组真实经济活动的 deliverable，不是“模型接管整个职业”的证明。
机制
①按 BLS work activities 构造职业任务；②让专业人士生成/评价参考交付物；③比较模型输出质量、时间和成本；④测试 context/scaffolding/reasoning effort。
实验契约
44 个职业、9 个 GDP 主要行业、平均 14 年经验专家、220-task gold subset；指标是 deliverable quality 与成本/时间。
锚点证据
摘要报告 frontier model 接近专家交付质量及监督、上下文和 reasoning effort 的影响；这些是具体职业任务上的比较。
不可外推
职业代表性、专家评分、自动 grading 和真实组织流程仍有限；质量接近不等于安全自主完成。
自测
如果模型交付物质量接近专家，但需要专家逐项审核，GDPVal 分数该如何解释？

DeepScholar-Bench

官方 reading · 摘要核验 · 原文 ↗
问题
研究 agent 的质量不是短答案对错；既要找资料，又要综合、引用并让读者核验。
先记住
研究综合应拆成 synthesis、retrieval、verifiability 三个维度，而不是用一个“看起来像论文”的分数。
机制
①从近期 arXiv 产生 live query；②agent 检索并写 related-work；③自动计算知识综合、检索质量和可核验性；④与 reference pipeline 比较。
实验契约
generative research synthesis、live benchmark、开源系统/搜索 agent/DeepResearch；指标是三维指标及 geometric mean。
锚点证据
摘要报告没有系统超过 31% geometric mean，说明任务远未饱和；锚点是“评测缺口本身”，不是某个模型冠军。
不可外推
live web 的时间点和 arXiv 分布会变化；自动引用指标不能完全替代专家对论证质量的判断。
自测
一个报告找到正确论文但引用并不支持具体 claim，应在哪个指标上失败？

补充阅读 · 连接 planning、SWE、memory 与 robotics

Tree of Thoughts

补充 reading · 摘要核验 · 原文 ↗
问题
token-level 左到右生成遇到需要探索、回溯和全局选择的任务会早早走错。
先记住
把 coherent thought 当作搜索节点，用评估和回溯换取规划能力；收益来自任务结构，不是“树”本身。
机制
①生成多个 thought；②自评或外部评估；③扩展高价值节点；④必要时回溯。
实验契约
Game of 24、Creative Writing、Mini Crosswords；GPT-4/CoT 与 ToT 比较；指标是任务成功率，搜索预算由节点数和深度决定。
锚点证据
Game of 24 摘要给出 GPT-4 CoT 4% 与 ToT 74% 的特定结果；不能把这当作所有语言任务的提升。
不可外推
自评估可靠性、thought 粒度和分支成本决定效果；与有环境反馈的 LATS 不应混为一谈。
自测
ToT 的节点评估如果只是模型自评，如何引入独立 verifier？

SWE-bench

补充 reading · 摘要核验 · 原文 ↗
问题
代码生成 benchmark 太短，不能测模型理解仓库、跨文件修改和真实 issue 修复的能力。
先记住
SWE-bench 把“交付一个通过验收的补丁”变成可重复任务，但测试通过仍不是完整软件质量。
机制
①提供真实 repo snapshot 和 issue；②模型修改多个文件；③运行项目测试；④按 issue 对应 patch/测试是否解决判定。
实验契约
2,294 个 issue、12 个 Python 仓库；Claude 2、SWE-Llama 等模型；指标 issue resolution，环境版本和测试套件很重要。
锚点证据
初始摘要报告最佳模型只解决 1.96% 的 issue，说明任务难度远高于短代码补全；不要把旧分数和新 benchmark 直接横比。
不可外推
测试缺口、patch acceptance、仓库版本和数据污染影响分数；真实维护还包括 review、部署、回滚和长期责任。
自测
一个补丁通过测试但修改了不该修改的 API，SWE-bench 的验收能否发现？

Generative Agents

补充 reading · 摘要核验 · 原文 ↗
问题
让多个 agent 在长期互动中表现得连贯，需要记住经历、形成高层反思并按情境检索。
先记住
observation、memory retrieval、reflection 和 planning 的组合能产生 believable behavior，但 believable 不等于真实。
机制
①记录自然语言 observation；②按相关性/近期性检索；③合成 reflection；④用记忆和计划产生下一行动。
实验契约
25-agent interactive sandbox；观察、规划、反思架构与消融；指标主要是行为可信度和涌现社交行为。
锚点证据
摘要描述 party 等社会行为并显示三类组件的消融贡献；证据是模拟环境行为，不是现实社会预测准确率。
不可外推
记忆内容可能虚构或陈旧；社会逼真度、用户满意度和事实可靠性是不同指标。
自测
如果 reflection 与原 observation 冲突，agent 应保留哪一个、凭什么？

SayCan

补充 reading · PMLR 摘要/页面核验 · 原文 ↗
问题
语言模型知道“应该做什么”，不代表机器人在当前物理状态“能做什么”。
先记住
把 language model 的 task value 与 skill affordance/value 相乘或组合，才会同时考虑目标相关性和物理可行性。
机制
①语言模型给技能对目标的价值；②低层 affordance 估计当前能否执行；③组合排序；④执行技能并观察结果。
实验契约
机器人技能库、模拟/真实任务和语言指令；比较有无 affordance grounding 的高层规划；指标是技能选择/任务完成。
锚点证据
论文的关键贡献是接口分解，而不是把 LLM 变成低层控制器；必须区分 semantic fit 和 physical feasibility。
不可外推
感知误差、技能失败、环境变化和安全约束会破坏 affordance 估计；语言上最优不等于安全执行。
自测
一个杯子“语义上应该拿起”但被遮挡时，哪一个模块应该否决动作？

PaLM-E

补充 reading · 摘要核验 · 原文 ↗
问题
通用语言模型缺少对连续传感器和真实世界状态的 grounding，难以做具身推理。
先记住
PaLM-E 走的是“把视觉/连续状态编码接入语言模型并联合训练”，与 SayCan 的高层 affordance 组合不是同一架构。
机制
①编码视觉、状态估计和文本；②交错成 multimodal sentence；③与预训练 LLM 端到端联合训练；④输出规划、问答或 caption。
实验契约
多个 embodiment、机器人 manipulation、VQA、captioning；最大 PaLM-E-562B；指标跨具身任务和通用视觉语言能力。
锚点证据
摘要报告多模态具身任务与 positive transfer；这支持联合训练的迁移观察，不代表每种传感器都能无损接入。
不可外推
模型规模、传感器分布、平台和训练数据决定迁移；视觉语言输出仍需低层控制和安全验证。
自测
PaLM-E 的多模态输入解决了“看见什么”，但谁来保证动作“做得安全”？

最后的读法：先读机制，再看数字

第一次学习时，每个 session 只挑一张主论文卡：S02 选 Large Language Monkeys，S03 选 Let's Verify，S04 选 ReAct，S05 选 LATS，S06 选 STaR，S07 选 DGM，S08 选 Search-o1，S13 选 CodeMonkeys，S14 选 MemGPT，S17 选 METR。读完后再看同组其他卡的“问题”和“不可外推”，就能形成对照。

论文最小复述：“在【任务/预算】下，作者用【机制】把【反馈】变成【选择/更新】，在【锚点比较】中观察到【结果】；这只说明【边界】，还没有证明【外推命题】。”
