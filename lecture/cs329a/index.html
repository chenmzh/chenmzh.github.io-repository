CS329A / 20-session reader
第一次阅读先看：CS329A 术语读法

下面的词会在课程中反复出现。以后正文只保留英文缩写，首次定义放在这里，避免把学生直接丢进论文黑话；论文名和产品名不当作概念解释。

Agent（智能体）
能观察环境、采取动作，并根据结果继续行动的系统。
Self-improving agent（自我改进智能体）
把反馈写回下一轮推理、训练或系统配置，让后续行为变好的智能体。
Environment（环境）
动作发生并返回结果的外部世界，例如代码执行器、网页或机器人场景。
Feedback（反馈）
告诉系统动作结果如何的信号，可以是测试、分数、观察或人工意见。
Verifier（验证器）
检查候选答案、步骤或动作是否满足要求的程序或模型。
Trajectory（轨迹）
一次运行中按时间排列的状态、动作、观察和结果记录。
State / action / observation
状态是当前信息，动作是系统做的事，观察是环境返回的新信息。
Policy（策略）
根据当前状态选择下一动作的规则或模型。
Inference-time scaling（推理时扩展）
不改模型参数，只增加采样、搜索或验证预算来提高当前任务结果。
Train-time scaling（训练时扩展）
把筛选后的轨迹或奖励用于更新模型参数，使能力跨任务复用。
System-time scaling（系统时扩展）
通过工具、记忆、规划或传感器增强整个系统，而不只改变模型。
Coverage / selector（覆盖率 / 选择器）
覆盖率是候选中至少出现正确答案的比例；选择器负责从候选中挑最终答案。
Reward model（奖励模型）
把答案或轨迹转换成“更值得保留”的分数，供选择或训练使用。
CoT / RLEF
CoT（Chain-of-Thought）是显式写出中间推理；RLEF 用代码执行反馈训练模型更新策略。
Weak supervision / ensemble
weak supervision 用不完整或间接标签训练；ensemble 融合多个评审器或模型的判断。
Active learning / oracle
active learning 优先标注最有信息量的样本；oracle 是假定可信的参考判定器。
ORM / PRM
ORM（结果奖励模型）只看最终结果；PRM（过程奖励模型）给中间步骤评分。
Calibration（校准）
模型说“0.8 分”时，长期来看是否真的约有 80% 的成功率。
SFT / RLAIF / RL
SFT（监督微调）用示例更新参数；RLAIF 用 AI 反馈强化学习；RL 是通过奖励试错更新策略。
API / tool schema / sandbox
API 是供程序调用的标准化接口；tool schema 是输入输出契约；sandbox 是限制副作用的隔离环境。
ReAct
Reasoning and Acting：让模型在思考、行动、观察之间交替，而不是只生成一段答案。
Planning / search
规划先比较多个候选行动；搜索是在候选空间中展开、评估和剪枝。
MCTS / branch / depth
MCTS（Monte Carlo Tree Search，蒙特卡洛树搜索）分配树搜索预算；branch 是分支数，depth 是展开步数。
Backtracking / checkpoint
回溯是退回旧节点换路；checkpoint（检查点）保存可恢复的状态和失败上下文。
Held-out / OOD
held-out 是训练时没见过的留出数据；OOD（分布外）是与训练分布明显不同的任务。
Reward hacking / data leakage
奖励投机是迎合评分漏洞而非真正完成目标；数据泄漏是训练信息意外进入评测。
Archive / evaluator
archive 保存候选变体及其历史；evaluator（评估器）执行测试并决定候选是否保留。
Claim / evidence / retrieval
claim 是可核验主张，evidence 是支持它的证据，retrieval 是从资料库找相关内容。
RAG
Retrieval-Augmented Generation：先检索资料，再把资料交给模型生成答案。
SWE-bench / benchmark
SWE-bench 是真实软件 issue 基准；benchmark 是规定任务、数据和指标的可比较评测。
Profiling / kernel
profiling 是性能剖析，测量各阶段耗时和资源来找瓶颈；kernel 是在 GPU 等硬件上执行的一段并行计算程序。
HPC mapper / DSL
HPC mapper 把算法映射成具体硬件配置并寻找更快实现；DSL 是为某类任务定制的小型语言。
Memory tiers / prefill
分层记忆把短期上下文和容量更大但更慢的长期存储分层；prefill 是生成前处理输入上下文的阶段。
KV cache / TTFT
KV cache 是注意力的键值缓存；TTFT（首 token 延迟）是请求到第一个输出 token 的时间。
Long horizon（长时程）
需要很多连续步骤才能完成的任务；每一步小概率失败会累积成整体失败。
Affordance / embodied AI
affordance 是当前物体和身体允许的动作；embodied AI（具身 AI）在真实或模拟身体中行动。
Multimodal（多模态）
同时处理文字、图像、传感器状态等不同类型输入的信息系统。
FLOPs / pass@1
FLOPs 是浮点运算次数；pass@1 是一次候选尝试通过任务的概率/指标。
best-of-N / Pareto frontier
best-of-N 是生成 N 个候选后选最好者；Pareto 前沿是准确率、成本等目标无法再互不牺牲地同时改进的候选集合。
value function / rollout
value function 估计一个节点未来成功或收益；rollout 是从节点展开一次采样轨迹。
GRPO / PPO
GRPO 是群体相对策略优化；PPO（近端策略优化）是限制策略更新幅度的强化学习算法。
zero-shot / self-consistency
zero-shot 是不提供同类示例直接做任务；self-consistency 是多次推理后按答案一致性选择。
Scaffolding / geometric mean
scaffolding 是给模型的外部上下文、工具或人工脚手架；geometric mean（几何平均）适合汇总跨任务比例表现。
Reward / self-training / rationale
reward 是对动作或轨迹达标程度的分数；self-training 用模型生成并筛选的样本继续训练；rationale 是中间推理依据。
Few-shot / self-consistency
few-shot 只给少量示例；self-consistency 多次采样后按答案一致性选择。
DAPO / decoupled clipping / dynamic sampling
DAPO 是大规模推理 RL 方法；decoupled clipping 分开调节更新约束；dynamic sampling 按训练状态调整样本。
LLM / ML / code completion
LLM 是大语言模型；ML 是机器学习；code completion 是根据上下文补全代码。
Oracle / agentic retrieval
oracle 是假定可信的参考判定器；agentic retrieval 是智能体根据不确定点主动规划并触发检索。
Falsifiable prediction / long tail
可证伪预测能被具体重复实验推翻；长尾是少量但严重、容易被平均分掩盖的失败。
SESSION 01 · COURSE OVERVIEW · AUTUMN 2025

课程地图：什么是自我改进智能体（Self-Improving Agent）？

先不要把 Agent（智能体：能观察环境、采取行动并继续循环的系统）想成“会聊天的模型”。本课程真正关心的是：一个系统能否利用环境反馈（动作结果返回的、可用于调整下一步的信号）、验证器（检查候选是否满足要求的程序或模型）、工具和历史经验，把下一轮行动做得更好。

官方课程主题基础概念20 讲中的 01

本讲要回答：改进发生在哪里？

普通语言模型通常是输入 x 后一次性生成 y。自我改进智能体则多出一个循环：提出候选、执行动作、观察结果、更新策略。这里的策略（policy）是“根据当前状态选择下一动作的规则或模型”。改进可以发生在三个位置：推理时增加搜索和验证，训练时利用反馈更新模型，或在系统层增加工具、记忆和规划。

01 · propose生成候选答案或动作
02 · act调用工具或环境
03 · verify获得可检查反馈
04 · update重试、搜索或学习

讲解：把“聪明”拆成可检查的接口

状态、动作和反馈

用最小模型表示：状态（state：当前可用信息）是 s_t，Agent 选择动作（action：系统执行的操作）a_t，环境返回观察（observation：动作后的新信息）o_{t+1}。这三者按时间排列的一次完整记录叫轨迹（trajectory）。如果反馈只有“好/坏”，系统很难知道错在目标、工具还是最后一步；如果反馈包含测试断言、执行轨迹或可复现的失败样例，下一轮就有了可操作的学习信号。

三条改进路线

Inference-time同一个模型多采样、搜索、验证；成本增加但不改权重。
Train-time把成功轨迹或反思转成训练数据；需要防止错误自我复制。
System-time接入代码、检索、记忆和物理传感器；能力取决于接口质量。

SESSION 02 · TEST-TIME COMPUTE SCALING

推理时计算扩展：多想几次，真的会更好吗？

推理时计算扩展（Test-Time Compute Scaling：不改模型参数，只增加当前任务的采样、搜索和验证预算）把“模型大小”之外的旋钮打开。但预算不是越大越好，关键是能否筛掉错误候选。

官方课程主题与阅读重复采样 · 路由 · 成本

本讲要回答：预算增加的收益从哪里来？

假设单次生成得到正确答案的概率是 p，独立采样 K 次并且有完美选择器时，至少出现一个正确答案的概率是 1 − (1 − p)^K。现实中选择器并不完美，采样之间也不独立，所以曲线会出现边际收益递减。

sample生成多个候选
score打分或验证
select选择并汇总
budget控制成本与延迟

讲解：从“多生成”到“会分配计算”

重复采样不是盲目投票

如果每个候选只是换一种表述，投票带来的信息很少；如果候选覆盖了不同推理路径，验证器才可能利用多样性。这里的token是模型处理文本时的基本计量单元，token 成本就是生成了多少这样的单元。工程上要同时看四项：候选多样性、验证器校准（预测分数与实际成功率长期一致的程度）、每个候选的 token 成本，以及总延迟。

静态 K 与自适应预算

简单系统对所有问题固定取 K=8；更好的路由器先判断题目难度，再把预算给不确定样本。路由器本身也可能错，因此需要保留小预算的安全路径和停止规则。

SESSION 03 · ROBUST VERIFICATION

稳健验证：答案对了，不等于过程对了

验证器把“看起来合理”变成可执行的判定接口。它也会被模型钻空子，因此必须区分结果验证、过程验证、校准和分布外失败。

官方课程主题与阅读ORM · PRM · calibration

本讲要回答：验证器在验证什么？

ORM 只看最终答案，成本低但可能放过“中间步骤错误、最后蒙对”的轨迹；PRM 对中间步骤打分，反馈更细但标注与校准更难。两者都不是地面真理：它们只是被训练出来的测量仪。

Outcome最终答案是否满足检查器。
Process每一步是否保持可接受的状态。
Calibration分数 0.8 是否真的约等于 80% 成功率。

讲解：从分数到决策

Generation–verification gap

生成器负责提出候选，验证器负责排序或拒绝；两者能力不对称时，系统可能生成很多好答案却挑错，也可能验证器很严格导致误杀。评估验证器时要报告 TP、FP、TN、FN（真阳性、假阳性、真阴性、假阴性四类判断），而不是只报最终准确率。

弱验证器的可用边界

一个弱验证器仍可用于早期剪枝，但不能被包装成最终裁判。可行策略是分层：便宜规则先过滤，昂贵检查器复核，保留少量候选供人工或独立评测。

Shrinking the Generation-Verification Gap with Weak Verifiers

官方 reading · 原文 ↗
问题
人类 oracle 太贵，单个 LM judge 不够准；如何组合多个弱 verifier？
机制
归一化不同输出，用 weak supervision 估计可靠性，过滤低质 judge，再做加权 ensemble。
锚点证据

SESSION 05 · MULTI-STEP REASONING / PLANNING

多步推理与规划：何时应该回溯？

单路径生成擅长顺着局部线索走下去，却不天然知道“这条路以后会死”。搜索把中间状态显式化，让系统能比较分支、剪枝和回滚。

官方课程主题search · branching · backtracking

本讲要回答：规划和生成有什么不同？

生成是一条轨迹，规划是一组候选轨迹及其评估。若动作有前置条件，最接近目标的动作可能不是正确的下一步；搜索的价值就在于保留“暂时绕路但可行”的分支。

讲解：树搜索的三个成本

分支数、深度和评估器

树搜索的粗略成本随分支数 b 和深度 d 增长。实际系统用启发式、beam（每轮只保留若干高分分支）、早停和并行执行减少成本；但每一次剪枝都依赖评估器，错误评估会把正确路径提前删掉。

回溯不是反思口号

可执行的回溯需要保存 checkpoint（检查点：包含状态、依赖和失败上下文的可恢复快照）：已用工具、失败原因和未尝试分支。只有“我应该更谨慎”而没有可恢复状态的文字反思，不足以改变行动。

SESSION 06 · TRAIN-TIME SCALING / RL

训练时扩展：怎样让一次成功变成可复用能力？

推理时搜索只在当前任务花预算；训练时扩展试图把成功轨迹、奖励和反思写回模型。难点是：模型生成的示范并不自动等于高质量标签。

官方课程阅读self-training · RL · data quality

本讲要回答：反馈怎样改变参数？

可以把循环写成：采样轨迹 → 过滤或评分 → 更新策略 → 在独立任务上复测。每一步都可能放大偏差：采样分布变窄、奖励被投机、训练集和评测集泄漏。

讲解：从 STaR 到更谨慎的自训练

为什么要保留推理过程？

若只保留最终答案，训练信号告诉模型“结果是什么”，却没有告诉它如何抵达。自生成 rationale（中间推理/解题依据）可以提供路径，但必须由正确性检查、人工抽样或独立 verifier 过滤。

反馈质量决定上限

高质量反馈让模型逐步覆盖更难样本；噪声反馈会让模型学习验证器的漏洞。一个安全实验应同时记录训练集分数、held-out 分数、数据去重和失败类型。

SESSION 07 · OPEN-ENDED EVOLUTION

开放式演化：从一个解到一群可比较的解

开放式演化把 Agent 看成候选程序或策略的群体：生成变体、运行评估、保留有潜力的分支，再继续探索。真正的挑战是定义不会被轻易作弊的目标。

官方课程主题exploration · novelty · selection

本讲要回答：改进和探索如何共存？

只保留当前最高分会迅速收敛到熟悉的套路；只追求新颖又可能产生无用变体。一个可解释的演化器需要同时记录性能、行为差异、资源成本和失败原因。

讲解：生成—评估—保留—再生成

四个可观测接口

生成器产生候选，评估器给出任务分数，档案库保存可复用的多样解，调度器决定下一批实验。将这四者分开，才能回答“是搜索变聪明了，还是评估器变宽松了”。

新颖性不是成功

新颖性奖励可能鼓励格式变化、无关行为或资源浪费。实践中要把 novelty 当作辅助指标，并用独立任务、预算上限和人工抽查守住边界。

SESSION 13 · SOFTWARE ENGINEERING AGENTS

软件工程 Agent：仓库是环境，测试是反馈

代码 Agent 的难点不是生成一个函数，而是在大型仓库中定位、修改、测试、回滚，并把局部修复的副作用控制住。

官方课程主题repository · tests · patch

本讲要回答：代码任务为何是长程任务？

一个 issue 往往包含自然语言描述、多个相关文件、隐藏约束和回归风险。Agent 需要先建立仓库地图，再提出小补丁，最后用测试与人工 review 验证。

讲解：从 issue 到可合并 patch

定位比生成更早

搜索符号、调用链和测试引用，先缩小改动面；“直接重写整个文件”可能短期通过，却会引入难以发现的行为变化。

验证不等于通过一组测试

测试集只覆盖已知行为。合并前还要检查差异范围、错误处理、权限、性能和未覆盖的边界样例。

SESSION 14 · MEMORY

给 Agent 加记忆：记住什么，也要忘掉什么

记忆不是把全部聊天记录塞进 prompt。它是一套写入、压缩、检索、更新和遗忘策略；错误记忆会让 Agent 更稳定地犯错。

官方课程阅读working · episodic · semantic

本讲要回答：记忆如何影响下一次决策？

当前上下文是 working memory，长期存储可以保存事件、事实和用户偏好。检索通常在相关性之外考虑时间、新鲜度、重要性和 token 预算；如果没有过期策略，旧 API 或错误偏好会污染新任务。

讲解：写入、检索与遗忘接口

写入与压缩

不要保存每个 token；保存可复用的事件、证据和失败原因，并保留来源与时间。压缩摘要若丢失限定条件，就会把猜测变成事实。

检索与陈旧性

Top-K 只是预算，不是质量保证。检索结果进入 prompt 前要过滤 stale、冲突和低置信度条目，并允许 Agent 表示“没有可靠记忆”。

长程任务把每一步的小错误累积成系统级失败。评测 Agent 不能只看单轮准确率，还要记录任务时程、恢复能力、成本和失败形态。

官方课程阅读horizon · checkpoint · generalization

本讲要回答：如何测量“能完成一项工作”？

在独立、无恢复的简化假设下，单步成功率为 p、任务有 T 步时，连续成功率近似为 p^T。这不是所有真实任务的定律，却提醒我们：任务长度会暴露短板。

讲解：从 endpoint 到 trajectory

任务时程

报告完成 50% 任务所需的时间或步骤跨度，比单次 benchmark 分数更能说明 Agent 能否承担长工作；同时要记录工具调用、人工介入和重试。

检查点与恢复

Checkpoint 不是把失败藏起来，而是保存可恢复状态，让系统能回到最近健康节点。评测应区分“从头重做”和“带状态恢复”。

SESSION 19 · MULTIMODAL AGENTS IN ROBOTICS

多模态机器人 Agent：语言计划必须落到物理可行性

机器人系统把 Agent 的错误变成真实动作。多模态（multimodal：同时处理视觉、语言、状态或触觉等信息）感知、语言规划、可供性（affordance：当前状态下动作实际能否成功）检验、低层控制（把技能变成执行器命令并持续纠偏）和力觉反馈必须形成闭环。

官方课程主题SayCan · PaLM-E · grounding（感知/目标与动作的对齐）

本讲要回答：知道“该做什么”够不够？

语言模型可以提出“把杯子放到桌上”，但它不知道杯子是否可见、夹爪是否能抓住、桌面是否有障碍。机器人 Agent 要把语义目标和当前传感器状态、技能成功率、运动学约束（关节、位姿和碰撞等几何限制）连接起来。

感知 perceptionRGB-D（彩色—深度图像）、触觉和状态估计
规划 planning把目标分解成技能/动作序列
可供性 affordance判断动作在当前状态是否可行
控制 control执行、感知、纠偏和重试

讲解：互补而不是同一架构

SayCan 的落地对齐（grounding）

SayCan 关注语言模型提出的技能与环境 affordance/value 之间的结合：不是只问“这句话合理吗”，而是问“当前状态下这个动作能不能做”。这里把语义匹配度（semantic fit：动作是否符合语言目标）和物理可行性（physical feasibility：当前传感器与约束下能否执行）分开。

PaLM-E 的具身输入

PaLM-E 研究将连续传感器观察接入具身语言模型。它和 SayCan 是互补路线；本页的五层流程是教学合成图，不声称两篇论文使用同一系统。

讲解：四个值得继续追问的问题

反馈会不会被优化坏？

当 Agent 能主动寻找高分路径时，验证器就成为攻击面。未来系统需要独立、动态、多视角的评测。

记忆如何保持可撤销？

可靠记忆必须带来源、时间和冲突处理；否则长期运行只会积累不可审计的隐性状态。

能力如何跨过长时程？

单步进步不会自动变成长程可靠性；checkpoint（检查点：保存状态、依赖和已完成子目标的可恢复快照）、子目标和恢复策略应成为一等评测对象。

模拟器和真实世界如何互相校验？

代码环境便宜但可能过于干净，机器人环境昂贵但有物理噪声；跨环境泛化需要明确的失效报告。
