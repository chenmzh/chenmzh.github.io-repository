SESSION 01 · COURSE OVERVIEW · AUTUMN 2025

课程地图：什么是 Self-Improving Agent？

先不要把 Agent 想成“会聊天的模型”。本课程真正关心的是：一个系统能否利用环境反馈、验证器、工具和历史经验，把下一轮行动做得更好。

阅读边界：本页把官方公开课程主题翻译成个人讲解；它不是官方讲义。后续 19 讲按课程页面公开的 session 顺序组织。
官方课程主题基础概念20 讲中的 01

本讲要回答：改进发生在哪里？

普通语言模型通常是输入 x 后一次性生成 y。Self-improving agent 则多出一个循环：提出候选、执行动作、观察结果、更新策略。改进可以发生在三个位置：推理时增加搜索和验证，训练时利用反馈更新模型，或在系统层增加工具、记忆和规划。

01 · propose生成候选答案或动作
02 · act调用工具或环境
03 · verify获得可检查反馈
04 · update重试、搜索或学习

讲解：把“聪明”拆成可检查的接口

状态、动作和反馈

用最小模型表示：状态是 s_t，Agent 选择动作 a_t，环境返回观察 o_{t+1}。如果反馈只有“好/坏”，系统很难知道错在目标、工具还是最后一步；如果反馈包含测试断言、执行轨迹或可复现的失败样例，下一轮就有了可操作的学习信号。

三条改进路线

Inference-time同一个模型多采样、搜索、验证；成本增加但不改权重。
Train-time把成功轨迹或反思转成训练数据；需要防止错误自我复制。
System-time接入代码、检索、记忆和物理传感器；能力取决于接口质量。

SESSION 02 · TEST-TIME COMPUTE SCALING

推理时计算扩展：多想几次，真的会更好吗？

Test-time scaling 把“模型大小”之外的旋钮打开：给同一个模型更多采样、搜索和验证预算。但预算不是越大越好，关键是能否筛掉错误候选。

官方课程主题与阅读重复采样 · 路由 · 成本

本讲要回答：预算增加的收益从哪里来？

假设单次生成得到正确答案的概率是 p，独立采样 K 次并且有完美选择器时，至少出现一个正确答案的概率是 1 − (1 − p)^K。现实中选择器并不完美，采样之间也不独立，所以曲线会出现边际收益递减。

sample生成多个候选
score打分或验证
select选择并汇总
budget控制成本与延迟

讲解：从“多生成”到“会分配计算”

重复采样不是盲目投票

如果每个候选只是换一种表述，投票带来的信息很少；如果候选覆盖了不同推理路径，验证器才可能利用多样性。工程上要同时看四项：候选多样性、验证器校准、每个候选的 token 成本，以及总延迟。

静态 K 与自适应预算

简单系统对所有问题固定取 K=8；更好的路由器先判断题目难度，再把预算给不确定样本。路由器本身也可能错，因此需要保留小预算的安全路径和停止规则。

SESSION 03 · ROBUST VERIFICATION

稳健验证：答案对了，不等于过程对了

验证器把“看起来合理”变成可执行的判定接口。它也会被模型钻空子，因此必须区分结果验证、过程验证、校准和分布外失败。

官方课程主题与阅读ORM · PRM · calibration

本讲要回答：验证器在验证什么？

ORM 只看最终答案，成本低但可能放过“中间步骤错误、最后蒙对”的轨迹；PRM 对中间步骤打分，反馈更细但标注与校准更难。两者都不是地面真理：它们只是被训练出来的测量仪。

Outcome最终答案是否满足检查器。
Process每一步是否保持可接受的状态。
Calibration分数 0.8 是否真的约等于 80% 成功率。

讲解：从分数到决策

Generation–verification gap

生成器负责提出候选，验证器负责排序或拒绝；两者能力不对称时，系统可能生成很多好答案却挑错，也可能验证器很严格导致误杀。评估验证器时要报告 TP、FP、TN、FN，而不是只报最终准确率。

弱验证器的可用边界

一个弱验证器仍可用于早期剪枝，但不能被包装成最终裁判。可行策略是分层：便宜规则先过滤，昂贵检查器复核，保留少量候选供人工或独立评测。

SESSION 04 · TOOLS / CODE FEEDBACK

从工具与代码反馈学习：让环境回答模型

工具调用的价值不在于“能运行代码”，而在于把模糊的自然语言判断转换成 stdout、测试断言和可复现的失败轨迹。

官方课程阅读ReAct · sandbox · feedback

本讲要回答：工具反馈如何进入下一轮？

一个可靠的工具接口应声明输入 schema、权限、超时、输出格式和失败语义。Agent 不应该只收到“失败”，而要收到可以定位的最小反例；否则循环会变成重复猜测。

讲解：Thought–Action–Observation

工具是一个有边界的环境

把工具看成函数 tool: (input, state) → (observation, state')。沙箱隔离危险副作用，测试集提供可重复的判定；模型负责提出动作，但不应拥有绕过验证器的隐藏通道。

一条好的失败轨迹

  1. 保留触发失败的输入。
  2. 记录期望值与实际值。
  3. 将失败归因成可修复的假设。
  4. 只修改一个变量，再运行回归测试。

SESSION 05 · MULTI-STEP REASONING / PLANNING

多步推理与规划：何时应该回溯？

单路径生成擅长顺着局部线索走下去，却不天然知道“这条路以后会死”。搜索把中间状态显式化，让系统能比较分支、剪枝和回滚。

官方课程主题search · branching · backtracking

本讲要回答：规划和生成有什么不同？

生成是一条轨迹，规划是一组候选轨迹及其评估。若动作有前置条件，最接近目标的动作可能不是正确的下一步；搜索的价值就在于保留“暂时绕路但可行”的分支。

讲解：树搜索的三个成本

分支数、深度和评估器

树搜索的粗略成本随分支数 b 和深度 d 增长。实际系统用启发式、beam、早停和并行执行减少成本；但每一次剪枝都依赖评估器，错误评估会把正确路径提前删掉。

回溯不是反思口号

可执行的回溯需要保存 checkpoint：状态、已用工具、失败原因和未尝试分支。只有“我应该更谨慎”而没有可恢复状态的文字反思，不足以改变行动。

SESSION 06 · TRAIN-TIME SCALING / RL

训练时扩展：怎样让一次成功变成可复用能力？

推理时搜索只在当前任务花预算；训练时扩展试图把成功轨迹、奖励和反思写回模型。难点是：模型生成的示范并不自动等于高质量标签。

官方课程阅读self-training · RL · data quality

本讲要回答：反馈怎样改变参数？

可以把循环写成：采样轨迹 → 过滤或评分 → 更新策略 → 在独立任务上复测。每一步都可能放大偏差：采样分布变窄、奖励被投机、训练集和评测集泄漏。

讲解：从 STaR 到更谨慎的自训练

为什么要保留推理过程？

若只保留最终答案，训练信号告诉模型“结果是什么”，却没有告诉它如何抵达。自生成 rationale 可以提供路径，但必须由正确性检查、人工抽样或独立 verifier 过滤。

反馈质量决定上限

高质量反馈让模型逐步覆盖更难样本；噪声反馈会让模型学习验证器的漏洞。一个安全实验应同时记录训练集分数、held-out 分数、数据去重和失败类型。

SESSION 07 · OPEN-ENDED EVOLUTION

开放式演化：从一个解到一群可比较的解

开放式演化把 Agent 看成候选程序或策略的群体：生成变体、运行评估、保留有潜力的分支，再继续探索。真正的挑战是定义不会被轻易作弊的目标。

官方课程主题exploration · novelty · selection

本讲要回答：改进和探索如何共存？

只保留当前最高分会迅速收敛到熟悉的套路；只追求新颖又可能产生无用变体。一个可解释的演化器需要同时记录性能、行为差异、资源成本和失败原因。

讲解：生成—评估—保留—再生成

四个可观测接口

生成器产生候选，评估器给出任务分数，档案库保存可复用的多样解，调度器决定下一批实验。将这四者分开，才能回答“是搜索变聪明了，还是评估器变宽松了”。

新颖性不是成功

新颖性奖励可能鼓励格式变化、无关行为或资源浪费。实践中要把 novelty 当作辅助指标，并用独立任务、预算上限和人工抽查守住边界。

SESSION 08 · SEARCH / DEEP RESEARCH AGENTS

搜索与深度研究 Agent：把问题拆成可验证的证据链

研究型 Agent 不只是“联网回答”。它需要提出检索计划、区分来源质量、合并证据，并在结论和证据之间留下可追溯关系。

官方课程阅读search · code · evidence

本讲要回答：搜索空间如何变成证据图？

把研究任务表示成 claim 节点和 source 边：每条主张都要知道来自哪里、是否直接支持、有没有相反证据。搜索 Agent 的“自我改进”首先表现为更会选择下一条检索动作，而不是更会写漂亮总结。

讲解：候选程序和候选证据的共同结构

代码搜索的反馈闭环

AlphaCode 类系统把自然语言目标转成许多程序候选，再用测试、过滤和排序缩小集合。研究 Agent 也可以这样看：查询是动作，文档是观察，引用一致性是验证器。

引用不是装饰

一条引用至少要回答三个问题：它支持哪一句话？是原始证据还是二手转述？在时间、模型和任务范围上是否可比？无法回答时，应该降低断言强度。

追问任务集合、成功定义、失败样例和成本。嘉宾观点可以启发问题，但论文、数据和可复现实验才是证据。

一句话主张

“我们的 Agent 更好”不是研究主张。好的句子包含任务分布、比较基线、改动接口和预期指标。

至少同时报告质量、成本和失败类型；只报平均成功率会掩盖长尾问题。

SESSION 11 · MIDTERM PRESENTATIONS II

期中展示二：从 demo 走向对照实验

第二次阅读展示时，最重要的不是把 demo 做得更长，而是解释哪一个组件造成了变化。

官方日程活动具体项目待补

本讲要回答：改进到底来自哪里？

消融一个组件

去掉 verifier、memory 或 planning 中的一个组件，再比较相同预算下的结果。若没有消融，就无法区分“系统更复杂”和“系统更有效”。

选择能说话的基线

基线应共享输入、工具权限和预算；否则差异可能来自资源不对等，而不是方法。

听众反馈可以分成三类：定义不清、证据不足、机制不成立。先把意见写成问题，再决定下一轮实验是否能回答它。

SESSION 13 · SOFTWARE ENGINEERING AGENTS

软件工程 Agent：仓库是环境，测试是反馈

代码 Agent 的难点不是生成一个函数，而是在大型仓库中定位、修改、测试、回滚，并把局部修复的副作用控制住。

官方课程主题repository · tests · patch

本讲要回答：代码任务为何是长程任务？

一个 issue 往往包含自然语言描述、多个相关文件、隐藏约束和回归风险。Agent 需要先建立仓库地图，再提出小补丁，最后用测试与人工 review 验证。

讲解：从 issue 到可合并 patch

定位比生成更早

搜索符号、调用链和测试引用，先缩小改动面；“直接重写整个文件”可能短期通过，却会引入难以发现的行为变化。

验证不等于通过一组测试

测试集只覆盖已知行为。合并前还要检查差异范围、错误处理、权限、性能和未覆盖的边界样例。

SESSION 14 · MEMORY

给 Agent 加记忆：记住什么，也要忘掉什么

记忆不是把全部聊天记录塞进 prompt。它是一套写入、压缩、检索、更新和遗忘策略；错误记忆会让 Agent 更稳定地犯错。

官方课程阅读working · episodic · semantic

本讲要回答：记忆如何影响下一次决策？

当前上下文是 working memory，长期存储可以保存事件、事实和用户偏好。检索通常在相关性之外考虑时间、新鲜度、重要性和 token 预算；如果没有过期策略，旧 API 或错误偏好会污染新任务。

讲解：写入、检索与遗忘接口

写入与压缩

不要保存每个 token；保存可复用的事件、证据和失败原因，并保留来源与时间。压缩摘要若丢失限定条件，就会把猜测变成事实。

检索与陈旧性

Top-K 只是预算，不是质量保证。检索结果进入 prompt 前要过滤 stale、冲突和低置信度条目，并允许 Agent 表示“没有可靠记忆”。

SESSION 17 · AGENTIC EVALUATIONS / LONG HORIZONS

Agent 评测：短题高分，能撑过长任务吗？

长程任务把每一步的小错误累积成系统级失败。评测 Agent 不能只看单轮准确率，还要记录任务时程、恢复能力、成本和失败形态。

官方课程阅读horizon · checkpoint · generalization

本讲要回答：如何测量“能完成一项工作”？

在独立、无恢复的简化假设下，单步成功率为 p、任务有 T 步时，连续成功率近似为 p^T。这不是所有真实任务的定律，却提醒我们：任务长度会暴露短板。

讲解：从 endpoint 到 trajectory

任务时程

报告完成 50% 任务所需的时间或步骤跨度，比单次 benchmark 分数更能说明 Agent 能否承担长工作；同时要记录工具调用、人工介入和重试。

检查点与恢复

Checkpoint 不是把失败藏起来，而是保存可恢复状态，让系统能回到最近健康节点。评测应区分“从头重做”和“带状态恢复”。

SESSION 19 · MULTIMODAL AGENTS IN ROBOTICS

多模态机器人 Agent：语言计划必须落到物理可行性

机器人系统把 Agent 的错误变成真实动作。视觉感知、语言规划、affordance 检验、低层控制和力觉反馈必须形成闭环。

官方课程主题SayCan · PaLM-E · grounding

本讲要回答：知道“该做什么”够不够？

语言模型可以提出“把杯子放到桌上”，但它不知道杯子是否可见、夹爪是否能抓住、桌面是否有障碍。机器人 Agent 要把语义目标和当前传感器状态、技能成功率、运动学约束连接起来。

perceptionRGB-D、触觉和状态估计
planning把目标分解成技能
affordance判断动作是否可行
control执行、感知、重试

讲解：互补而不是同一架构

SayCan 的 grounding

SayCan 关注语言模型提出的技能与环境 affordance/value 之间的结合：不是只问“这句话合理吗”，而是问“当前状态下这个动作能不能做”。

PaLM-E 的具身输入

PaLM-E 研究将连续传感器观察接入具身语言模型。它和 SayCan 是互补路线；本页的五层流程是教学合成图，不声称两篇论文使用同一系统。

SESSION 20 · FUTURE RESEARCH AREAS

未来研究：把“会做”推进到“可信地会做”

最后一讲不是一个答案，而是一张研究地图：更强的模型、更多的搜索、更多的工具，都必须和可靠反馈、长期评测以及真实约束一起设计。

讲解：四个值得继续追问的问题

反馈会不会被优化坏？

当 Agent 能主动寻找高分路径时，验证器就成为攻击面。未来系统需要独立、动态、多视角的评测。

记忆如何保持可撤销？

可靠记忆必须带来源、时间和冲突处理；否则长期运行只会积累不可审计的隐性状态。

能力如何跨过长时程？

单步进步不会自动变成长程可靠性；checkpoint、子目标和恢复策略应成为一等评测对象。

模拟器和真实世界如何互相校验？

代码环境便宜但可能过于干净，机器人环境昂贵但有物理噪声；跨环境泛化需要明确的失效报告。
