闭环、扩展与验证 Agent Loop & Scaling.

从单轮文本补全到具备自我改进能力的智能体，核心转变在于建立“生成—执行—验证—修正”的闭环，并在推理时（Test-time）按需分配计算预算与验证强度。

为什么单轮推理不够？从静态生成到反馈闭环

在传统的 LLM 推理中，模型根据输入单向生成自回归 Token 序列。一旦中间某一步推理出现幻觉或逻辑断层，错误会级联放大导致最终答案失败。而 Self-Improving Agent 的本质是将推理拆解为带有显式验证和回滚机制的状态机：

01 · 目标解析接收输入并分解子目标
02 · 候选生成生成动作、代码或推导路径
03 · 环境交互执行工具或运行测试
04 · 反馈校验验证器评分与错误归因
05 · 接受或重试接受合格输出或触发修订

推理时计算扩展：Test-Time Compute Scaling

过去几年模型能力提升主要依赖预训练（Pre-training）和后训练（Post-training）计算量的增加。近期研究（如 Snell et al., 2024）指出：在推理阶段按需扩展计算量（Test-time compute）同样能带来显著的准确率提升，甚至在某些推理任务上，较小模型通过推理时搜索能超越数倍参数量的基准模型。

PARALLEL SAMPLING

并行采样与重排序 (Best-of-N)

独立采样 N 条候选解，利用验证器（Verifier）对候选答案进行打分排序，选取最优解。适合验证容易但生成较难的问题（如数学答案代回检验、代码单元测试）。

SEQUENTIAL SEARCH

序贯修订与树搜索 (Sequential Search)

在推理过程中维护搜索树（如 Beam Search、MCTS），在每一步评估分叉并回溯剪枝。相比并行采样，能在长程规划中有效抑制无谓的算力浪费。

过程验证 vs 结果验证：PRM 与 ORM 的权衡

验证器（Verifier）的质量直接决定了推理时搜索与自我改进的上限。主流验证架构可分为两类：

OUTCOME REWARD MODEL (ORM)

结果级验证 (ORM)

仅对最终生成的答案或输出进行二元判定（Pass/Fail）。实现简单且无标注歧义，但无法指出中间具体哪一步出错，容易产生“推理步骤错误但蒙对最终答案”的伪正例（False Positive）。

PROCESS REWARD MODEL (PRM)

过程级验证 (PRM)

对推导过程中的每一个中间步骤单独给出信用分配与打分（Lightman et al., 2023）。能够精准实现步骤级剪枝与回溯，但训练数据构建成本更高且容易对特定推导风格产生偏见。

过程描述：逐步移项并代回原方程严格验证。

候选 C · 答案：x = 5 得分: 0.12

过程描述：移项符号错误，导致最终答案算错。

过程描述：步骤省略，中间缺少因式分解步骤。
