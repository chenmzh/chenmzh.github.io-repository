为什么需要这一层？

20 讲 reader 按官方公开 schedule 展开；参考仓库则按决策问题重新聚合。两种目录解决不同问题：前者回答“课程什么时候讲什么”，后者回答“我现在要决定什么、应该检查哪些证据”。它们的交集是一个闭环：目标先变成规格，Agent 受约束行动，环境返回 observation，验证器选择或拒绝，轨迹进入搜索/训练，最后用真实任务和资源成本审计。

goal写出完成条件与权限
state保存环境和依赖状态
action只选当前允许动作
verify用外部证据停止或升级

使用规则：先问决策，不按名词堆资料

如果你要决定“是不是 Agent”，先看最小闭环；要决定“采样预算放哪”，先看 coverage 与 selected accuracy；要决定“judge 能不能信”，先审计验证信号；要决定“能否上线”，最后才看生产就绪度。一个问题最多加载一个主模块和一个真正相关的第二模块，避免把七个 checklist 一次性塞进上下文。

七个实践模块：每个模块是一扇准入门

模块不是七个必须全部加载的 prompt，而是七个不同决策的检查门。下面的短文是本站原创导航；点击标题进入参考仓库的原始模块，阅读时仍要结合项目自身的风险和领域专家。

01 · 最小 Agent 闭环

关联 S01 / S04 / S13

先写 goal、state、action、observation、verifier 和 stop condition，再决定是否需要更复杂的自主循环。它能拦住“只是把多个 prompt 串起来就叫 Agent”的误判。

阅读原始模块 ↗ · 回到 S01 ↗

02 · 验证约束下的推理预算

关联 S02 / S03

同时测候选覆盖率与最终 selected accuracy；采样、顺序修订、搜索和验证的预算只有穿过可靠选择器才会变成交付质量。

阅读原始模块 ↗ · 回到 S02 ↗

03 · 验证信号与 Judge 审计

关联 S03 / S17

先区分 outcome、process 和 meta-verification，再检查误报、漏报、覆盖盲区与相关错误。多个同源 judge 的一致不自动等于独立证据。

阅读原始模块 ↗ · 回到 S03 ↗

04 · 依赖、可逆性与执行控制

关联 S05 / S13 / S19

不是所有任务都能并行，也不是所有失败都能回滚。只读检查、草稿和沙箱实验可以探索；付款、发信、删数据等不可逆动作必须有最新状态、验证和审批。

阅读原始模块 ↗ · 回到 S05 ↗

05 · 可验证轨迹训练门

关联 S06 / S07

一次成功轨迹不能直接成为训练标签；先检查是否可发现、是否被可信验证、是否包含要学习的过程，再观察写回后的 held-out 与奖励投机。

阅读原始模块 ↗ · 回到 S06 ↗

06 · 证据缺口驱动的研究

关联 S08 / S17

先列出 claim 缺什么，再检索、在文档内抽取、压缩回上下文并审计引用。找到网页、抽到事实、正确综合和引用支持是四个不同指标。

阅读原始模块 ↗ · 回到 S08 ↗

07 · Agent 生产就绪度评测

关联 S17 / S19 / S20

部署权限不能由平均 benchmark 单独决定；还要看任务时长、可靠性、尾部伤害、证据质量、专家价值、延迟、成本和能耗。

阅读原始模块 ↗ · 回到 S17 ↗

工作术语：读论文时先对齐定义

Coverage / pass@kk 个候选里出现正确答案的潜在能力，不是最终交付准确率。
Generation–verification gap正确候选出现了，但选择器没找出来。
ORM / PRM结果奖励与过程奖励的对象、成本和盲区不同。
Meta-verification审计 judge 指出的缺陷是否存在、评分是否由证据推出。
Time horizon指定成功率下能完成多长任务的能力边界，不是生产 SLA。
Evidence graph把 claim、source、支持强度和冲突关系显式保存。

证据边界：哪些结论不能直接外推？

来源层级

课程事实优先回到 Stanford 官方页面和 Stanford Online 原始视频；论文细节回到论文原文；本页和参考仓库的中文解释只是综合层。外部网页、工具输出和模型轨迹都应被视为不可信输入，行动前要结构化验证。

不能从数学/代码 benchmark 推出通用自主学习

可快速验证的数学、代码、检索和定理证明任务适合搜索与执行反馈，但不能直接证明同样方法在政策、创作、谈判或科学实验中具有同等收益。

不能用单一指标授权部署

pass@k 上升、多个同源 judge 一致、50% time horizon 变长或平均 benchmark 提升，都不能单独授权训练回写、提权或不可逆外部动作。必须加上证据、尾部风险、成本、权限和人工责任。

版本提醒：课程与模型论文会更新；参考仓库的模块是稳定方法的社区归纳，不替代当前产品能力、法规、隐私和领域安全评审。

推荐使用顺序

第一次学习

S01 → 模块 03 → S02 → S05 → S08 → S17。先让闭环看见错误，再给它更多计算和更大权限。

正在开发 Agent

先做模块 01 的最小状态机；遇到采样预算读模块 02，遇到 judge 信任读模块 03，遇到副作用和回滚读模块 04。不要因为“更自主”听起来更强，就跳过 stop condition。

做 Deep Research 或 post-training

Deep Research 重点看模块 06 和 S08；SFT/RL 重点看模块 05 和 S06；准备上线时最后读模块 07，并回到 S17 检查长时程而非只看平均分。

一页式自检：写出你的 Agent 的 goal、state、action、observation、verifier、stop condition、预算、依赖、回滚、证据表和生产阈值。任何一个字段为空，结论应是“补证据/降级/人工审批”，而不是“完成”。
