# 生物方向模型微调课程：从 H200 入门到可复现实验

课程版本：2026-10-24。建议安排为 4 周、每周 3 课；这是学习组织方式，不是训练时间承诺。所有学习率、batch、实验组合和验收阈值均是教学建议，未在你的 H200 上实测。

## 课程目标与两条路线

主线 A 解决“给定生物医学论文证据，模型能否作出可靠的结构化判断”；主线 B 解决“给定蛋白质序列，模型能否预测一个实验相关数值”。这两种输入、监督目标、tokenizer、指标和泛化边界不同，不能把文字大模型训练方法原样套到所有生物任务上。

结课交付包括：数据卡、固定划分、基线结果、适配器或回归模型、训练配置、完整评估输出、错误分析与复现说明。不要求每次微调都超过基线；要求能够说明结论来自哪些证据。

入门先备：Python 函数/字典/文件、虚拟环境、Linux 基本操作、张量与梯度、训练/验证/测试区别。缺少 PyTorch 经验时先用一小段张量代码演示 `loss.backward()` 与梯度累积，再进第 5 课。

## 第 1 课：先定义问题，再选模型

**知识点。** “微调”不是一个统一任务。自然语言问答可以学习固定格式与证据使用；序列回归直接预测连续标签；检索系统从外部语料找材料；领域继续预训练学习语料分布。先写清输入、输出、预期使用者和不适用范围，再决定需要训练什么。

本课程默认采用带上下文的 PubMedQA：输入问题和去掉结论的摘要，输出 `{"decision":"yes|no|maybe"}`。这种小任务利于测量，不意味着它已成为通用生物科研助手。只有 450 条训练样本时，更不能合理承诺“掌握整个生物领域”。

**实验。** 对比三个目标：有证据的文献判断；输入氨基酸串预测荧光；基于最新文献回答问题。给每个目标写一组合法输入与输出。最后一个目标应先考虑如何获得和引用外部文献，而不是直接把所有事实写入参数。

**作业。** 任务卡写明：目标使用者、输入单位、输出 schema、成功指标、不可声称的能力、数据来源。若选择“生物研究助手”，必须继续缩窄成可评测的子任务。

**验收。** 能解释“问答分数高”为什么不证明“序列建模好”；能指出至少一种无需微调就应先测的基线。

**阅读。** R03、R12、R16。

## 第 2 课：把 H200 当作实验资源，而不是必须占满的设备

**知识点。** NVIDIA 标称 H200 为 141 GB HBM3e；容器或 MIG 可见值应现场检查。BF16 的模型权重理论下限约为参数数×2 字节：8B 约 16 GB、32B 约 64 GB、70B 约 140 GB，均未含激活、梯度、优化器、临时张量和运行时开销。这是计算下限，不是训练显存实测。

因此起步选择 8B BF16 LoRA，不是因为 H200 只能训练 8B，而是为了把注意力留给数据和评估。8B 全参数 Adam 的状态占用远大于仅存权重，不能因权重能装入显存就认定全量训练也能装入。多卡 DDP 复制模型，不自动分片；要扩大单模型容量需另行设计 FSDP/ZeRO 等。

**实验。** 运行 `scripts/check_environment.py`，记录 GPU 数、名称、GiB、驱动、PyTorch CUDA build 与包版本。先完成一个小批次，再根据峰值显存调整 micro-batch，不用事先编造吞吐数字。

**作业。** 计算有效 batch：单卡 2×8=16；双卡为保持同样 batch，改成 2×4×2=16。说明改变卡数后为何不能忘记梯度累积。

**验收。** CUDA 可用；保存环境；能区分 GB/GiB、模型权重占用/完整训练占用、数据并行/模型分片。

**阅读。** R01、R02、R06。

## 第 3 课：数据切分先于训练

**知识点。** PubMedQA 的 1,000 条专家标注中包含官方 500 条测试题。Hugging Face 的 split 名称不应替代任务官方评估协议。脚本以原作者 `test_ground_truth.json` 的 PMID 划出测试集，然后仅把剩余 500 条分为 450/50。

输入只用问题与上下文，不使用结论、标签、已有模型预测。表面的“模型很聪明”可能只是读取了答案字段。原文、摘要改写和中文翻译属于同一来源组，不能分到不同 split 后声称独立。

**实验。** 运行 `prepare_pubmedqa.py`，阅读 `manifest.json` 和 `audit.json`。人工抽查每类至少数条训练样本，检查证据、否定、统计结论和标签。脚本的精确哈希检查不是语义去重，也不是标签准确性审核。

**作业。** 写数据卡：谁标注、任务是什么、标签如何理解、哪些字段可输入、如何切分、许可有何边界、何种污染尚无法排除。整理一张“泄漏路径”表，例如结论进 prompt、同文翻译跨 split、根据测试错题改训练样本。

**验收。** 预期 450/50/500；测试标签与输入分开保存；无跨 split 精确重复，或对发现的问题明确停止处理并调查。报告课程开发切分并非官方 10 折协议。

**阅读。** R10–R13、R21–R23。

## 第 4 课：训练前先留下一条可比较的起跑线

**知识点。** 多数类基线暴露类别不均衡；原模型基线测量预训练模型已经具备多少能力。没有原模型输出，就无法判断微调是在增加正确性，还是只让 JSON 更整齐。

本实验固定 model revision、prompt、非思考模式、解码设置和验证题目。Qwen3 使用 `enable_thinking=False`；不比较一组长思考输出与另一组短 JSON 输出后归因于 LoRA。

**实验。** 运行 `majority_baseline.py` 与 `evaluate_llm.py`。保存每一道题的原始输出，不只保存 aggregate accuracy。记录非法 JSON、每类预测比例和主要错误。

**作业。** 从验证结果中选出正确/错误/非法各一例，讨论“读懂了证据”与“碰巧猜中了类别”如何区分。暂不打开测试集。

**验收。** 两份基线有完整逐题预测；多数类从训练集选择，不从测试标签选择。基座版本写入报告。

**阅读。** R09、R12、R03 的评估部分。

## 第 5 课：理解模型到底在学哪些 token

**知识点。** 自回归 SFT 学习目标 token 的条件概率。对本任务，用户问题、系统提示和证据是条件；只让 assistant 的答案与 EOS 计算 loss。把整个长摘要都当目标会改变任务权重，让训练目标偏向复述输入。

本包用显式 `labels`：prompt 对应位置设为 `-100`，completion 对应 token ID 保留。padding 也用 `-100`。不因 pad 与 eos 偶尔相同就把所有 EOS 都清零；停止符应得到训练。学习时可把实现与 TRL 的 completion-only loss 对照。

**实验。** 用 `data/smoke_*.jsonl` 检查训练流程；运行单元测试，确认 EOS 有监督、输入不含金标准、超长样本报错。再对真实 tokenizer 打印一条样本的 prompt 长度、目标长度及有监督 token 数。

**作业。** 修改一份拷贝，将 prompt 也计入 loss，说明优化目标发生了什么变化；不把这一修改混入正式对照实验。解释为什么训练和推理必须保持同一 chat template。

**验收。** 有监督 token 全部来自 assistant 目标和结束符；没有目标全部为 `-100` 的样本；没有静默截掉证据或目标。

**阅读。** R03、R04、R05。

## 第 6 课：第一次 BF16 LoRA

**知识点。** LoRA 冻结原始权重，只学习低秩增量。示意公式为 `W' = W + (alpha/r) BA`。r 越大并不自动越好；需要在容量、显存和过拟合间比较。对于本课程小数据，先选择 r=16、alpha=32、dropout=0.05。

默认学习率 1e-4、micro-batch 2、梯度累积 8、最大长度 4096、最多 3 epoch 是起跑设置。启用梯度检查点，先采用框架自带 SDPA，不把外部 FlashAttention 编译问题引入第一课训练。保存适配器而非复制整份基座。

**实验。** 先运行 5-step 玩具流程，再用正式数据训练。记录可训练参数量、目标 token 数、训练/验证 loss、峰值 allocated/reserved 显存。训练结束加载适配器，运行同一验证集。

**作业。** 在验证集范围内比较 r=8 和 r=16，或学习率 5e-5 和 1e-4；一次只改一个因素。不要一次改模型、数据、模板和精度后猜测原因。

**验收。** 适配器可加载；没有 NaN/Inf；输出有测量结果；明确 checkpoint 先按 validation loss 选择，再核对 Accuracy/Macro-F1。无法提升也写清楚，不能删除负结果。

**阅读。** R07、R04、R06。

## 第 7 课：QLoRA 是可选节省手段，不是 H200 上的必选项

**知识点。** QLoRA 将冻结基座以低比特形式保存，通过计算路径训练 LoRA 参数；4-bit 不是所有计算、梯度和优化器状态都为 4-bit。本包采用 NF4、double quantization、BF16 计算。额外量化内核也引入兼容性与性能变量。

合理比较需要四组：BF16 基座、BF16+LoRA、NF4 基座、NF4+LoRA。只比较 BF16 基座与 NF4+LoRA，会把量化与微调两个变化混在一起。

**实验。** 用相同模型 revision、数据、模板和 seed 训练 QLoRA，记录显存、训练日志与验证指标。运行 NF4 未微调基座作为对照。不要据单次运行声称 QLoRA 在所有任务上一定更快或更准。

**作业。** 做一张对照表：参数精度、可训练参数、峰值显存、Accuracy、Macro-F1、非法输出率。说明是否值得为了更大的模型引入量化。

**验收。** 对照条件明确；数据和 prompt 一致；没有把量化后的基座差异归到 LoRA 本身。多卡 QLoRA 不在本包实现范围内。

**阅读。** R06、R08。

## 第 8 课：数据规模增长必须带着来源和质量标签

**知识点。** PQA-A 是人工构造的弱标注数据，PQA-L 是专家标注；不能把两个集合都描述为“专家知识”。PQA-U 没有可直接当作金标准的决策标签。大数据不保证提高小型专家任务性能。

第一轮扩展建议取 10,000 条 PQA-A，记录实际类别分布并人工抽查。脚本排除全部 PQA-L 的精确 PMID、问题和上下文重叠；相似题和改写仍可能留下，必须在报告说明。

**实验。** 组 A：仅 PQA-L。组 B：PQA-A 一个阶段，然后以较低学习率继续 PQA-L。两个阶段必须使用同一基座 commit；`--base-adapter` 继续训练适配器。保存单独输出目录。

**作业。** 从弱数据抽样标注“问题不自然/证据不足/标签可疑/与专家数据近重复”等缺陷，形成一页抽查报告。比较扩展前后的 `maybe` 类 F1，避免大量二分类数据让模型忘记不确定类别。

**验收。** 来源和标签质量分开；没有测试内容进入任一阶段；与仅专家数据模型做消融；未提升时提出可检验的原因而非继续盲目加数据。

**阅读。** R10–R13。

## 第 9 课：科学评估不能止于一个平均分

**知识点。** Accuracy 反映整体正确率；Macro-F1 给各类别相等权重；格式正确性不是答案正确性。置信度与“不确定”标签也不是同一概念。没有概率校准实验时，不能把模型自报“90%”当成真实可靠性。

本包对输出执行严格 JSON 解析；多余解释或错格式视为 INVALID，不自动清洗成正确答案。保存混淆矩阵和逐题预测，检查是否把 `maybe` 全判成 `yes`。Wilson 区间描述准确率抽样不确定性；模型差异使用同题配对 bootstrap，不拿两个独立区间是否重叠替代配对比较。

**实验。** 运行 `compare_runs.py`。对错误案例分组：否定词、相关不等于因果、群体差异、结果不显著、证据混合、格式错误。50 条验证集的微小分数波动不可夸大。

**作业。** 写一页错误分析，至少展示原文证据、模型输出、参考标签、错误类别和改进假设。若提出新训练数据，先固定获取策略，不根据测试答案反向编题。

**验收。** 不只展示最好一个 seed；在资源允许时比较 3 个 seed。若改善不确定，结论写为“目前证据不足以支持稳定改善”。推荐课程格式合格率目标 99%，这是自定工程目标，不是文献标准或能力保证。

**阅读。** R03、R12；统计实现可直接检查 `compare_runs.py`。

## 第 10 课：把任务移向基础生物学，而不是继续堆医学考题

**知识点。** BioRED 提供摘要层面的实体和关系标注，可设计基因/蛋白、化学物质和疾病等信息抽取任务。信息抽取不应只靠“回答看起来合理”；需要明确实体类型、跨度、标准化 ID、关系方向和证据范围。

推荐标注格式：`entities=[{id,type,text,start,end}]`；`relations=[{head,tail,type}]`。字符偏移必须说明以哪个原文、哪种索引单位计算；生成文本与原文对应关系应自动校验。先做“给定实体候选，判断关系”，再尝试端到端抽取，以分离实体识别与关系判断错误。

**实验设计（拓展作业，不是本包已实现脚本）。** 使用 NCBI 官方数据与标注指南，保持官方文档 split；按文档建立 JSON schema 与 gold。实体评估使用跨度/类型 F1，关系评估使用指定端点与类型的 F1，空输出和格式失败计入评估。不要把一篇文章切成多段后随机分到训练和测试。

最新文献问答可另建检索模块，让答案引用真实文献和证据片段。微调负责任务行为与结构；检索负责可更新的外部材料。给出引用不等于引用支持论断，需要人工或专门的蕴含评估。

中文扩展要核对基因符号、单位、否定和关系方向；翻译数据按同源论文分组。未知许可的全文不直接进入数据包。

**验收。** 有来源、split、schema、错误定义和评分函数设计；明确关系方向、实体标准化与文本偏移规则。不能把本课方案写成已完成的 BioRED 训练结果。

**阅读。** R14、R15、R21。

## 第 11 课：真正的蛋白质序列微调

**知识点。** ESM-2 使用蛋白质序列表示，回归任务需添加输出数值的头。训练目标是 MSE 等数值损失，而非让模型生成一句“荧光较高”。本包先用 35M 型号，比较冻结编码器仅训回归头与全参数微调；前者是带模型自带头的基线，不声称是严格线性探针。

TAPE GFP 任务预测 `log_fluorescence`。官方测试划分用于考察特定的序列泛化；不要重新随机切分近邻突变体来抬高指标。这个任务的结果也不能推广为所有蛋白质功能或结构预测能力。

**实验。** `prepare_fluorescence.py` 后运行 head/full 两个模型。标签标准化的均值与方差只来自训练集。按验证 Spearman 选择 checkpoint，early stopping；RMSE/MAE 转回原始 log 标签尺度。报告训练均值预测的 RMSE 基线。

**作业。** 检查序列长度分布、精确重复和跨 split 重叠；讨论同源性与预训练重叠风险。确认流程后才设计更大 ESM-2 模型或家族隔离外测，不因为 H200 显存空闲就跳过基线。

**验收。** 数值标签正确；未二次取对数；没有静默截断序列；保持官方 split；未把验证集统计用于标签标准化；没有在选模型时反复查看最终测试。

**阅读。** R16–R20。

## 第 12 课：结课不是一张截图，而是一份可复现证据链

**实验。** 固定最终模型、模板、精度、超参数与评分规则。对原模型和最终模型执行一次约定的最终测试比较；之后的改进应视为新一轮研究，不能继续把已反复查看的测试集称作未见数据。

**报告模板。** 任务与边界 → 数据来源/许可/版本 → 切分和污染风险 → 模型/环境 → 训练方法 → 基线与消融 → 逐类指标和不确定性 → 错误案例 → 资源占用 → 复现命令 → 未解决问题。附全部配置和预测，不只附最好结果。

**评分建议。** 数据与切分 25 分；基线与对照 20 分；训练实现与复现 20 分；评估与误差分析 25 分；局限、许可和表达 10 分。训练集/测试集泄漏或虚构效果属于关键缺陷，不能以较高准确率抵消。

**实际应用边界。** 课程模型只作为研究原型。论文判断标签不是临床诊断；GFP 回归分数也不是某种湿实验结果已经被验证。发生不确定性时准确说明证据边界，而不是生成更自信的解释。

| 现象 | 优先检查 | 不应立即采取的做法 |
|---|---|---|
| OOM | 实际可见显存、输入长度、micro-batch、梯度检查点、并行方式 | 直接断言 H200 不够，或只改 epoch |
| train loss 降而验证变差 | 数据量、标签质量、过拟合、lr、类别分布 | 继续增加 epoch 直至训练 loss 最低 |
| 总预测 yes | 类别不均衡、模板、监督 token、弱数据标签分布 | 仅报 Accuracy |
| JSON 失败多 | 模板/停止符/目标格式、thinking 开关、输出长度 | 在评分时偷偷用正则修正输出 |
| 微调反而退化 | 基线已强、数据噪声、学习率、checkpoint、量化影响 | 认为训练越久越好 |
| 运行失败而单元测试通过 | GPU/依赖/API/模型下载/真实字段 | 把本包本地测试当作 H200 集成验证 |
| 生物关系看似正确但 F1 低 | 实体跨度、归一化 ID、关系方向、否定与缺失标注 | 只展示人工挑选的几个例子 |

## 课程完成后优先做什么

优先扩大经审核的开发评估与独立外测，再考虑更大模型、领域继续预训练、偏好优化或复杂多卡策略。本课程不需要先投入 DPO/GRPO、全量 PubMed 抓取或 70B 模型，才能学到最关键的微调与生物数据实践。
