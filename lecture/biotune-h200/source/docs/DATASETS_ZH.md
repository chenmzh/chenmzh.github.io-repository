# 数据集准备与使用方案

## 交付边界

本包已经包含 12 条原创、明确虚构的流程测试样例，以及可执行的正式数据获取/转换脚本。**完整 PubMedQA、TAPE 和 BioRED 数据不在压缩包内。** 原始公开数据下载未在当前环境成功，故没有把它们描述为“已下载并清洗”。正式数据需要在你的联网环境运行脚本获取，或使用指定源下载后以本地参数输入。

## 数据清单

| 数据 | 大小/任务 | 课程角色 | 获取与切分 | 许可与局限 |
|---|---|---|---|---|
| PubMedQA PQA-L | 1,000 条专家标注；yes/no/maybe 文献问题 | 第一套正式 SFT 与评估数据 | `prepare_pubmedqa.py`；保留官方 500 测试，其余自定义 450/50 | 仓库 MIT；来源摘要版权单独核查；规模小且公共基准可能被预训练见过 |
| PubMedQA PQA-A | 官方称约 211.3k 条人工构造问题 | 选修弱标注扩展 | `--artificial 10000` 起步；单独训练阶段；排除与 PQA-L 的精确重叠 | 不是专家标注；必须报告标签分布、噪声与抽样版本 |
| PubMedQA PQA-U | 官方称约 61.2k 条未标注问题 | 只用于讲解未标注语料边界 | 不默认下载，不直接当作有可靠答案的 SFT 数据 | 可研究领域继续预训练或检索，但不凭空补“金标准”标签 |

| TAPE GFP fluorescence | 21,446 train / 5,362 valid / 27,217 test；序列回归 | 真正的蛋白质序列任务 | `prepare_fluorescence.py`；保持原始划分 | TAPE 代码 BSD-3-Clause 不等于所有底层数据采用同一许可；引用原始 GFP 数据论文 |

## 为什么不以医学考试题作为主线

医学考试多选题可以测答题知识，但不等同于读生物研究证据，更不等同于蛋白质或基因组序列建模。主线优先选择有文献上下文的 PubMedQA，再把 BioRED 与 GFP 预测作为生物学相关扩展。临床医考数据可在目标确实是医考问答时单独加入，而不是为了堆积条数。

## SFT 记录格式

```json
{
  "id": "record-id",
  "pmid": "source-pmid",
  "source": "PubMedQA/PQA-L",
  "prompt": [
    {"role": "system", "content": "仅根据证据判断，并输出固定 JSON。"},
    {"role": "user", "content": "Question: ...\n\nEvidence:\n..."}
  ],
  "completion": [
    {"role": "assistant", "content": "{\"decision\": \"yes\"}"}
  ],
  "gold": "yes",
  "question_sha256": "...",
  "context_sha256": "..."
}
```

这是字段说明，不是一条真实科学样本。实际课程 prompt 为英文，输出仍是 JSON。元数据、哈希和 `gold` 不进入 tokenizer；训练代码显式只处理 `prompt` 和 `completion`。

**不能输入的字段：** `LONG_ANSWER`、`final_decision`、`reasoning_required_pred`、`reasoning_free_pred`。前者是结论，后几项是标签/预测，作为输入会污染证据判断任务。以后做“给摘要写结论”时可以把结论当目标，但那是另一个任务，不能混报为同一种设置。

测试文件分为输入和标签两份，降低误用风险。这是工程约束，不是加密保护；真正的流程约束仍依赖实验记录、权限与团队纪律。

## PubMedQA 质量检查

已实现的脚本检查：源文件内容身份、总行数、官方测试 PMID、标签一致性、必填字段、允许标签、分层开发切分、跨 split 的 PMID/问题/上下文精确重复、来源与输出文件 SHA-256。检测到跨 split 精确重复时停止，不偷偷把官方测试样本挪到训练集。

**尚未实现自动化的检查：** 语义近重复、同一论文改写题、版本之间的相关研究、标签专家复核、预训练污染。第二轮实验可按问题与摘要 shingle/向量相似度筛查候选，再人工检查。不要把精确哈希去重写成“已彻底消除数据泄漏”。

只用 50 条开发集可以教学，但超参数搜索会很不稳定。为了可靠比较，可在非测试的 500 条中使用原作者 CV 协议，或预先固定额外开发语料；不得把官方 test 当作验证集反复调整。

## 弱标注数据策略

从 PQA-A 取 10,000 条是建议起点，不是保证最佳的规模。先记录来源 commit、样本 ID 与标签分布；抽查问题是否自然、证据是否足够、答案是否与证据一致。脚本阻断全部 1,000 条 PQA-L 与弱数据的精确重叠。

两阶段对照：A 组仅 PQA-L 训练；B 组先 PQA-A，再 PQA-L。保持基座、模板、验证集、评估设置一致。优先报告“弱数据带来的变化”，而不是只展示成绩较好的模型。

不要直接把未标注数据交给大模型生成答案后当作专家标注。合成数据必须标记生成来源、生成模型/版本、证据出处及审核情况；“解释很流畅”不代表科学正确。

## 更偏基础生物学的自建数据配方（建议，不是已附数据）

可选目标：基因功能文献阅读、代谢通路关系抽取、细胞生物学论文结构化总结。

第一轮建议建立一个经过审核的较小集合，例如 1,000–3,000 条任务样本，而不是上来生成几十万条。按**论文/项目**先切分，再派生问题、摘要、翻译与解释；同一论文的中英文版本必须留在同一个 split。标记证据定位和许可。这里的数量是课程规划值，不是领域最佳实践的实测阈值。

若同时训练问答、实体抽取、关系抽取、总结与拒答，分别保留 task 标签和评估集，避免“总分”掩盖某项能力退化。任务比例必须以验证集和目标需求来选择，本包不把某个固定比例冒充通用最优配方。

中文扩展先用人工复核的专业术语表及少量双语样本：核对基因符号、缩写、剂量/单位、正负向关系与否定词。英文题的中文翻译不是新的独立测试题。

## GFP 序列回归检查

脚本只接受氨基酸字符串与有限数值标签；记录长度范围、标签范围、重复序列和跨 split 精确序列重叠。保持原始划分，不随机重分。若发现重叠，只记录并警告，不能一边修改 benchmark 一边声称还是同一标准任务。

`log_fluorescence` 已是上游变换后的量，不要再随意取对数。训练中的均值/标准差只在训练集计算；验证/测试恢复至该原始 log 尺度后报告 RMSE/MAE。

同一 GFP 家族的突变体测试不能证明对所有蛋白家族、酶功能或实验条件都有效。预训练时见过近似序列，也与下游标签泄漏不是同一回事；都需要独立披露。

## 许可和隐私

为每个数据源保存许可说明、获取日期、来源地址和版本标识。公开可访问不代表无限制训练、再分发或商业使用。PMC OA 的许可逐篇不同，批量获取应采用官方允许的途径。真实患者病历不纳入本入门包；后续研究使用须另行处理授权、隐私与访问控制。
