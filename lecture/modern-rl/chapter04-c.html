07$V$ 给局面打分；要比较动作，还要把第一步固定下来

状态价值把策略会选的动作平均在一起。可 agent 真正面临的问题是：此刻先做左还是右？

action-value function（动作价值函数）记作 $Q^\pi(s,a)$：当前在状态 $s$，先指定动作 $a$，之后再按照策略 $\pi$ 行动时，未来回报的期望。

$$Q^\pi(s,a)=\mathbb{E}_\pi\left[G_t\mid S_t=s,\ A_t=a\right]$$
STATE VALUE

$V^\pi(s)$

还没指定第一步动作；由策略 $\pi$ 选择，并把各动作的长期结果平均起来。

ACTION VALUE

$Q^\pi(s,a)$

第一步动作 $a$ 已固定；从下一步开始，才重新交回策略 $\pi$。

两者的区别只发生在第一步动作是否已经作为条件固定：$Q$ 拆开各动作，$V$ 再按策略概率把它们合回去。

因此 $V^\pi(s)$ 正是同一状态下各个 $Q^\pi(s,a)$ 按策略概率的加权平均：

$$V^\pi(s)=\sum_{a\in\mathcal A}\pi(a\mid s)Q^\pi(s,a)$$

数值检查：若策略有 70% 概率向右、30% 概率向左，而 $Q^\pi(s,\text{右})=10$、$Q^\pi(s,\text{左})=4$，那么：

$$V^\pi(s)=0.7(10)+0.3(4)=8.2$$

$Q^\pi$ 自己也能一步拆开。第一步动作已经固定，所以不再对当前动作按 $\pi$ 平均，只对这个动作造成的环境后果取平均：

$$Q^\pi(s,a)=\sum_{s'}P(s'\mid s,a)\left[R(s,a,s')+\gamma V^\pi(s')\right]$$
Insight 05

$V$ 与 $Q$ 不是两套互不相干的评分系统

$Q$ 把当前动作拆开来评价；$V$ 再按照策略会怎样选择，把这些动作价值合回一个状态价值。

从 $V$ 到 $Q$ 多的是“先做哪个动作”这一项条件；从 $Q$ 回到 $V$ 做的是按策略概率求平均。

08把公式落到最小代码：右侧计算新值，左侧保存估计

代码不需要先变复杂。固定策略走廊里，动作与下一状态都唯一，贝尔曼备份只有四行核心逻辑。

# corridor: S0 -> S1 -> S2 -> G
# entering G gives +1; V(G) stays 0
values = [0.0, 0.0, 0.0, 0.0]
rewards = [0.0, 0.0, 1.0]

def backup(old_values, gamma):
    new_values = old_values.copy()
    for state in range(3):
        next_state = state + 1
        new_values[state] = (
            rewards[state] + gamma * old_values[next_state]
        )
    new_values[3] = 0.0  # terminal state
    return new_values
数学对象代码变量在完整公式里的位置
$V_k(s)$old_values[state]备份前对当前状态的估计
$V_k(s')$old_values[next_state]右侧读取的下一状态旧估计
$R(s,a,s')$rewards[state]这条转移的即时奖励
$\gamma$gamma下一状态价值的折扣权重
$V_{k+1}(s)$new_values[state]本轮右侧算出的新目标
$\pi,P$没有显式数组因为策略和转移在此都确定，求和各只剩一项

这里特意同时保留 old_values 与 new_values。这样每个状态都读取同一轮旧表，页面实验才会呈现“一轮传播一条边”。如果边算边覆写同一个数组，后面的状态可能立刻读到本轮新值，传播速度会改变；那是另一种更新时序，不是价值定义发生了变化。

09贝尔曼方程给出自洽条件，但不会凭空送来环境知识

知道“真价值必须满足什么关系”，和知道“现实里怎样得到这些数字”，是两个问题。

$$\underbrace{V^\pi(s)}_{\text{真正价值}}=\underbrace{\sum_a\pi(a\mid s)\sum_{s'}P(s'\mid s,a)[R(s,a,s')+\gamma V^\pi(s')]}_{\text{同一个真正价值必须满足的关系}}$$

如果完整知道 $\pi$、$P$ 与 $R$，就能像实验那样对所有动作和下一状态精确求平均。但 Chapter 03 已经提醒过：MDP 用 $P$ 描述世界，不代表 agent 能读取完整的 $P$。现实中，环境常常只是一个 step() 黑盒，每次只返回实际发生的一条 $(s,a,r,s')$。

KNOWN MODEL

能计算完整期望

查询每个 $P(s'\mid s,a)$ 与 $R(s,a,s')$，把所有分支按概率加权。

BLACK-BOX ENVIRONMENT

只看到发生的一条经验

走一步得到一个 $r$ 和一个 $s'$；其他本可能发生的分支这次没有出现。

左边能一次枚举全部分支；右边每次只看到一个样本。贝尔曼关系没有改变，改变的是右侧期望可用什么证据来估计。

终止状态和“时间到了”不能混成同一个边界

走廊里的 G 是 terminal state（终止状态）：进入它时拿到 $+1$，任务本身随后结束，之后不会再有奖励，所以定义 $V^\pi(G)=0$。若采样只是因为最大步数或页面预算耗尽而停止，那叫 truncation（截断）；环境中的任务可能仍在继续，不能仅因为记录在此中断，就自动断言下一状态价值为 0。怎样从截断处保留后续价值，会在下一章讨论更新目标时处理。

容易想错

“写出了贝尔曼方程，就已经算出了 $V^\pi$。” 不对。方程说明正确答案必须怎样前后一致；要得到数值，还需要环境模型、交互数据，或二者的某种组合。页面实验能直接备份，是因为走廊规则被完整写进了代码。

Insight 06

贝尔曼方程统一了目标，却没有统一信息来源

不同方法可以追求同一种“当前估计与一步未来相一致”，但它们可用的信息完全不同：有的读取完整环境规则，有的等待整条轨迹，有的只观察一步。

这正是下一章要建立的坐标系：你知道什么、要等多久、是否用当前估计帮助更新。

10检查你的理解：你是在评价一次结果，还是一个未来分布？

每题都要求说清条件和平均对象。只记住“当前价值等于奖励加下一价值”还不够。

1. 两个动作的即时奖励都是 0，为什么动作价值仍可能不同？
因为动作还会改变下一状态，而下一状态携带不同的未来奖励机会。$Q^\pi(s,a)$ 计算的是即时奖励加后续价值的期望，不只看当前 $r_t$。
2. 从同一状态跑出一次 $G_t=12$，能否断言 $V^\pi(s)=12$？
不能。12 是一条实际轨迹的回报样本；$V^\pi(s)$ 是固定起点与后续策略后，对所有可能轨迹回报的期望。只有未来完全确定时，单次 $G_t$ 才必然等于 $V^\pi(s)$；随机情况下，需要汇总许多同条件 return 样本，其平均才可能逐渐接近 $V^\pi(s)$。
3. 为什么 $V(s)$ 最好写成 $V^\pi(s)$？
因为同一个状态由不同策略接手，会产生不同动作分布、访问不同后续状态，因而得到不同的回报分布。上标说明正在评价哪一条固定策略。
4. 贝尔曼期望方程里的两层求和分别在平均什么？
内层按 $P(s'\mid s,a)$ 对一个动作可能造成的环境后果取平均；外层按 $\pi(a\mid s)$ 对固定策略可能选择的动作取平均。
5. 在实验中，为什么第一次同步备份只让 S2 变成 1，而 S1 仍是 0？
本轮所有状态都只读取第 0 轮旧表。S2 直接进入目标，能看到即时奖励 +1；S1 读取的仍是 $V_0(S2)=0$。到第二轮，S1 才能用上一轮出现的 $V_1(S2)=1$。
6. $V^\pi(s)=\sum_a\pi(a\mid s)Q^\pi(s,a)$ 在说什么？
$Q^\pi(s,a)$ 先固定每个候选动作分别评价；$V^\pi(s)$ 不固定第一步，因此按策略在该状态选择各动作的概率，把这些动作价值加权平均回来。
7. 为什么写出贝尔曼方程仍不能直接解决黑盒环境里的价值估计？
完整右侧需要 $P$、$R$ 和下一状态价值。黑盒环境通常不提供所有分支的概率与奖励，只给一次实际 transition。还需要规定怎样从模型或数据构造可用的更新目标。

第四章真正建立起来的压缩

许多可能轨迹
→
期望回报
→
$V^\pi(s)$ / $Q^\pi(s,a)$
→
一步贝尔曼关系

$G_t$ 描述一条实际未来，$V^\pi$ 与 $Q^\pi$ 描述固定条件下许多未来的平均；贝尔曼期望方程再把这份长远评价压缩成“一步奖励 + 下一状态价值”的自洽关系。
