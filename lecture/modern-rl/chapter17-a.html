Chapter 17 · Reasoning models and inference-time compute

为什么增加思考 token 和采样次数能改善推理？

Chapter 16 已经用 GRPO 与 RLVR 让“得到可验证正确结果的轨迹”更常出现。可训练结束后，模型参数就固定了：面对同一道难题，我们还能不能靠多写一段草稿、多采几条候选，把偶然走错的机会降下来？本章把这件事变成一笔可以计算的质量—成本账。

本章核心问题：增加思考 token 或采样次数，究竟在什么假设下提高成功率？为什么候选更多不等于交付结果一定更好，又该在什么时候停止加计算？

01训练完了，单次回答仍可能只是“这次没发挥好”

把模型训练得更强，与让固定模型在当前题上发挥得更充分，是两个发生在不同时间尺度的问题。

假设一个模型已经会用因式分解解 $x^2-5x+6=0$，但随机生成时，有时写出正确的 $(x-2)(x-3)$，有时把符号抄错。第一次答错不一定表示模型完全没有这项知识；也可能只是这次采样走进了低概率的错误路径。

TRAINING COMPUTE

改变参数，扩大能力集合

继续预训练、监督微调或强化学习，让模型学会原本不会的方法，并提高好轨迹的生成概率。

回答“模型会不会？”
INFERENCE-TIME COMPUTE

固定参数，重新分配当前预算

在同一道题上生成更长草稿、更多候选或更多轮检查，让模型更接近已有能力上限。

回答“这次怎样发挥出来？”

真正要观察的是“参数是否更新”：左边改变策略本身；右边保持同一个模型，只改变当前请求消耗的计算量。

test-time compute / inference-time compute（测试时／推理时计算），指模型参数已经固定后，为一次请求投入的生成、检查、采样和聚合计算。两种说法在本章同义；“test-time”强调研究评测，“inference-time”更贴近部署。

容易想错

“多采样是在偷偷继续训练模型。” 不对。训练会更新参数 $\theta$；推理时扩展保持 $\theta$ 不变，只从同一分布 $\pi_\theta(\cdot\mid x)$ 多取样或延长当前轨迹。请求结束后，模型没有因此永久学会新知识。

Insight 01

训练计算提高上限，推理计算减少“没发挥出来”

增加当前请求的计算，最擅长修复选错路线、漏掉检查和偶然算错；它很难补出模型分布里根本不存在的知识。

先区分“完全不会”和“偶尔会”，才能判断下一份算力应该花在训练，还是花在当前题的多次尝试上。

02推理模型：先把一部分 token 当草稿，再把答案交出去

传统短答像“看到题目立刻落笔”；推理模型则允许先列条件、试路线、检查矛盾，再组织最终答案。

reasoning model（推理模型）是被训练为在最终答案前分配较长中间计算、检查或工具反馈的语言模型。Chain-of-Thought（CoT，思维链）是把问题连接到答案的一串中间推理步骤；它可以表现为可见文本，也可以只是服务内部使用的推理 token。

DIRECT ANSWER
问题→答案

路径短、延迟低；第一步方向错时，没有显式检查空间。

REASONING MODEL
问题→列条件 · 尝试 · 验算→答案

中间计算为纠错提供机会，但更长不自动意味着更正确。

因果差别不是“有没有写解释”，而是最终作答之前是否真的分配了可用于尝试和检查的计算；面向用户的整理解说也不等同于原始内部推理。

例如分解 $x^2-5x+6$，一条有用的短思维链可以是：

  1. 寻找乘积为 $6$、和为 $-5$ 的两个数：$-2,-3$。
  2. 写成 $(x-2)(x-3)=0$。
  3. 得到 $x=2$ 或 $x=3$，再代回原式验证两者都成立。

这里第三步确实减少了符号错误；若模型把同一个乘法再算十遍，却从不检查题设条件，新增 token 只是重复，不是有效计算。因此本章关注的不是“文本越长越好”，而是新增预算是否创造了新的候选、证据或纠错机会。

可见性边界：本讲义为了教学，会展示可以独立核查的推导；真实产品可以隐藏原始内部 CoT，只提供最终答案与整理后的依据。展示多少与推理是否正确是两个不同问题。

03从 Chapter 16 接过来：RLVR 把偶尔成功的轨迹变得更常见

Chapter 16 已经正式解释了 outcome verifier 与组内相对优势。本章只沿用它们的结论，不重讲 GRPO 更新式。

设模型面对问题 $x$ 时可能生成若干类轨迹 $z$：直接猜、列式后计算、换一种方法、最后验算。把选择第 $z$ 类轨迹的概率写成 $\pi_\theta(z\mid x)$，该类轨迹最终通过验证的概率写成 $s(z)$，则单次平均成功率可以写成：

$$p(x)=\sum_z \pi_\theta(z\mid x)\,s(z).$$

这个式子只是全概率公式：模型先按 $\pi_\theta$ 生成一种轨迹，再以 $s(z)$ 的概率成功。RLVR 给最终结果提供可验证奖励，使更常成功的整条轨迹获得更高概率，从而改变上式里的 $\pi_\theta$。

轨迹类型 $z$训练前概率该类成功率 $s(z)$对单次成功率的贡献
直接猜$0.60$$0.05$$0.030$
列式但不检查$0.30$$0.30$$0.090$
推导并验算$0.10$$0.70$$0.070$

训练前单次成功率为 $0.03+0.09+0.07=0.19$。若结果奖励把三类概率重排为 $(0.25,0.35,0.40)$，而各类内部成功率暂时不变，则：

$$p_{\text{after}}=0.25(0.05)+0.35(0.30)+0.40(0.70)=0.3975.$$

成功率提高，不要求奖励函数逐字写着“请验算”；只要“推导并验算”更容易得到最终奖励，它的整条轨迹概率就会被提高。但这不等于 RL 从零创造了验算能力：基座模型必须先以非零概率生成过这种行为，验证器才有机会选中并放大它。

Insight 02

所谓“推理涌现”，常常包含一次概率重排

没有逐步 CoT 标签时，反思和验算仍可能在 RL 后稳定出现；但要判断 RL 是“创造”还是“激活”，必须先检查基座模型多次采样时是否已经偶尔产生正确轨迹。

RLVR 提高的是通过结果验证的轨迹概率；预训练知识、采样覆盖和验证器共同决定有哪些轨迹可被强化。

04预算有两个基本方向：把一条路走深，或从多个起点重走

“多给 4,000 个 token”还不是完整方案。它们可以连在一条推理链后面，也可以拆给多条独立候选。

DEPTH · 更多思考 token

一条链继续推导与修订

保留已有中间状态，适合证明、复杂代码和多步规划。早期路线选错时，也可能沿错误前缀越走越远。

1 path × 4,000 tokens
BREADTH · 更多采样次数

从题目重新生成多条候选

覆盖不同起点，适合存在偶然采样错误、候选可以并行且最终结果可聚合的任务。

8 paths × 500 tokens

相同总 token 预算不代表相同效果：需要连续依赖时，深度保留上下文；首步路线容易选错时，广度提供不同起点。

这里要区分三个成本：总计算量近似随生成 token 总数增长；墙钟延迟取决于这些路径能否并行；验证成本来自执行测试、规则检查或评分模型。八条并行候选可能等待时间接近一条，却仍消耗约八倍生成计算。

容易想错

“并行生成八条，所以成本仍是一条。” 并行只把总工作摊到多块硬件上，主要缩短墙钟时间；八条候选的总 token、显存占用和后续验证工作并不会消失。

下一步先把“广度”算清楚：若单条候选有概率 $p$ 正确，采 $k$ 条以后，至少看见一次正确答案的概率是多少？这个量会给多采样一个最理想的质量上限。
