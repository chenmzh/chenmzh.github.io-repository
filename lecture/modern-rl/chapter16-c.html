09可验证结果奖励：让可执行规则检查结果

GRPO 规定怎样由一组 reward 更新策略，却不规定 reward 必须来自哪里。数学答案可自动判定时，可以把学习到的 Reward Model 换成规则验证器。

Reinforcement Learning with Verifiable Rewards（RLVR，可验证奖励强化学习）指用可自动复查的规则结果作为强化学习奖励。对数学题，最小 outcome verifier（结果验证器）通常做两件事：从完整回答中提取最终答案，再与 ground truth 做等价判断：

$$R_{\mathrm{verify}}(x,y)= \mathbf 1\!\left[\operatorname{equiv}\!\left(\operatorname{extract}(y),a^*(x)\right)\right]$$

$a^*(x)$ 是标准答案，$\operatorname{extract}$ 找到模型声明的最终答案，$\operatorname{equiv}$ 判断两种表示是否数学等价。这里的“verifiable”表示判定过程可重复执行、可写边界样例检查，不表示验证器自动等于任务真理。

横向问优化算法，纵向问奖励来源。GRPO 常与 RLVR 搭配，却不是同义词：GRPO 也能使用 Reward Model；RLVR 也能把规则 reward 接到 PPO 或其他策略优化器。

一个教学级数学 verifier 至少要过三类检查：

检查要避免什么边界样例
提取位置误把草稿或被否定的候选当最终答案“先猜 $7/8$，复核后答案 $9/8$”

误把正确答案判错叫 false negative（假阴性）；误把错误答案判对叫 false positive（假阳性）。在 RL 里，后者尤其危险，因为被奖励的错误样本会被主动增概率。更复杂的代码测试验证器留到 Chapter 21；验证器漏洞如何在强优化下形成系统性失败，则留到 Chapter 26。本章只看一个局部机制：一次判定错误怎样改变整组相对优势。

Insight 04

GRPO 与 RLVR 是两条正交选择

一个决定 advantage 和 policy loss 怎样构造，另一个决定 reward 的证据来自规则还是学习到的评分器。把两者拆开，才能准确定位失败发生在优化器还是裁判。

先问“分数从哪来”，再问“分数怎样变成梯度”。

10实验：只换验证器或组内结果，优势会怎样整体重排？

下面不训练真实模型，只把 GRPO 更新前最关键的数据管线摊开：同一 prompt 的四条回答 → verifier reward → 组均值与标准差 → 相对优势。

Question
同一组回答不变时，严格字符串、语义等价和“取第一个数字”的缺陷验证器，会怎样改变 reward 与 advantage？当四条回答全对或全错时又会怎样？
Prediction
假阴性会错误压低正确回答；假阳性会强化错误回答，而且它还会改变组均值与标准差，进而改写其他样本的优势。全同 reward 会让组内标准差为 0，整组没有相对梯度。
Experiment

默认的等价判断正确接受 $7/8$ 与 $0.875$，拒绝两条错误回答；reward 为 $[1,1,0,0]$，优势为 $[+1,+1,-1,-1]$。
Interpretation
GRPO 并不知道“正确”是什么，只忠实放大 verifier 提供的相对顺序。裁判错一条，不只污染一条 label，还会通过组内统计量影响整组更新尺度。

Insight 05

可执行只保证判定可重复，不保证判定含义正确

字符串比较每次都会给同样结果，却会拒绝数学等价表示；读取第一个数字也很稳定，却可能奖励已经被模型否定的草稿。确定性是好 verifier 的必要条件，不是充分条件。

训练前先用反例测试裁判；训练中同时记录通过率、解析失败与误判类型。

11把公式落到代码：保留回答轴，也保留 token 轴

下面是与上游手写代码地图一致的概念骨架。每一行都能回指一层公式；省略模型加载、分布式 rollout 与 optimizer 细节。

# [A] 当前批次由 old policy 对每个 prompt 采 G 条回答
responses, mask = generate_many(policy_old, prompts, num_generations=G)

# [B] RLVR: outcome verifier 给每段回答一个 reward
rewards = verifier(prompts, responses)              # [B * G]
grouped = rewards.view(batch_size, G)                # [B, G]

# [C] 同一 prompt 内构造 group-relative advantage
mean = grouped.mean(dim=1, keepdim=True)
std = grouped.std(dim=1, keepdim=True, correction=0)  # 与公式一致：除以 G
advantages = (grouped - mean) / (std + 1e-4)         # [B, G]
advantages = where(std < 1e-4, 0.0, advantages).view(-1)

# [D/E] 逐 token ratio 与 PPO-style clip
old_logps = per_token_logps(policy_old, prompts, responses).detach()
new_logps = per_token_logps(policy, prompts, responses)
ratio = exp(new_logps - old_logps)                   # [B * G, T]
adv = advantages[:, None]                            # 回答优势广播到 token
surrogate = minimum(
    ratio * adv,
    clip(ratio, 1 - clip_eps, 1 + clip_eps) * adv,
)

# [F] 当前 policy 相对冻结 reference 的逐 token KL
ref_logps = per_token_logps(reference, prompts, responses).detach()
delta = ref_logps - new_logps
per_token_kl = exp(delta) - delta - 1

# [G] 先按每段回答有效 token 平均，再按回答平均
objective = masked_sequence_mean(
    surrogate - beta * per_token_kl, mask
).mean()
loss = -objective

12检查你的理解：你能把“裁判”与“更新器”分开吗？

先遮住答案。若能从一组 reward 手算优势，并解释 old、reference、verifier 各自负责什么，就已经掌握本章主线。

1. GRPO 为什么必须让同一个 prompt 生成多条回答，而不是直接把整个 batch 的奖励一起标准化？
同一 prompt 固定了题目条件，组内差异才主要反映回答采样差异。跨 prompt 混合会把题目难度也塞进 advantage：简单题的普通回答可能压过难题的优质回答，失去“相对同题预期”的含义。
2. “GRPO 不需要 Critic”是否等于“不需要 baseline”？
不等于。GRPO 仍执行奖励减基线，只是用同题 $G$ 条回答的组均值作为临时样本基线，不训练单独的价值网络。它减少 Critic 的显存与训练成本，同时付出同题多次 rollout 的采样成本。
3. 四条二值 reward 为 $[1,0,0,0]$ 时，总体标准差口径下优势是多少？
$p=1/4$，通过样本优势为 $\sqrt{(1-p)/p}=\sqrt3\approx1.732$；三个失败样本各为 $-\sqrt{p/(1-p)}=-1/\sqrt3\approx-0.577$。优势之和为 0。
4. 为什么 $[1,1,1,1]$ 与 $[0,0,0,0]$ 都通常跳过更新？两者语义一样吗？
两组标准差都为 0，组内没有相对排序，所以优势置 0。语义不一样：全对可能表示这道题已掌握；全错表示结果奖励过于稀疏，无法指出哪条更接近成功。算法层面同为零梯度，数据诊断层面必须分开记录。
5. $\pi_{\mathrm{old}}$ 与 $\pi_{\mathrm{ref}}$ 各自回答什么问题？
old policy 生成本批数据，与当前 policy 形成 importance ratio，回答“证据是否已经过期”；reference policy 是较长期冻结的行为锚点，与当前 policy 形成 KL，回答“行为是否漂得太远”。
6. 为什么 GRPO 与 RLVR 不能当作同义词？
GRPO 是策略优化算法，规定组内 advantage、ratio、clip 与 KL 怎样形成 loss；RLVR 是奖励来源，规定用规则 verifier 给结果打分。GRPO 可以接 Reward Model，RLVR 的规则 reward 也可以接 PPO 等其他算法。
7. 一个确定性的 verifier 是否一定适合 RLVR？
不一定。确定性只保证同样输入重复得到同样判定；严格字符串比较会稳定地产生假阴性，读取第一个数字会稳定地产生假阳性。还要检查最终答案提取、等价表示、边界输入和误判方向。
