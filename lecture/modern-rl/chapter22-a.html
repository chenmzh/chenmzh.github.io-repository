Chapter 22 · Research is a trajectory of evidence

搜索、阅读、引用如何形成长轨迹？

上一章的代码智能体有一个强验证器：补丁能否通过测试。研究型智能体面对的真值没有那么整齐——一句话可能碰巧正确，引用却指向错误的人；来源可能真实存在，却根本不支持相邻论断。于是研究不能只把答案当终点，还必须保存从问题走到证据的整条路径。

本章核心问题：怎样把搜索、打开网页、阅读、点击、保存引用与提交答案写成 RL trajectory？又怎样分别测量答案、证据、过程与成本，而不是让一个漂亮总分掩盖归因错误？

01答案碰巧正确，为什么仍可能是一条失败轨迹？

代码测试主要检查“产物是否满足契约”；研究报告还要检查“每个关键论断是否真的由访问过的来源支持”。

设问题是“论文第一作者本科毕业于哪所大学？”模型最后都回答 Example University。下面三条轨迹的最后一句一样，研究质量却完全不同：

MEMORY ONLY

直接凭记忆回答

答案可能正确，但没有访问记录，也无法证明信息来自哪里。

answer ✓ · evidence 0/3
WRONG ENTITY

引用同名人物主页

URL 真实、文字相关，却不是论文作者本人，归因链断裂。

answer ✓ · attribution ✕
EVIDENCE CHAIN

先消歧，再引用教育经历

论文页确认姓名与单位，学校主页再支持教育事实。

answer ✓ · evidence 3/3

真正要观察的是“正确答案”与“可验证研究”之间的缺口：只有第三条轨迹把身份、结论和引用连接成了同一条证据链。

Deep Research Agent（深度研究智能体）不是“多搜索几次”的聊天模型，而是把问题分解、检索、阅读、交叉核对、保存证据与报告写作组织成长轨迹的策略。它的输出不仅是文本 $\hat y$，还包括可以回放的动作历史与证据集合 $E$。

Insight 01

Research 的最小交付不是答案，而是“答案—论断—证据”的绑定

答案正确只说明终点碰对了；来源归因还要证明这条路线确实读到了能够支持结论的材料。

验证研究轨迹时，要问“证据是否支持这句话”，而不只是“这个 URL 能不能打开”。

02把会变化的网页封装成可重复实验台

Browser RL Harness（浏览器强化学习实验台）把模型、搜索服务、网页读取器、轨迹日志与验证器接在一起，使一次研究能够 reset、step、回放和评分。

QUESTION研究问题 + 预算
→
POLICY选择下一动作
→
WEB ENV返回页面观察
→
VERIFIER检查答案与证据

闭环中真正可训练的是策略产生的动作；网页文本属于环境观察，验证器在终点把答案、证据和预算转换成反馈。

完整浏览器状态 $s_t$ 包含当前 URL、Document Object Model（DOM，文档对象模型）、会话、滚动位置、缓存和网络状态；策略通常只看到抽取正文、搜索结果、页面摘要和研究笔记组成的观察 $o_t$。因此更准确的写法是：

$$o_t\sim O(\cdot\mid s_t),\qquad a_t\sim\pi_\theta(\cdot\mid q,o_{\le t},a_{<t}),\qquad s_{t+1}\sim P(\cdot\mid s_t,a_t).$$

$q$ 是原始研究问题，$O$ 是状态到可见观察的映射，$P$ 则提醒我们真实网页并非确定环境：同一个 URL 可能更新、超时或重定向。只保存最终报告，会把策略失败和网页失败混在一起。

Harness 对象研究任务里的实例日志中必须保存
观察 $o_t$搜索结果、正文片段、当前笔记内容、抓取时间、工具状态
动作 $a_t$查询、打开、点击、读取、引用、回答原始模型输出与解析动作
转移新页面、失败提示、重定向下一观察与错误类别
终止提交答案、超预算、不可恢复错误终止原因，不能只写 reward=0

03从 search 到 cite：每个动作解决不同的信息缺口

搜索负责扩大候选集合，阅读负责取得内容，引用负责把内容绑定到论断。把它们压成一个“browse”动作，会失去可解释的信用分配。

search(query)提出可检索的问题
open(url)进入候选来源
click(target)处理分页或动态页面
read(scope)抽取正文、表格或段落
cite(claim, span)保存论断—证据边
answer(text)提交结论并终止

动作链的因果关系是：search/open/click 改变可见页面，read 把页面变成可用观察，cite 再把观察中的具体片段绑定到报告论断；引用不是事后补 URL。

ACTIONS = {
    "search": {"query": str},
    "open":   {"url": str},
    "click":  {"target": str},
    "read":   {"scope": str},
    "cite":   {"claim_id": str, "quote": str, "url": str},
    "answer": {"text": str},
}

一条最小可审计轨迹可以写成：

$$\tau=(q,o_0,a_0,o_1,a_1,\ldots,o_T,a_T,E,\hat y).$$

$E$ 不是散乱链接列表，而是一组 (claim_id, quote, url, visited_at) 记录。这样验证器才能检查某段引文是否来自实际访问页面、是否支持指定论断，以及同名实体是否已经消歧。

Insight 02

工具动作不只是“做事”，也在改变下一步能知道什么

一次查询改写会改变候选来源，一次阅读范围选择会决定哪些证据进入上下文，一次错误引用则会把正确事实绑到错误来源。

浏览器策略同时控制环境路径与信息路径，因此过程日志本身就是训练数据的一部分。
