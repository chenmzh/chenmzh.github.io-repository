Chapter 14 · Learning a reward from feedback

怎样把人类或 AI 的反馈变成训练信号？

上一章把探索、多个智能体和长任务放进了同一张决策图：奖励稀疏时，关键是怎样发现有价值的行为、又怎样分配功劳。到了大语言模型，问题再向前一步——一段回答可以看作很长的 token 轨迹，可是环境不会自动弹出一个“好回答 +1”。本章要搭起那条缺失的桥：把示范、比较与原则逐步变成策略能够优化的数。

01语言模型会续写，不等于它知道什么叫“好助手”

预训练告诉模型哪段文字常见；对齐训练还要告诉它，面对同一个用户请求，哪些行为更值得保留。

基座语言模型的训练目标是预测下一个 token。它能学会语言、知识和代码模式，却没有被单独要求“服从用户意图、承认不确定、控制风险”。例如用户说“只用三句话解释强化学习”，续写一篇教材、接着模拟一段论坛对话，在预训练分布里都可能自然；但只有一部分续写像可靠助手。

Reinforcement Learning from Human Feedback（RLHF，从人类反馈中进行强化学习）不是一个单独的 loss，也不包括从零预训练。经典流程从已有基座模型出发，依次产生三件可检查的产物：

STAGE 1示范微调后的模型示范教它怎样回答
→
STAGE 2偏好评分模型比较教它怎样评分
→
STAGE 3受约束更新后的策略按分数小步改行为

真正应观察的是每段箭头的数据契约：示范回答训练策略，成对比较训练评分器，评分器再为策略自己的新回答提供奖励；三种数据不能互相偷换。

Insight 01

这条反馈流水线的核心不是“人给一个分”，而是两次接口转换

人类首先提供相对偏好，评分模型把偏好压成可重复调用的标量；受约束的策略更新再把这个标量变成 token 概率的更新方向。

只说“用人类反馈训练”会藏掉最重要的误差来源：偏好数据可能有噪声，评分器也可能把偏好学错。

02先把一段回答重新写成 RL 轨迹

PPO 能接入语言模型，不是因为“LLM 很像 RL”，而是因为自回归生成本身就是一串条件决策。

给定 prompt $x$，已经生成的前缀是 $y_{<t}$。第 $t$ 步的状态、动作与策略可以写成：

$$s_t=(x,y_{<t}),\qquad a_t=y_t,\qquad \pi_\theta(a_t\mid s_t)=P_\theta(y_t\mid x,y_{<t}).$$
RL 对象语言模型中的对应物这一章真正困难的地方
状态 $s_t$prompt 与已生成前缀上下文很长，状态空间巨大
动作 $a_t$词表中的下一个 token每个位置都有大量候选
转移把选中的 token 拼到前缀几乎确定，真正难点不在动力学
episode从 prompt 到 EOS 的完整回答常有几十至数百步
奖励对完整 $(x,y)$ 的偏好分数通常结束后才出现，而且没有天然真值

一个 sequence-level score（序列级分数）只说整段回答好不好，并没有指出哪个 token 立功。Chapter 08–09 已经介绍 advantage、GAE 与 PPO 裁剪如何把延迟回报传回多个动作；本章不重新推导它们，而是专注于更靠前的问题：整段回答的 reward 到底怎样制造出来？

03监督微调：先给策略一个能工作的行为起点

Supervised Fine-Tuning（SFT，监督微调）把高质量的“指令—回答”当作监督样本。它先教模型怎样像助手行动，还没有比较两个回答谁更好。

设 $\mathcal D_{\mathrm{SFT}}$ 中每条数据包含 prompt $x$ 与示范回答 $y=(y_1,\ldots,y_T)$。规范的对话 SFT 只对 assistant 应生成的 token 计算负对数似然：

$$\mathcal L_{\mathrm{SFT}}(\theta) =-\mathbb E_{(x,y)\sim\mathcal D_{\mathrm{SFT}}} \left[\sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t})\right].$$

逐步读这条式子：

  1. $x$ 与此前正确 token $y_{<t}$ 作为上下文，不是本步要预测的标签；
  2. 模型给示范中的真实 token $y_t$ 一个概率；
  3. 真实 token 概率越大，$-\log$ 越小；
  4. 对回答位置求和、再对训练样本平均，得到 SFT loss。

一个三 token 手算例

简化地说，示范回答只有三个目标 token。模型起初给它们的条件概率依次为 $0.80,0.50,0.25$，那么整段负对数似然是：

$$-\log(0.80\times0.50\times0.25)=-\log(0.10)\approx2.303.$$

训练后概率变为 $0.90,0.70,0.50$，loss 变成 $-\log(0.315)\approx1.155$。这说明模型更会复现示范，但它仍未见过“另一个回答为什么更差”。

数学对象代码里的位置作用
$(x,y)$instruction, response一条高质量示范
对话格式tokenizer.apply_chat_template(...)固定 user / assistant 边界
$\mathcal D_{\mathrm{SFT}}$train_dataset送入 SFTTrainer 的样本集
$\mathcal L_{\mathrm{SFT}}$SFTTrainer.train()提高示范回答 token 的概率
容易想错

“SFT 是 RLHF 中的强化学习阶段。” 不对。SFT 是监督学习，也是经典 RLHF 的起点。真正按学习到的 reward 更新策略发生在后面的 PPO 阶段。

04Preference data：人更容易比较，而不是发明绝对分数

Preference data（偏好数据）通常写成 $(x,y_w,y_l)$：同一个 prompt 下，$y_w$ 是 chosen（更偏好的回答），$y_l$ 是 rejected（较不偏好的回答）。

CHOSEN · $y_w$

准确、直接、有边界

先解释核心机制，再给一个最小例子；不知道的地方明确说明不确定。

REJECTED · $y_l$

流畅，却没有解决问题

重复用户问题、堆叠礼貌套话，最后没有给出可检查的答案。

要观察的不是 chosen 是否“完美”，而是同一 prompt 下的相对次序。标注没有定义跨 prompt 的统一十分制，也没有证明 chosen 中每句话都正确。

比较比绝对打分更稳：两位标注者可能对“7 分”与“8 分”的尺度理解不同，却更容易同意 A 比 B 好。但这个便利也带来边界：偏好标签只保留了顺序，选择理由、标注者分歧与 rubric（评判准则）必须另存元数据，否则后面无法解释 Reward Model 学到了什么。

Insight 02

偏好对消除了绝对分数尺度，却没有消除价值判断

chosen/rejected 不要求大家共享“8 分”的含义，但仍然要求人或 AI 决定准确性、帮助性、安全性之间怎样权衡。

数据格式更简单，不代表目标更客观；rubric 和来源仍是训练信号的一部分。

05偏好评分模型：把相对次序变成可以反复调用的标量

Reward Model（RM，奖励模型）读取 prompt 与完整回答，输出标量 $r_\phi(x,y)$。单个分数没有天然单位；真正有训练意义的是同一 prompt 下的分数差。

Bradley–Terry model（Bradley–Terry 模型，成对偏好概率模型）用两项潜在分数之差描述谁更可能胜出：分数更高的回答被选择的概率更大，而两个分数共同平移不改变比较结果。因此 chosen 胜过 rejected 的概率为：

$$\begin{aligned} P(y_w\succ y_l\mid x) &=\frac{e^{r_\phi(x,y_w)}}{e^{r_\phi(x,y_w)}+e^{r_\phi(x,y_l)}}\\ &=\frac{1}{1+e^{-[r_\phi(x,y_w)-r_\phi(x,y_l)]}}\\ &=\sigma\!\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right). \end{aligned}$$

第二行同时把分子分母除以 $e^{r_\phi(x,y_w)}$，于是绝对平移会消失：两个分数同时加 100，偏好概率不变。这正说明 RM 首先学的是排序，而不是有物理意义的“质量温度计”。

对真实标签做最大似然，等价于最小化成对负对数似然：

$$\mathcal L_{\mathrm{RM}}(\phi) =-\mathbb E_{(x,y_w,y_l)\sim\mathcal D_{\mathrm{pref}}} \log\sigma\!\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right).$$

分数差如何决定梯度强弱？

若 $r_w=2.0,r_l=0.5$，则差值为 $1.5$：

$$P(y_w\succ y_l)=\sigma(1.5)\approx0.818, \qquad \mathcal L_{\mathrm{RM}}=-\log0.818\approx0.201.$$

若顺序打反，$r_w=0.5,r_l=2.0$，概率变为 $\sigma(-1.5)\approx0.182$，loss 约为 $1.704$。更大的损失会产生更强修正，把 chosen 分数推高、rejected 分数压低。

上游实现用语言模型最后一个有效 token 的隐藏状态表示整段 $(x,y)$，再经线性 value_head 输出一个标量。训练时同一参数分别前向 chosen 与 rejected，核心代码与公式逐项对应：

r_chosen = model(chosen_ids, chosen_mask)
r_rejected = model(rejected_ids, rejected_mask)
loss = -torch.log(torch.sigmoid(r_chosen - r_rejected)).mean()
