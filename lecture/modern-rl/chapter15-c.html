08实验：同一个 log-ratio margin，beta 怎样改变 loss 与梯度？

不运行大模型，也能把 DPO 的核心机制看完整。下面把四条 log-prob 已经做完的两次减法直接暴露出来，让你操纵 $\ell_w$、$\ell_l$ 与 $\beta$。

Question
chosen/rejected 的 log-ratio 差 $\Delta$ 与 $\beta$，怎样共同决定偏好概率、DPO loss 和梯度强度？
Prediction
提高 $\ell_w$ 或降低 $\ell_l$ 会增大 $\Delta$，使偏好概率上升、loss 下降；改变 $\beta$ 会缩放 logit，但梯度还会受 sigmoid 饱和影响，不能把它当学习率。
Experiment
先保持默认值，核对上一节的手算；再令 $\ell_w=\ell_l$，最后交换二者。每种情况下把 $\beta$ 从小调大，比较 $L$ 与 $\partial L/\partial\Delta$。
Observation
默认 $\Delta=1.50$、$\beta=0.50$：模型给 chosen 胜出的概率约 0.679，loss 约 0.387，margin 梯度约 −0.160。
Interpretation
梯度为负意味着梯度下降会增大 chosen 相对 rejected 的 log-ratio；当正 margin 已很大时，sigmoid 饱和会让梯度趋近 0。
Limitation
这是单条偏好样本、序列 log-prob 已知的损失面切片；真实训练还受 token 长度、batch 中偏好噪声、优化器、模型参数共享和数据覆盖影响。

09公式落到代码：四次序列打分，只有 policy 接收梯度

上游脚本用 TRL 的 DPOTrainer 封装训练。要读懂日志和排错，仍应能把 trainer 展开成最小数据流。

# batch 提供同一个 prompt 下的一对回答
policy_chosen = sequence_logprob(policy, x, chosen)      # p_w
policy_rejected = sequence_logprob(policy, x, rejected)  # p_l

with torch.no_grad():
    ref_chosen = sequence_logprob(reference, x, chosen)      # p_w^0
    ref_rejected = sequence_logprob(reference, x, rejected)  # p_l^0

chosen_logratio = policy_chosen - ref_chosen
rejected_logratio = policy_rejected - ref_rejected
dpo_logits = beta * (chosen_logratio - rejected_logratio)
loss = -F.logsigmoid(dpo_logits).mean()

optimizer.zero_grad()
loss.backward()      # reference 没有梯度
optimizer.step()     # 只更新 policy
公式最小实现变量上游训练脚本里的入口常见错误
$(x,y_w,y_l)$prompt, chosen, rejectedDataset.from_dict(data_dict)把 chosen/rejected 颠倒或来自不同 prompt
$\log\pi(y\mid x)$sequence_logprob(...)由 DPOTrainer 内部计算把 prompt token 也计入回答 loss，或误用单个 token 概率
$\ell_w,\ell_l$chosen_logratio, rejected_logratiopolicy 与冻结 reference 的 log-prob 差只拿 raw policy log-prob 做好减坏
$\beta$betaDPOConfig(beta=0.1)把它当学习率，或脱离 margin 单独解释
$-\log\sigma(\beta\Delta)$-F.logsigmoid(dpo_logits)DPOTrainer.train()先算 sigmoid 再取 log，造成不必要的数值不稳定

训练日志中，rewards/chosen 与 rewards/rejected 对应 $\beta\ell_w$ 和 $\beta\ell_l$ 的 batch 统计；二者之差是 reward margin，chosen 高于 rejected 的样本比例是 reward accuracy。loss 下降只说明训练偏好似然改善，最终仍要在留出 prompt 上检查事实性、安全性、风格与能力是否真的更好。

10DPO 家族：每个分支都在放松一个不同约束

下面只建立选型坐标，不再推导五套损失。问清楚“我有什么数据、是否能放下 reference、希望 margin 怎样停止”，比背算法年份更有用。

方法反馈数据需要 reference相对 DPO 改了什么先问哪一个现实问题
DPO（直接偏好优化）chosen/rejected 对是$-\log\sigma(\beta\Delta)$有稳定偏好对，先用经典基线能否工作？
Identity Preference Optimization（IPO，恒等偏好优化）chosen/rejected 对是用平方损失把 $\Delta$ 推向有限目标 $1/(2\beta)$，避免噪声偏好被无限拉开是否担心 noisy pair 被无限拉开？
Kahneman–Tversky Optimization（KTO，卡尼曼–特沃斯基优化）单条 desirable / undesirable 标签是不要求同 prompt 的成对比较，引入反馈基线与好坏权重产品日志只有点赞/点踩怎么办？
Simple Preference Optimization（SimPO，简单偏好优化）chosen/rejected 对否用长度归一化的 policy log-prob 与目标 margin 取代 referencereference 的显存与前向成本是否成为瓶颈？
Odds Ratio Preference Optimization（ORPO，优势比偏好优化）chosen/rejected 对否把 chosen 的监督似然与 chosen/rejected odds-ratio 惩罚合在一起是否想在一阶段同时保留 SFT 与偏好排序信号？

这不是“越往下越先进”的排行榜。各行删除或更换的组件不同：KTO 改数据形态，SimPO/ORPO 去 reference，IPO 改 margin 的目标形状；选择取决于真实约束。

家族名会继续增加，但本章只保留一个不变骨架：回答概率怎样被比较、比较相对谁、标签来自什么数据生成过程。如果说不清这三点，即使能背 loss，也无法判断训练曲线究竟在奖励什么。

11离线偏好不是免费的 RL 替代品

DPO 把工程链路缩短了，也把上限更直接地交给了固定数据。它不会自动发现数据里从未出现的更好回答。

DATA SUPPORT

只能比较数据里出现过的方向

固定 pairs 没有训练期探索。若数据缺少某类任务或失败模式，loss 无法凭空提供纠正证据。

LABEL NOISE

比较者偏差会成为策略偏差

标注歧义、位置偏差、长度偏好与 self-preference 都可能被模型当作目标学习。

RELATIVE SIGNAL

“更好”不等于“足够好”

若一对回答都错误，chosen 仍会胜出。相对排序不能替代绝对正确性、安全红线或任务验证。

REFERENCE DRIFT

有 reference 不等于永不偏离

reference 定义相对坐标和正则来源，但有限数据、超参和反复优化仍可能损伤通用能力。

四格的共同因果链是“数据决定可见差异 → 损失放大这些差异 → 生成行为继承其盲区”。算法简化不能修复偏好数据没有表达的目标。

Insight 05

偏好 loss 衡量标签拟合，任务成功需要额外证据

较低 DPO loss 可以与事实性退化、回答变长或安全性下降同时发生，因为 pair 标签可能没有隔离这些维度。

最小评估单元不是一条 training loss 曲线，而是留出偏好准确率、chosen/rejected 动态和真实任务行为的联合检查。

12理解检查：你能从偏好概率重新推出 loss 吗？

DATA同一 prompt 的偏好对$(x,y_w,y_l)$
→
REFERENCE比较相对训练起点的变化$\ell=\log\pi_\theta/\pi_{ref}$
→
MARGINchosen 变化减 rejected 变化$\Delta=\ell_w-\ell_l$
→
LIKELIHOOD让观察到的偏好更可能$-\log\sigma(\beta\Delta)$
1. chosen 是否等于“绝对正确答案”？
不等于。chosen 只表示在同一 prompt 的这一对回答里被比较者偏好。两条回答可能都不完美，标签也可能混入长度、风格或标注者偏差。
2. 为什么 DPO 需要“2 个模型 × 2 个回答”的四条 log-prob？
policy 和 reference 都要分别给 chosen、rejected 计算序列 log-prob。先做 policy−reference 得到两条相对变化，再做 chosen−rejected 得到偏好 margin；只看 policy 的绝对概率会失去训练起点的坐标。
3. Bradley–Terry 模型中，两个回答奖励相等时 chosen 胜出的概率是多少？
奖励差为 0，所以 $P=\sigma(0)=0.5$。标签说 chosen 胜，但当前模型尚没有区分两者的证据。
4. 为什么反解奖励时的 $\beta\log Z(x)$ 可以消失？
$Z(x)$ 只依赖共同 prompt，对 $y_w$ 和 $y_l$ 完全相同。BT 只使用奖励差，因此两个相同的 $\beta\log Z(x)$ 相减为 0。
5. 若 $\pi_\theta=\pi_{ref}$，一条偏好样本的 DPO loss 是多少？
两条 log-ratio 都为 0，$\Delta=0$，偏好概率为 0.5，因此 $L=-\log0.5=\log2\approx0.693$。这表示策略相对 reference 尚未学习这条排序。
6. “beta 越大，就等于学习率越大”为什么错？
$\beta$ 是原始目标的 KL 惩罚系数，同时在 DPO loss 中缩放 margin logit。固定 $\Delta$ 时它改变偏好置信度和梯度，但梯度还会 sigmoid 饱和；优化器学习率则直接控制参数步长，两者不是同一对象。
7. 只有大量点赞/点踩而没有配对回答时，为什么标准 DPO 不直接匹配？
标准 DPO 的 $\Delta$ 需要同一 prompt 下 chosen 与 rejected 的成对差。单条 desirable/undesirable 反馈缺少配对项，更接近 KTO 所处理的数据形态；无论采用哪种方法，都仍需审查反馈偏差。
