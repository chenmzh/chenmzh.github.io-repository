09先把“按什么原则判断”写出来

Constitutional AI（CAI，宪法式人工智能）给模型一组自然语言原则，让 AI 依据这些原则批评、修订或比较回答。这里的 Constitution（宪法／原则集合）不是模型权重，也不是一个总分，而是可阅读、可讨论的评判准则集合。

例如，一条原则可以同时要求：“不要协助实际伤害；如果请求只是合法科普，则应在安全边界内尽量提供帮助。”它比笼统的“保持安全”多给了一层冲突处理：敏感话题不自动等于高风险行动。

SUPERVISED BRANCH · SL-CAI

批评 → 修订 → 再做 SFT

  1. 模型先生成原回答 $y_0$；
  2. 按原则 $c_k$ 生成 self-critique；
  3. 根据批评得到 revision $y^*$；
  4. 把 $(x,y^*)$ 当作新的示范。
REINFORCEMENT BRANCH · RL-CAI

比较 → 偏好对 → RM → PPO

  1. 同一 prompt 采样 $y_1,y_2$；
  2. AI judge 按 $c_k$ 选优；
  3. 偏好对训练 Reward Model；
  4. 按相同 PPO/KL 流程更新 Actor。

两条分支共同的因果变量是 Constitution；左边把“修订后的文本”变成监督标签，右边把“AI 的比较选择”变成偏好标签。它们不是同一个训练目标。

Self-critique 与 self-revision 是两个条件生成步骤

Self-critique（自我批评）先产出对原回答的文本诊断；self-revision（自我修订）再读取诊断和原则，生成修正版：

$$\begin{aligned} q&\sim\pi(\cdot\mid x,y_0,c_k,\text{“critique”}),\\ y^*&\sim\pi(\cdot\mid x,y_0,q,c_k,\text{“revision”}). \end{aligned}$$

$q$ 是一段解释“哪里违背原则”的文字，不是 reward；$y^*$ 才能作为新的 assistant 示范进入 SFT：

$$\mathcal L_{\mathrm{SL\text{-}CAI}} =-\mathbb E_{(x,y^*)}\log\pi_\theta(y^*\mid x).$$

Reinforcement Learning from AI Feedback（RLAIF，从 AI 反馈中进行强化学习）则把偏好标签的生产者从人类换成 AI judge。若 judge 按 Constitution 比较，就得到 CAI 的强化学习分支；但 RLAIF 也可以使用别的 rubric，因此：

RLAIF描述“反馈由 AI 产生”+Constitution描述“AI 按哪些显式原则判断”=RL-CAICAI 的强化学习路线

RL-CAI 产生的数据仍是 $(x,y_w,y_l)$，训练的 RM loss 与 PPO/KL 目标也没有换：

$$\mathcal D_{\mathrm{AI}}=\{(x,y_w,y_l;c_k)\},\qquad \mathcal L_{\mathrm{RM}}=-\mathbb E_{\mathcal D_{\mathrm{AI}}} \log\sigma(r_w-r_l).$$

分号后的 $c_k$ 最好作为可追溯元数据保存；训练公式只看到 chosen/rejected，但审计需要知道 judge 当时依据了哪条原则。

Insight 04

Constitution 不是替人类消失，而是改变人类介入的位置

人不必逐条比较海量回答，但仍要选择原则、构造边界案例、检查 judge 是否正确应用规则，并处理原则冲突。

自动化的是反馈生产，不是价值选择本身；显式原则的意义在于让价值选择更可见、更可审计。

10反馈来源、判断依据与目标维度分属不同层

反馈“由谁给”、判断“依据什么”、系统“想优化什么”是三类问题。Helpful, Harmless, Honest（HHH，有帮助、无害、诚实）是通用助手研究中的三项目标维度，不是第四种反馈来源。把这些层压成同一个“alignment signal”，就会误以为换一个 judge 等于换了目标。

Insight 05

反馈来源、评判准则与优化目标必须分别记账

“AI 给标签”只说明数据生产者；“按 Constitution”说明 rubric；“追求 HHH”说明希望实现的目标维度。三者可以组合，却不能互相推出。

只有分别保存 source、rubric、label 与模型版本，实验才可能回答：变化来自谁判断、按什么判断，还是优化器怎样使用判断。

11从公式回到上游代码：三个脚本，三个数据契约

固定上游代码把经典 RLHF 拆成三份教学脚本。读代码时不要先找框架 API，而要先问每份脚本消费什么数据、产出什么 artifact。

1 · sft_pipeline.py

示范 → SFT policy

generate_sft_data() 构造 instruction/response；format_sft_dataset() 应用 chat template；SFTTrainer 提高示范 token 概率。

sft_pairs = generate_sft_data()
train_dataset = format_sft_dataset(sft_pairs, tokenizer)
trainer = SFTTrainer(model=model, train_dataset=train_dataset, ...)
2 · reward_model_training.py

偏好对 → scalar scorer

PreferenceDataset 把同一 prompt 分别与 chosen/rejected 拼接；RewardModel.forward() 取最后有效 token 隐状态，经 value_head 输出分数。

r_chosen = model(chosen_ids, chosen_mask)
r_rejected = model(rejected_ids, rejected_mask)
loss = -log(sigmoid(r_chosen - r_rejected))
3 · rlhf_ppo_train.py

prompt → rollout → PPO update

policy_model 生成，冻结的 reference_model 算 KL，reward_model.score() 打分，PPOTrainer.train_step() 保存 old log-prob 并做 clipped update。

response = generate_response(policy_model, tokenizer, prompt)
reward = reward_model.score(prompt, response)
old_log_probs = compute_log_probs(policy_model, ...)
total_loss = policy_loss + kl_coef * kl

实现边界：上游 sft_pipeline.py 展示了 chat template 与 SFTTrainer，但没有显式构造 assistant-only loss mask；本章公式给出的是规范的数据契约。rlhf_ppo_train.py 同样是教学简化版：它可以使用规则评分模拟 RM，并用 batch reward 标准化近似 advantage。生产级 PPO-RLHF 通常还需要严格的 assistant mask、真正的 Critic/GAE、token reward、分布式 rollout 和评估闭环。

12理解检查：你能沿着一条反馈追到策略梯度吗？

不要只背“SFT → RM → PPO”。尝试明确每条箭头上流动的数据、谁生成它、下一阶段怎样使用它。

1. SFT 与 Reward Model 都看到了好回答，训练目标为什么仍然不同？
SFT 把一个示范回答当作 token 级监督标签，提高它在给定 prompt 下的条件概率；RM 同时读取 chosen 与 rejected，只学习同一 prompt 下的相对分数次序。SFT 产出生成策略，RM 产出评分器。
2. 若 $r_w=2.0,r_l=0.5$，为什么不能说 chosen 的“绝对质量是 2 分”？
Bradley–Terry loss 只依赖差值 $r_w-r_l$。两个分数同时加任意常数，偏好概率和 loss 都不变。因此 RM 分数首先是当前数据分布中的相对排序坐标，不能脱离比较对象解释成统一绝对质量。
3. Reference policy 和 old policy 最关键的区别是什么？
old policy 是采当前 rollout batch 时的 Actor 快照，用于 PPO ratio 和局部裁剪，通常随 batch 刷新；Reference 通常是跨训练冻结的 SFT 锚点，用于 KL 正则和长期漂移控制。局部小步不保证长期不漂移。
4. 为什么单条回答的 $\log\pi_\theta(y\mid x)-\log\pi_{ref}(y\mid x)$ 可能为负，而 KL 仍然非负？
单条 log-ratio 是一个采样值；某些回答可以被 Reference 赋更高概率，所以它为负。对 $y\sim\pi_\theta$ 的所有可能回答取期望后才得到 $D_{KL}(\pi_\theta\|\pi_{ref})$，该期望非负。
5. RLAIF 与 Constitutional AI 是同义词吗？
不是。RLAIF 说明偏好或评价由 AI 产生；CAI 说明 AI 按显式自然语言原则进行批评、修订或比较。AI judge 按 Constitution 生成偏好并接入 RM/PPO 时，是 RL-CAI，也属于 RLAIF；RLAIF 还可以使用别的 rubric。
6. 互动实验中，人类与 AI 给出相同 chosen 标签时，为什么下游数值相同？
当前 RM loss 只读取 chosen/rejected 与两项分数，不读取“human”或“AI”字符串。相同标签和分数产生相同 loss、梯度与更新后 RM 分数。来源差异只有通过标签分布、置信度、rubric 或元数据影响训练，不能由 PPO 自行猜出。
7. HHH、Constitution 与 human/AI feedback 分别属于哪一层？
HHH 是希望实现的有帮助、无害、诚实三个目标维度；Constitution 是把目标落实为可供批评和判断的自然语言规则；human/AI feedback 是偏好数据或修订数据的生产来源。目标、准则和来源必须分别记录。

本章带走的主链

SFT用示范给策略一个助手起点；偏好数据保存同一 prompt 下的相对判断；Reward Model用 Bradley–Terry loss 把判断变成可调用分数；PPO把分数与 Critic advantage 接回 token 策略更新；Reference KL提供跨训练的 SFT 锚点。CAI 与 RLAIF 改变的首先是反馈数据怎样生成，而不是这条下游数学链。

经典 RLHF 要维护 Actor、Critic、Reference 与 Reward Model，还要不断生成 rollout。可是我们手里已经有 $(x,y_w,y_l)$。下一章将追问：能否直接从偏好对更新策略，把 Reward Model 隐含进目标里，并省掉在线 PPO 循环？这正是直接偏好学习路线的出发点。
