06种群、循环与成对评分：一个数字装不下整张对战图

历史快照能减轻遗忘；维护多个同时探索的策略，则把训练从一条版本链扩展成一个种群。但最终仍要回到逐对手对战矩阵。

Population-Based Training（PBT，种群式训练）同时维护多个策略实例，让它们使用不同初始化、超参数或训练经历，并周期性比较、复制与扰动较好的配置。在对抗场景中，这些实例还可以互相配对，增加行为多样性。它与对手池有关，却不是同义词：

OPPONENT POOL

档案库

可以只保存不可训练的历史快照，重点是提供稳定、可回放的对手分布。

LIVE POPULATION

并行学习者

多个策略继续更新并探索不同区域，重点是维持多样性与发现新最佳回应。

EXTERNAL EVAL POOL

封存考卷

不参与训练、选择和调参，重点是给进展提供独立证据。

训练池可以改；评测池必须有封存部分。否则根据评测池持续挑选对手和超参数以后，它实际上已经变成训练信号。

为什么循环策略会让总排名失真？

行策略 \ 列对手石头 $\pi_R$布 $\pi_P$剪刀 $\pi_S$等权平均
石头 $\pi_R$$0.5$$0$$1$$0.5$
布 $\pi_P$$1$$0.5$$0$$0.5$
剪刀 $\pi_S$$0$$1$$0.5$$0.5$

三项平均都是 $0.5$，但逐格结构完全不同：布克石头、剪刀克布、石头又克剪刀。这类关系称为非传递。只保留平均值或单一名次，会丢失“谁克制谁”的关键信息。

Elo rating（Elo 等级分）把成对胜负压缩成标量。若 A、B 当前等级分为 $R_A,R_B$，A 的期望得分常写成：

$$E_A=\frac{1}{1+10^{(R_B-R_A)/400}},\qquad R_A'=R_A+K(S_A-E_A).$$

$S_A\in\{0,0.5,1\}$ 是本场实际得分，$K$ 是更新步幅。两名 1500 分选手交手时 $E_A=0.5$；若 A 获胜、$K=32$，则 $R_A'=1500+32(1-0.5)=1516$，B 相应变为 1484。

容易想错

“Elo 更高，所以它对每个对手都更强。” Elo 适合汇总大量成对比赛，却默认能力近似可以排在一条轴上。遇到石头—剪刀—布式循环时，等级分可能相近，逐对手克制关系仍然很强。

因此种群评测至少保留三层输出：完整 cross-play matrix（交叉对战矩阵）、预先约定的汇总分数，以及对最差匹配或可利用性的诊断。Elo 是仪表盘，不是原始数据的替代品。

07规模化：先说清楚横轴，再谈“越大越强”

环境数、对手数、每次 rollout 长度、更新步数与评测场次都能增加计算；把它们混成一个“训练更久”会让曲线无法解释。

DATA SCALE

环境与任务多样性

增加地图、提示、初始状态和规则变体；同时做去重、污染检查与难度覆盖。

POPULATION SCALE

对手与策略数量

增加历史快照和活跃策略；报告有效多样性，不能只报列表长度。

ROLLOUT SCALE

每轮交互预算

增加并行环境、每对局轨迹数和 horizon；记录有效样本率与墙钟时间。

UPDATE SCALE

优化轮数与步幅

更新更多次也会放大非平稳性；监控 KL、熵、回归测试和版本漂移。

一个训练成本账本可以写成 $C_{\text{train}}=N_{\text{rollout}}\,L\,c_{\text{step}}$：$N_{\text{rollout}}$ 是轨迹数，$L$ 是平均轨迹长度，$c_{\text{step}}$ 是一步交互与推理成本。它不是经验 scaling law，只负责阻止不同预算被悄悄混在一起。若线上有 $Q$ 次独立评测或请求，则总成本仍要把评测侧单列：

$$C_{\text{total}}=C_{\text{train}}+Q\,C_{\text{eval}}.$$

种群扩大时，评测本身也会二次增长

若有 $K$ 个策略，要对每个无序、非自身配对运行 $n_{\text{seed}}$ 个随机种子，完整交叉评测的对局数是：

$$N_{\text{match}}=\binom{K}{2}n_{\text{seed}}=\frac{K(K-1)}{2}n_{\text{seed}}.$$

例如 $K=40,n_{\text{seed}}=20$，共有 $40\times39/2=780$ 个配对，需要 $780\times20=15{,}600$ 局。若游戏有先后手，还应交换位置或把方向分别统计，不能用一局代替两种角色。

想画的曲线只改变必须固定同时报告
对手池大小 → 稳健性$K$ 与明确淘汰规则总 rollout、环境、优化器均值、最差项、矩阵多样性
rollout 数 → 表现$N_{\text{rollout}}$池、更新次数、评测集总步数、有效样本率、墙钟时间
更新步数 → 表现梯度更新次数数据、对手权重、评测预算KL、熵、旧对手回归
训练成本 → 独立得分总计算预算封存评测协议多随机种子与不确定性

一条可信曲线还应先定义停止规则，再运行多个随机种子，并在没有参与超参数选择的保留对手上复测。只挑最好一次运行、只展示最终种群冠军，都会把大量失败候选藏在图外。

Insight 05

规模化首先放大的是实验设计

策略数从 10 增到 40，不只增加训练候选，也把完整配对从 45 组推到 780 组。若评测预算没有同步设计，系统越大，遗漏的关系反而越多。

所谓“规模收益”必须落在一个预先固定、成本可核算、分布独立的评测协议上。

08研究前沿：每个“自我改进”系统究竟改了什么？

自博弈、进化搜索、世界模型和多智能体训练都能形成闭环；它们的共同外形很像，写回系统的对象却不同。

POLICY SELF-PLAY

更新策略参数

当前／历史版本制造课程，环境胜负进入梯度更新。关键审计：对手分布、循环与独立评测。

OPEN-ENDED CURRICULUM

更新任务分布

Proposer 生成略高于 Solver 当前能力的任务。关键审计：太易、不可解与外部正确性锚点。

PROGRAM EVOLUTION

更新可执行候选库

固定上游的 AlphaEvolve 例子由语言模型改程序、评估器执行、数据库选择；它主要改变程序种群，不等同于策略梯度训练。

WORLD / PARTNER MODEL

更新后果预测

显式预测环境或其他参与者的响应再规划。关键审计：模型偏差会不会随规划深度累积。

读到“系统不断变强”时，先圈出被修改的对象：权重、任务、程序、记忆还是环境模型；再追问谁验证它、失败是否保留、改动能否回滚。

前沿真正共享的是一个有边界的发现循环：生成候选，执行或交互，获得外部反馈，把被接受的改变写回，再在封存评测上复测。数学和代码任务更容易构造高速验证器；机器人、生物与长期社会交互的现实反馈昂贵且有风险，闭环速度不能替代安全门槛。

GENERATE扩大候选策略／任务／程序
→
EXECUTE让结果发生环境／沙箱／实验
→
VERIFY外部判断胜负／测试／证明
→
ARCHIVE写回与回滚保留失败记录

09从固定上游代码出发：先承认它实现了什么

固定仓库的 multi_agent_marl.py 实现多智能体网格环境、独立 Q-learning 与共享 Q 表对比；它提供联合交互接口，但没有实现本页的对手池、Elo 或自博弈课程。

本章对象固定上游中的对应还缺什么
联合动作与回报MultiAgentGridWorld.step(actions)对抗式胜负或可验证任务结果
策略作用域QLearningAgent / SharedPolicyAgent可保存、恢复并配对的版本标识
训练轨迹train_independent / train_shared按 $\mu_t$ 选择对手的 matchmaker
结果指标episode_rewards、completion_ratescross-play matrix、最差匹配与 Elo
推理搜索对照tree_of_thought.py 的 breadth 与 score它搜索思路节点，不更新对手策略；不能当作自博弈实现

沿着现有训练函数扩展，最小的对手池循环可以写成下面的接口草图。它强调版本、抽样与独立评测，不声称是固定仓库已经提供的可运行实现：

pool = [snapshot(policy, version=0)]

for iteration in range(num_iterations):
    scores = evaluate_against_pool(policy, pool)     # s_k
    weights = softmax(-beta * scores)                # mu_k
    opponent = sample(pool, probabilities=weights)

    trajectories = rollout(policy, opponent, env)
    policy.update(trajectories)

    if (iteration + 1) % snapshot_every == 0:
        pool.append(snapshot(policy, version=iteration + 1))

# 即使最后一轮不落在 snapshot_every 上，也把最终策略纳入评测
final_policy = snapshot(policy, version=num_iterations)
eval_population = pool if pool[-1].version == num_iterations else [*pool, final_policy]

# sealed_eval_pool 从未参与上面的抽样、更新与调参
cross_play = evaluate_all_pairs(eval_population, seeds=20)
heldout = evaluate_against_pool(final_policy, sealed_eval_pool)

公式到程序的映射是直接的：scores[k] 估计 $s_k$，weights[k] 是 $\mu_t(k)$，snapshot_every 决定池的时间分辨率；eval_population 额外保证最终策略不会因快照间隔而漏评，cross_play[i][j] 则保留非传递结构。若只打印 policy 对最后一个 opponent 的 reward，前面整章最关键的信息都会消失。

10一份可操作的研究检查表

无论你下一步研究机器人、多 Agent、推理还是科学发现，都可以用同一组问题检查闭环是否值得相信。

  1. 01
    先定义被更新的对象。

    策略参数、对手池、任务生成器、程序库与世界模型不能用同一句“系统自我改进”带过。

  2. 02
    固定参与者、可见信息与行动顺序。

    记录谁在何时看到什么、版本号是什么，以及哪次工具调用真正改变了环境。

  3. 03
    写出训练分布。

    给出环境、任务与对手的采样权重；报告实际采样频率，而不只报告池容量。

  4. 04
    保留外部验证锚点。

    胜负、单元测试、形式证明或人工复核至少有一项不由同一学习者自说自话。

  5. 05
    建立最小基线与反事实。

    固定对手、最新对手、均匀池、自适应池逐项比较；关闭遗忘、课程或历史快照，看结论是否仍成立。

  6. 06
    保存完整关系数据。

    保留 cross-play matrix、版本与随机种子；Elo、均值和冠军只是派生摘要。

  7. 07
    核算每一根规模横轴。

    分别记录 rollout、轨迹长度、更新步数、对手数、评测对局与墙钟时间；一次只改变一个核心变量。

  8. 08
    预注册停止与接受规则。

    先规定何时停止训练、何时把新版本纳入种群、哪些回归会阻止部署，并保留失败候选。

  9. 09
    在封存分布上复测。

    不用于课程、调参和模型选择的任务与对手，才有资格给出最后一份外推证据。

这份清单不保证研究一定成功；它保证失败更容易定位，成功也更难被训练分布泄漏、代理奖励或只挑冠军的叙事伪装。

11课程收束：从“会更新”走到“值得相信”

最后的理解检查不问术语背诵，而问你能否识别一条结果曲线背后少了哪份证据。

1. 永远出布的策略对固定石头胜率 100%，为什么不能称为稳健最优策略？
因为胜率是相对于对手分布定义的。它对石头是最佳回应，却会被剪刀稳定击败；对手池均值、最差匹配和完整对战矩阵都会暴露这个弱点。
2. 环境规则不变时，自博弈为什么仍然非平稳？
其他参与者的策略 $\pi_{-i}^{(t)}$ 随训练更新。它改变当前智能体在同一状态下遇到的联合动作分布，从而改变有效转移 $P_t$ 与回报分布；物理规则固定不等于学习分布固定。
3. 若逐对手得分为 $(0.9,0.2,0.4)$，固定第一名对手与均匀三对手的目标分别是多少？
固定权重 $(1,0,0)$ 时 $J=0.9$；均匀权重 $(1/3,1/3,1/3)$ 时 $J=(0.9+0.2+0.4)/3=0.5$。两者都还应补充最差项 $0.2$。
4. 课程公式里把 $\beta$ 调大，总是更好吗？
不是。较大的 $\beta$ 会更集中到当前低分对手；如果它只是尚不可解、没有学习进度，就可能长期吞噬预算并返回零信号。需要权重上限、学习进度诊断与均匀池消融。
5. “关闭遗忘”反事实能否证明固定对手训练已经足够？
不能。关闭遗忘会阻止未练习能力下滑，却不会让它们得到提升。固定对手仍只改善一项，对手池会把预算分配给三项；这说明退化由遗忘解释一部分，覆盖不足仍是另一部分。
6. 为什么 Elo 不能替代 cross-play matrix？
Elo 把成对比赛压成一个标量，适合观察总体趋势，却会隐藏石头—剪刀—布式非传递循环。完整矩阵保留谁克制谁，才能诊断特定弱点与循环。
7. 40 个策略、每个无序配对跑 20 个随机种子，需要多少局？
无序非自身配对数为 $40\times39/2=780$，乘以 20 个种子得到 $15{,}600$ 局。若先后手不对称，还需要交换角色或分别统计。
8. 一个“自我改进”结果最先应该追问哪四件事？
被修改的对象是什么；反馈由谁提供；训练与评测分布怎样生成；最佳结果能否在封存任务、独立代码或外部实验中复现。若这四项说不清，“改进”仍可能只是指标循环。

DEFINE状态、动作、奖励问题可学习
→
TRAIN策略与数据分布对手会移动
→
EVALUATE独立关系与成本不只看冠军
→
VERIFY复现、回归与边界结果值得相信

自博弈把当前能力变成下一轮课程；对手池保存历史，课程分配有限交互，种群扩展多样性，交叉评测揭示循环。规模越大，版本、成本与独立验证越不能省略。现代强化学习的终点不是一个永远上升的奖励数字，而是一条能被反事实、保留集和复现实验反复检查的改进链。
