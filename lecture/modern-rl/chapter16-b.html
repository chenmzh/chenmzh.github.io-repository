05二值奖励最重要的边界：全对与全错都没有相对信号

可验证结果常写成 $0/1$。它很清楚，却也很稀疏：一组里至少要同时出现不同结果，组内比较才知道该偏向谁。

设一组 $G$ 条回答中有 $m$ 条通过，令通过率 $p=m/G$。二值 reward 的组均值就是：

$$\bar r=p$$

因为 $r_i\in\{0,1\}$，方差可逐步化简：

$$\begin{aligned} s^2 &=p(1-p)^2+(1-p)(0-p)^2\\ &=p(1-2p+p^2)+(1-p)p^2\\ &=p-p^2=p(1-p). \end{aligned}$$

因此，在 $0<p<1$ 时，通过与未通过样本的优势分别是：

$$\hat A_{\mathrm{pass}}=\sqrt{\frac{1-p}{p}},\qquad \hat A_{\mathrm{fail}}=-\sqrt{\frac{p}{1-p}}$$

真正要观察的不是平均 reward 越高梯度越大，而是组内是否存在可比较的差异：全对表示这组已经没有相对改进对象；全错则表示验证器只说“都失败”，却没有告诉策略哪条更接近成功。

代码不能真的让 $0/(0+10^{-8})$ 产生方向；常见做法是在 $s$ 小于阈值时把整组优势显式设为 0 或跳过更新。扩大 group size 会增加看到“至少一次成功”的机会，但 rollout 计算也按 $G$ 增长。这里已经埋下下一章的问题：采样次数本身也是一种推理计算预算。

06有了相对优势以后，仍要防止一批旧回答把策略推得太远

组内优势回答“往哪个方向改”；PPO-style ratio 与 clip 回答“这一批由旧策略生成的数据，最多允许改多猛”。

原始 GRPO 保留逐 token 概率。第 $i$ 条回答第 $t$ 个 token 的新旧策略比值是：

$$\rho_{i,t}(\theta)= \frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})} {\pi_{\mathrm{old}}(y_{i,t}\mid x,y_{i,<t})} =\exp\!\left(\ell_{i,t}^{\theta}-\ell_{i,t}^{\mathrm{old}}\right)$$

$\rho=1$ 表示当前策略与采样时相同，$\rho=1.2$ 表示当前策略给这个已采 token 的条件概率提高了 20%。回答只得到一个结果优势 $\hat A_i$，所以这一个数广播给回答里的所有 token；但每个 token 的 $\rho_{i,t}$ 仍分别计算。

对单个 token，裁剪目标写成：

$$j_{i,t}(\theta)=\min\!\left( \rho_{i,t}\hat A_i, \operatorname{clip}(\rho_{i,t},1-\epsilon_{\mathrm{clip}},1+\epsilon_{\mathrm{clip}})\hat A_i \right)$$

这里最大化 $j_{i,t}$；实现训练 loss 时再取负号。取 $\epsilon_{\mathrm{clip}}=0.2$，看两个方向：

POSITIVE ADVANTAGE

$\hat A=+1,\ \rho=1.35$

未裁剪项为 $1.35$，裁剪项为 $1.20$，取较小者 $1.20$。高分回答已经被大幅增概率，继续奖励被封顶。

NEGATIVE ADVANTAGE

$\hat A=-1,\ \rho=0.65$

未裁剪项为 $-0.65$，裁剪项为 $0.80\times(-1)=-0.80$，取较小者 $-0.80$。低分回答已经被大幅降概率，目标不给进一步收益。

两栏要一起看：clip 同时限制“把好回答抬得过快”和“把坏回答压得过快”。优势给方向，概率比给偏离程度，二者缺一不可。

容易想错

“既然整段回答只有一个 reward，就应该先把所有 token 概率连乘成回答级 ratio。” 原始 DeepSeekMath GRPO 不是这样做的。它先保留逐 token log-prob，逐 token 计算 ratio 与 clip，再对每段回答的有效 token 求平均。把 ratio 连乘会引入明显的回答长度效应。

07old policy 负责说明数据从哪来，reference policy 负责说明别漂到哪去

两者都可能是冻结的模型副本，也都出现在 log-prob 里，但职责不同。把它们混成一个“旧模型”，后面的 ratio 与 KL 就失去解释。

DATA SNAPSHOT

$\pi_{\mathrm{old}}$ · 采样时策略

它生成本批 $y_i$。当前策略与它比较形成 $\rho_{i,t}$，判断一份旧数据对当前更新是否已经过时。

TRAINABLE

$\pi_\theta$ · 当前策略

唯一被梯度更新的模型。它要提高正优势回答的概率、降低负优势回答的概率。

BEHAVIOR ANCHOR

$\pi_{\mathrm{ref}}$ · 参考策略

通常来自对齐前或阶段起点的冻结模型。它不说明数据由谁生成，而是惩罚当前策略离语言与行为锚点太远。

沿左栏到中栏读出 importance ratio，沿右栏到中栏读出 KL anchor。old 会随 rollout 批次刷新；reference 通常在一个训练阶段内保持冻结，二者不能仅因某一时刻参数相同就混为同一概念。

沿用 Chapter 14 的 KL 直觉。原始 GRPO 对每个 token 可使用非负估计：

$$\Delta_{i,t}=\ell_{i,t}^{\mathrm{ref}}-\ell_{i,t}^{\theta},\qquad \widehat D_{i,t}=\exp(\Delta_{i,t})-\Delta_{i,t}-1$$

为什么它不会给出负惩罚？令 $g(\Delta)=e^\Delta-\Delta-1$，则：

$$g'(\Delta)=e^\Delta-1,\qquad g''(\Delta)=e^\Delta>0$$

所以 $g$ 是凸函数，唯一驻点 $\Delta=0$ 是全局最小点，且 $g(0)=0$。当当前策略与 reference 在该 token 上一致时惩罚为 0；偏离任一方向，惩罚都为正。若 $\Delta=0.2$，则：

$$\widehat D=e^{0.2}-0.2-1\approx0.0214$$

它不是“让策略永远等于 reference”。总目标会用系数 $\beta$ 权衡学习新高分行为与保留锚点；$\beta$ 越大，离开 reference 越贵。

Insight 03

old 与 reference 分别回答“证据是否过期”和“行为是否漂移”

概率比值关心当前策略相对采样策略变了多少；KL 关心当前策略相对长期锚点变了多少。一个约束数据复用，一个约束行为漂移。

同一份 log-prob 表里出现两个冻结模型，不代表它们扮演同一个角色。

08完整 GRPO 目标：先回答，再 token，最后回到 prompt

长公式并没有新增神秘部件，只是在三个平均层级里组合“相对优势、保守更新、参考锚点”。按索引从里向外读即可。

$$\mathcal J_{\mathrm{GRPO}}(\theta)= \mathbb E_{x_j}\!\left[ \frac{1}{G}\sum_{i=1}^{G}\frac{1}{T_{j,i}}\sum_{t=1}^{T_{j,i}} \left( \min\!\left[\rho_{j,i,t}\hat A_{j,i}, \operatorname{clip}(\rho_{j,i,t},1-\epsilon_{\mathrm{clip}},1+\epsilon_{\mathrm{clip}})\hat A_{j,i}\right] -\beta\widehat D_{j,i,t} \right) \right]$$
  1. 最内层 token：对第 $t$ 个生成 token 计算新旧 ratio、clip 与 reference KL。
  2. 一段回答：结果奖励只产生一个 $\hat A_{j,i}$，广播到回答的 token；再用 $1/T_{j,i}$ 对有效 token 求平均，避免长回答仅因 token 多就拥有更大权重。
  3. 同题一组：用 $1/G$ 平均 $G$ 条回答，它们共享 prompt，却有不同采样结果。
  4. 许多 prompt：最外层对题目分布取期望；训练代码用一个 prompt batch 的均值近似。
数学对象代码常见形状含义
$r_{j,i}$[B, G]每个 prompt 的每条回答一个 reward
$\hat A_{j,i}$[B, G]回答级组内相对优势
$\ell^\theta,\ell^{\mathrm{old}},\ell^{\mathrm{ref}}$[B·G, T]回答 token 的逐位置 log-prob
completion mask[B·G, T]排除 prompt 与 padding，只平均生成 token
$\mathcal L$scalar优化器最小化 $\mathcal L=-\mathcal J$

因此，“没有 Critic”只删掉 value loss 与 value model。rollout policy、当前 policy、reference、reward/verifier、逐 token log-prob、mask 与 optimizer 都还在。GRPO 是更轻的 Actor 侧结构，不是“只算一次 z-score 就训练完”。
