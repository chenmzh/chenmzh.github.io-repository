07候选里出现正确答案以后，还要把它识别出来

pass@k 假设评测者事后知道哪些候选正确。真实服务必须在看不到标准答案时，决定最终交付哪一条。

best-of-N（$N$ 个候选择优）是生成 $N$ 条候选，用验证器或评分器给它们打分，再返回得分最高者。若 $C$ 表示“候选集中至少有一条正确”，$S$ 表示“选择器从含正确答案的候选集中选中正确者”，则：

$$P(\text{最终答对})=P(C)\,P(S\mid C).$$

在实验的简化记号里，$P(C)$ 是相关覆盖率，$P(S\mid C)=v$，所以交付正确率为 $vP(C)$。若 $p=0.2,k=8,\rho=0$，覆盖率约 $83.22\%$；选择器可靠度只有 $v=0.75$ 时，最终正确率只有 $62.42\%$。正确答案“曾经出现”不代表用户“最终收到”。

GENERATE$N$ 条候选提高覆盖
→
NORMALIZE抽取答案统一格式
→
SCORE验证或排序可能误判
→
DELIVER返回一条产品指标

最容易忽略的是中间两步：格式抽取失败或评分器误排，都会把 pass@k 的候选覆盖损失掉。

没有可靠验证器时：让多条推理对最终答案投票

self-consistency（自洽投票）是从多条不同思维链中抽取最终答案，选择出现次数最多的答案。它依赖一个直觉：不同路径可能在中间用不同方法，但正确结论更容易被重复到达。

五条候选12 · 12 · 9 · 12 · 15
归一化计数12 → 3 票；9 → 1 票；15 → 1 票
最终交付12

自洽投票与 pass@k 回答的不是同一问题：只要五条里出现一次正确答案，pass@5 就记成功；投票则要求正确答案形成多数或至少成为众数。如果模型有系统性误解，五条轨迹可能一致投给同一个错误答案；“意见一致”只能提供稳定性证据，不能替代外部真值。

方法需要什么信号衡量／返回什么典型失败
pass@k事后正确性验证候选是否至少覆盖一次正确不能说明部署时怎样选
best-of-N能比较候选的评分器返回评分最高的一条评分器把漂亮的错答排第一
self-consistency可归一化的最终答案返回众数答案相关的系统性错误形成多数
容易想错

“self-consistency 得到 4:1，所以答案有 80% 概率正确。” 票数是这组相关样本中的频数，不是经过校准的正确概率。五条回答可能都继承同一个错误前提。

08不是每道题都值得多想：模式、预算和停止条件

“把 $k$ 永远设成 32、把思维链永远拉满”会让简单题白白变慢，也可能让难题重复同一种错误。

Hybrid Thinking（混合思考）让同一个模型支持“直接回答”和“展开思考”两种模式：简单翻译走短路径，竞赛证明走长路径。它解决的是离散路由问题——这次要不要进入思考模式。

adaptive thinking（自适应思考）进一步让系统根据当前证据动态决定还要投入多少计算：已经通过外部检查就提前停止；候选仍冲突且新增路径带来新证据，就继续；接近硬上限时收束并预留最终答案空间。它解决的是序贯决策问题——下一份计算的预期收益是否仍大于成本。

FIXED BUDGET

每题同样多

成本最容易预测；简单题浪费，难题可能不够。

HYBRID THINKING

快／慢二选一

减少明显简单题的延迟；路由误判会损失质量或费用。

ADAPTIVE THINKING

边做边决定

根据验证结果和候选分歧继续或停止；尾部成本更难预测。

三者的控制粒度逐步变细：预设一个数、先选一种模式、再根据中途反馈连续调整；粒度越细，对停止规则和成本监控要求越高。

把“答对”和“少算”写进同一笔教学账

一种通用的成本敏感抽象是：

$$r_{\text{total}}=r_{\text{task}}-\lambda C,$$

$r_{\text{task}}$ 是任务是否完成，$C$ 可以是推理 token、采样数、工具时间或费用，$\lambda$ 是把一单位成本折算成多少奖励损失的汇率。这个式子用于说明权衡，不是任何具体产品公开的训练配方。

请求与方案$r_{\text{task}}$成本 $C$$\lambda=0.0002$ 时的净奖励
翻译 hello，200 token$1$$200$$1-0.0002(200)=0.96$
翻译 hello，3,000 token$1$$3{,}000$$1-0.0002(3000)=0.40$
数学题直接答错，200 token$0$$200$$0-0.0002(200)=-0.04$
数学题长思考答对，3,000 token$1$$3{,}000$$1-0.0002(3000)=0.40$

同样的长思考，在翻译题上把净奖励从 $0.96$ 降到 $0.40$，在数学题上却把答错的 $-0.04$ 提到 $0.40$。因此自适应系统不应只给输入打一次“难度分”，而要持续追问：当前证据够不够？下一步计算还可能改变结论吗？

Insight 05

自适应思考的核心是停止策略，不是静态难度标签

短题可能是尚未解决的猜想，长文可能只需抽取第二句话。真正有用的信号来自执行过程：是否已验证、候选是否仍冲突、新采样是否还带来不同证据。

预算控制从“一开始给多少”升级为“看到当前状态后，还值不值得继续”。

09把概率账本写成代码：生成、覆盖、选择必须分层

下面的最小代码复现页面实验使用的模型。它不会调用真实 LLM，只把每一层概率的含义固定下来。

from math import ceil, log

def independent_coverage(p, k):
    return 1 - (1 - p) ** k

def correlated_coverage(p, k, rho):
    # rho: 所有候选共享一次成败的混合概率
    return rho * p + (1 - rho) * independent_coverage(p, k)

def delivered_accuracy(p, k, rho, selector_reliability):
    coverage = correlated_coverage(p, k, rho)
    return coverage * selector_reliability

def samples_for_target(p, target_coverage):
    return ceil(log(1 - target_coverage) / log(1 - p))

p = 0.20
k = 8
rho = 0.40
v = 0.90
tokens_per_sample = 500

print(independent_coverage(p, k))   # 0.8322
print(correlated_coverage(p, k, rho))  # 0.5793
print(delivered_accuracy(p, k, rho, v)) # 0.5214
print(k * tokens_per_sample)        # 4000 token
数学对象程序变量它回答的问题
$p$p一条候选的边际正确率是多少？
$k$ / $N$k这次共生成多少条候选？
$1-(1-p)^k$independent_coverage独立候选里至少出现一次正确的概率？
$\rho$rho候选有多大概率共享同一次成败？
$v=P(S\mid C)$selector_reliability已经有正确候选时，选择器能否挑中？
$kL$k * tokens_per_sample生成侧总 token 预算是多少？

真实 best-of-N 系统还需要实际生成 candidates、计算 scores、抽取规范化答案并记录验证器调用。页面故意不把这些藏进一个“accuracy”变量：只有分开记录覆盖率与选择率，才能定位失败发生在生成端还是评价端。

10什么时候继续加计算不会再救你？

推理时扩展是一种部署旋钮，不是把任何固定模型变成无限强模型的定律。

01 · $p\approx0$

模型产不出正确候选

有限次采样只会产生更多相似错误；应补训练、工具或知识，而不是盲目增加 $k$。

02 · 高相关错误

数量增加，思路没有增加

独立公式会高估覆盖率。应直接测量候选间的错误重合，而不是把采样数当有效样本数。

03 · 选择器失真

正确答案出现却被错答压过

best-of-N 的收益受验证器上限约束；评分器偏爱格式、长度或自信语气时会系统性误排。

04 · 无效长链

token 增长，证据没有增长

重复、绕圈和预算耗尽前的仓促收尾都会增加成本而不提升质量。

四类失败分别落在候选能力、联合多样性、选择信号和计算利用率；只有先定位瓶颈，增加预算才有明确作用点。

比较系统时也必须控制变量：模型版本、工具权限、每题 token、候选数、验证器和超时任一项改变，都可能影响分数。只报告“开启深度思考后提升了多少”，不能单独证明提升来自 CoT 长度还是来自更多候选、代码执行或更强选择器。

到这里，我们已经能计算“正确轨迹有没有出现”，也知道选择器会形成第二个瓶颈。但只看最终答案的 verifier 往往要走到结尾才知道整条路是否失败：某个中间步骤已经偏离时，怎样尽早评价并把预算转向更好的分支？步骤级过程评价与正式搜索机制留给 Chapter 18。

11检查你的理解：你增加的是计算量，还是有效机会？

每题都要指出使用了什么假设。脱离独立性、选择器和成本谈“多采样更好”，结论是不完整的。

1. 训练计算与推理时计算最根本的区别是什么？
训练计算会更新参数，改变模型以后面对所有请求时的策略分布；推理时计算保持参数固定，只为当前请求增加生成、检查、采样或聚合预算。前者主要提高能力上限，后者主要减少已有能力这次没有发挥出来的概率。
2. 为什么观察到 RL 后出现长 CoT，不能立刻断言 RL 从零创造了推理？
基座模型可能已经以低概率生成过推导、反思和验算轨迹。RLVR 用结果奖励提高成功轨迹的概率，使这些行为稳定出现。要区分创造与激活，需要先对基座模型多次采样，检查正确轨迹是否原本就在支持集里。
3. 若单条正确率 $p=0.25$，独立采样 4 条的 pass@4 是多少？
四条全部错误的概率是 $(1-0.25)^4=0.75^4\approx0.3164$，所以 $\operatorname{pass@4}=1-0.3164\approx0.6836$，即约 $68.36\%$。
4. pass@8 已经是 90%，为什么最终产品准确率仍可能只有 60%？
pass@8 只表示候选集中至少出现一条正确答案。产品还要抽取、评分并选择；若选择器在含正确候选时只有约 $2/3$ 概率挑中，最终正确率就是约 $0.9\times2/3=0.6$。
5. 为什么把同一个提示重复 32 次不一定获得独立公式预测的收益？
候选会共享模型知识、提示偏置和高概率错误路线，正确性并不独立。正相关错误使“全部失败”的概率高于独立模型预测；极端情况下 32 条完全同涨同跌，覆盖率仍只有单条的 $p$。
6. self-consistency 的 7:1 投票能否解释为答案有 87.5% 概率正确？
不能。票数只是当前一组相关样本的频数，不是经过校准的后验概率；模型可能因为同一个错误前提而高度一致。自洽投票需要用外部有答案的数据评测和校准。
7. 自适应思考为什么更像停止策略，而不是一次难度分类？
任务的可解性会随中间证据变化：验证通过可以提前停，候选冲突可能需要新工具，新增采样持续重复则应停止。因此每一步都要依据当前状态比较下一份计算的预期收益与成本，而不是只在开头贴一个“难题”标签。
