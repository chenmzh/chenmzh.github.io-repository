07PPO 这一章先看懂什么，不必一次吃完

原项目第一章直接跑 PPO。作为学习入口，我们只抓住它最核心的三件事：收集轨迹、判断动作比预期好多少、再谨慎地修改策略。

STEP 1 · ROLLOUT

用旧策略收集一段经验

让当前策略与环境交互，保存 $s_t,a_t,r_t$ 以及旧策略对动作的概率。数据必须来自真实交互，而不是预先固定的数据集。

STEP 2 · ADVANTAGE

哪些动作比预期更好？

Critic 给出基准 $V(s_t)$，再根据实际结果估计 advantage $A_t$。正 advantage 的动作值得更常发生，负的则相反。

STEP 3 · CLIP

更新，但别一下改得太猛

PPO 比较新旧策略对同一个动作的概率，并裁剪过大的概率变化，避免一次更新把 policy 推到完全陌生的区域。

概率比是 PPO 的主角之一

$$r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{old}}(a_t\mid s_t)}$$

如果 $r_t=1$，新旧策略对这个动作的看法没变；如果 $r_t=1.5$，新策略让这个动作出现的概率提高了 50%。PPO 不希望每个好样本都把这个比例推得无限大，于是有了 clip。

直觉图：好动作也不能无限加码

假设 $A_t>0$，横轴是概率比 $r_t$。

这是“为什么 PPO 比裸 policy gradient 更稳”的第一层直觉，不是完整推导。下一阶段学 Actor-Critic、GAE 时再把这里补严谨。

08把概念落到 Gymnasium 代码

第一次读 RL 代码时，最容易被框架 API 淹没。先只认出交互循环，你就已经抓住了骨架。

import gymnasium as gym

env = gym.make("CartPole-v1")
obs, info = env.reset(seed=42)

done = False
while not done:
    # policy: state -> action
    action = policy(obs)

    # environment: action -> next state + reward
    next_obs, reward, terminated, truncated, info = env.step(action)

    # 这里通常会保存 transition，供后续算法更新使用
    obs = next_obs
    done = terminated or truncated
代码RL 语言这一章该怎么理解
obs$s_t$当前决策所依据的信息
action$a_t$policy 在当前状态下选出的动作
reward$r_t$这一步环境返回的即时反馈
next_obs$s_{t+1}$动作改变世界后的新局面
terminated自然终止杆倒了 / 小车越界，任务真正失败
truncated时间截断达到 500 步上限，并不等于状态本身“坏了”

09检查你的理解：第一章真正应该带走什么

不需要背术语。你能用自己的话回答这些问题，就可以进入下一章。

1. 为什么 CartPole 不能简单看成一个“状态 → 左/右标签”的分类问题？
因为没有现成的正确动作标签，而且某一步动作的好坏取决于它对未来状态和长期回报的影响。动作还会改变未来收集到的数据分布。
2. Reward 和 Return 有什么区别？
Reward $r_t$ 是一步的即时反馈；Return $G_t$ 是从当前时刻开始的一串未来 reward 的折扣和。RL 的优化通常关心长期 return，而不是单步 reward。
3. 为什么状态里需要 $\dot\theta$，只有杆角度 $\theta$ 不够？
角度只描述位置，不描述运动趋势。相同角度下，杆可能正在加速倒下，也可能正在回正，这两个状态需要不同动作。
4. Policy 到底是什么？
它不是一个固定动作，而是状态到动作分布的映射：$\pi(a\mid s)$。状态变化后，动作概率也会变化。
5. 为什么 PPO 需要比较新旧策略？
rollout 数据来自旧策略。如果一次更新让新策略偏离太远，这批数据就不再能很好代表新策略会遇到的行为分布，训练也容易不稳定。PPO 用概率比和 clipping 限制过大的更新。
