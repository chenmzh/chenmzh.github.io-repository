07长轨迹评测：答案、证据、过程、成本分四层报告

总 reward 适合训练更新，分层指标才适合研究诊断。相同零分可能分别来自模型答错、网页超时、引用错配或预算耗尽。

短答案可先用规范化后的 Exact Match（EM，精确匹配）：

$$S_{\mathrm{EM}}=\mathbb 1[\operatorname{norm}(\hat y)=\operatorname{norm}(y)].$$
层核心问题最小指标典型假高分
答案结论是否正确、完整Exact Match、事实覆盖靠参数记忆直接猜中
证据引文是否支持对应论断覆盖、归因、可访问性URL 真实但实体错误
过程查询是否带来新信息冗余率、冲突核对率重复搜索后碰巧答对
成本固定资源内能否完成预算内成功率、时间、token用更多并行轨迹换成绩

四层沿因果链定位失败：过程产生证据，证据支撑答案，成本限制可用过程；任何一层的高分都不能证明其余三层合格。

过程冗余可以从重复查询和重复访问开始：

$$S_{\mathrm{redundancy}}=\frac{N_{\mathrm{repeat\ query}}+N_{\mathrm{repeat\ visit}}}{N_{\mathrm{tool\ calls}}}.$$

在预算 $B$ 下的成功率则写成：

$$S_{\mathrm{budget}}(B)=\frac{\#\{\text{在 }B\text{ 内完成的任务}\}}{\#\{\text{全部任务}\}}.$$

BrowseComp（持续浏览短答案基准）更偏多跳检索后的短答案；General AI Assistants（GAIA，通用人工智能助理基准）同时引入文件与多种工具；开放式研究报告还要检查事实覆盖和引用。比较系统时必须固定题目版本、搜索后端、最大工具步数、采样条数与网页时间；否则“模型更强”可能只是“浏览次数更多”。

Insight 05

环境错误必须从模型错误中拆出来

搜索服务 500、页面抽取为空、模型找到证据却推理错、模型提交格式错，最终都可能是 reward=0，但修复路径完全不同。

长轨迹评测最重要的产物之一，是可以按失败类型切片重放的完整日志。

08从研究轨迹到训练：先学会闭环，再优化闭环

Chapter 20 已经解释多轮工具 trajectory，Chapter 21 已经解释 verifier。这里不重讲优化算法，只看浏览器环境额外需要哪些训练材料。

这里的 Supervised Fine-Tuning（SFT，监督微调）先用已有成功轨迹教会动作格式，再让当前策略进入环境采样。

01 · HARNESS SMOKE TEST固定规则 agent 跑通 reset / step / timeout先证明环境可靠
→
02 · TRAJECTORY SFT学习 query、read、cite 的合法格式先获得非零成功率
→
03 · ON-POLICY ROLLOUT在缓存或真实网页生成新轨迹记录环境 token mask
→
04 · VERIFIER UPDATE答案 + 证据 + 预算反馈保留分项与失败原因

训练顺序的因果关系是：Harness 不稳定会污染轨迹；没有基本工具格式会让终点奖励长期为零；只有前两步可靠后，在线反馈才主要反映研究策略。

离线搜索 API 环境速度快、可缓存，适合先研究查询改写；正文抽取加入来源核对；真实浏览器再处理动态页面、点击和下载。环境保真度越高，工具噪声和成本越大。课程学习应逐层增加环境难度，而不是一开始就把验证码、弹窗、页面改版与策略学习同时混进 reward。

边界提醒

“只要加入每步奖励，长轨迹就一定更容易学。” 不成立。过程评分器如果偏爱“多搜、多写、多引用”，策略会优化这些表面行为。过程信号必须能指向可核验的进展，并和独立终态评测一起监控。

09把公式落到代码：先返回指标字典，再决定是否聚合

下面是教学化 evaluator。它刻意不在函数内部生成唯一真相分数，避免调用者失去失败结构。

def evaluate_research(task, run):
    supported_required = sum(
        evidence_supports(claim, run.citations)
        for claim in task.required_claims
    )
    supported_citations = sum(
        citation_supports_neighbor(citation, run.answer)
        for citation in run.citations
    )

    coverage = supported_required / len(task.required_claims)
    attribution = (
        supported_citations / len(run.citations)
        if run.citations else 0.0
    )
    within_budget = float(run.steps <= task.max_steps)

    return {
        "answer": exact_match(run.answer, task.answers),
        "coverage": coverage,
        "attribution": attribution,
        "within_budget": within_budget,
        "status": run.status,  # completed / timeout / tool_error
    }
数学/概念程序变量必须追溯到
$\tau$run.trajectory逐步观察、动作、错误和时间
$E$run.citations实际访问过的 URL 与原文片段
$S_{\mathrm{coverage}}$coverage任务要求的原子事实集合
$S_{\mathrm{attribution}}$attribution每条引用与相邻论断的支持关系
环境失败run.status搜索、页面、解析器或模型

本章的核心对象是证据型研究，即使调用 click，也优先使用 DOM、正文或带语义的链接目标。下一章会拿走这些舒适接口。

维度本章：证据型研究 / 浏览器智能体下一章：像素界面操作

11检查你的理解：能否从证据缺口定位轨迹问题？

先回答，再展开。每题都要求指出“该看哪一层指标”，而不只背工具名称。

1. 两个 Agent 给出相同正确答案，为什么仍不能只给相同 reward？
因为一个可能有可回放的证据链，另一个可能凭记忆猜中或引用错人。答案正确性只检查终点字符串；研究质量还要检查证据覆盖、来源归因、过程与预算。
2. read 和 cite 为什么不能合并成“看过网页”？
read 把页面内容变成策略观察；cite 建立某个论断与某段原文之间的可审计绑定。看过正确页面不等于最终引用正确，也不保证引用支持相邻论断。
3. 覆盖率高、归因分低意味着什么？反过来呢？
覆盖率高而归因低表示许多必需事实似乎都有材料，但报告给出的引用经常错配或不支持论断；归因高而覆盖低表示少数引用很可靠，仍有大量关键事实缺少证据。
4. 为什么网页超时不能和模型答错都简单归为“失败样本”？
网页超时属于环境或工具故障，模型答错属于策略或推理失败。二者都可得到零终态奖励，但分别需要修 Harness 与修模型；混在一起会让训练和失败分析都失真。
5. 为什么不能单独最小化工具步数？
交叉验证和实体消歧本来就需要额外步骤。过强步数惩罚会鼓励模型提前停止、直接猜测或省略反证来源。预算要作为约束，与答案和证据分项一起报告。
6. 本章与 Chapter 23 最关键的环境差异是什么？
本章主要用带语义的搜索、正文和引用动作，目标是形成可信证据链；Chapter 23 主要从像素观察输出鼠标键盘动作，动作会改变真实软件状态，还必须处理误点与不可逆副作用。
