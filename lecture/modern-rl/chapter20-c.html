07在策略与真实世界之间加入可审计编排层

多轮公式描述“策略与环境交互”，工程上还需要一个可审计的中间层，把模型文本变成受控动作，再把真实结果变成结构化观测。

harness（运行编排层）负责解析动作、校验工具名和参数、执行允许的调用、记录 observation、计算奖励并判断是否终止。environment（环境）是动作真正作用的任务世界，例如一个模拟目录服务、受控 API 或沙箱。二者分工如下：

POLICY

提出候选动作

catalog.search({sku:"MX-8"})

能建议，不能自行授予权限
HARNESSschema → permission → budget → execute → log
ENVIRONMENT

执行并返回事实

{price:120, stock:7}

返回值、错误和状态变化都要保真

真正要看的是中间的 gate：模型只提出候选动作；harness 根据预先配置的工具白名单、参数 schema、权限与预算决定能否执行。拒绝本身也必须作为 observation 写回轨迹。

工具失败不是空白，而是下一轮必须面对的观测

错误观测含义允许的恢复不应自动做什么
schema_error参数名、类型或必填项不合法依据 schema 修正一次参数猜测隐藏字段并反复试探
empty_result合法查询没有匹配记录在任务范围内改写查询捏造一条“可能的”结果
timeout环境未在预算时间内返回有限次数重试或安全终止无限重试耗尽资源
permission_denied动作超出当前授权停止并说明需要哪项授权换接口绕过权限边界
runtime_error工具执行过程中失败读取可见错误后修正或退出把失败日志当作成功结果

安全边界不能只写进 prompt。harness 要在策略外部强制执行：限制可调用工具、参数范围、最大轮数、超时、并发和可逆性；把外部 observation 当作不可信数据，而不是新的系统指令；对不可逆动作要求显式授权或人工确认。训练时奖励“越过边界但侥幸成功”的轨迹，会直接把危险行为变成高回报策略。

Insight 05

安全约束首先是环境动力学的一部分，其次才是语言提醒

prompt 可以告诉模型不要越权，harness 才能让越权动作实际不可执行，并留下明确的拒绝观测。

可靠 Agent 的训练环境必须让“违规失败”真实发生；否则策略只学会复述规则，没有学会在边界前停下。

08实验：同样最终成功，奖励放在哪里会改变第一步吗？

固定两条都能完成任务的四轮轨迹：A 第一轮精确搜索，B 第一轮模糊搜索、后来补救。比较“只看最终成功”与“分出一部分奖励给可验证的精确搜索”。

Question
两条轨迹最终都成功时，结果奖励能否推动策略更偏好高质量的第一步？把比例 $\lambda$ 的奖励分给第一轮后会怎样？
Prediction
纯结果奖励下两条轨迹的 $G_0$ 相同，组内 advantage 都为 0；$\lambda>0$ 后，精确搜索获得正 advantage，模糊搜索获得负 advantage。
Experiment
调节折扣 $\gamma$、早期奖励份额 $\lambda$、最终奖励尺度、第一步当前概率 $p$ 与学习率 $\alpha$，比较两种分配下的回报、优势和一次简化策略更新。
Observation
默认 $\gamma=0.8,\lambda=0.4,R=1,p=0.5,\alpha=1$ 时，纯结果奖励给两条轨迹相同的 $G_0=0.512$；逐轮分配给出 $A_0^{\text{精确}}=+0.2$、$A_0^{\text{模糊}}=-0.2$，精确搜索概率从 0.500 升到约 0.525。
Interpretation
过程信号让相同最终结果下的早期动作变得可区分；策略梯度因而能提高精确搜索的概率。折扣只能传播已有奖励，不能凭空区分两个相同 outcome。
Limitation
实验假设“精确搜索”可被无误验证，并把每轮动作简化成二选一。真实工具调用由多 token 参数组成，过程评分可能有偏差，且还要处理不同长度与不同历史。

为了把 advantage 翻译成“第一步概率怎样动”，实验把第一轮简化为两个动作：精确搜索的概率为 $p=\sigma(z)$，模糊搜索的概率为 $1-p$。二元 softmax 的两个 log-probability 对 logit $z$ 的导数分别是：

$$\frac{\partial\log p}{\partial z}=1-p,\qquad \frac{\partial\log(1-p)}{\partial z}=-p.$$

用同一任务的两条 rollout 做一次平均策略更新：

$$\Delta z=\frac{\alpha}{2}\left[A_0^{+}(1-p)+A_0^{-}(-p)\right],\qquad p'=\sigma\!\left(\operatorname{logit}(p)+\Delta z\right).$$

默认值 $A_0^+=0.2,A_0^-=-0.2,p=0.5,\alpha=1$ 给出 $\Delta z=0.1$，所以 $p'=\sigma(0.1)\approx0.525$。这只是把更新方向做成可手算数值；真实语言模型会对整段动作 token 使用 action mask 和对应轮次 advantage。

要观察的不是“稠密奖励总比稀疏奖励好”，而是 $\lambda$ 是否提供了可信的路径区分。把 $\lambda$ 调到 0，两种方案立刻失去对第一步的相对偏好；若评分规则不可信，非零 $\lambda$ 也可能强化错误动作。

09公式落到代码：先保存 turn，再从后往前算回报

固定上游实验 multi_turn_rl.py 的核心结构很朴素：每轮保存 action 与 observation，奖励确定后再反向累计。关键不在代码长，而在字段不能混。

turns = []
history = [task]
done = False

while not done:
    action = policy.act(history)  # a_t：策略产生
    observation, reward, done, info = harness.step(action)
    turns.append({
        "history_before": list(history),
        "action": action,
        "observation": observation,
        "reward": reward,
        "done": done,
        "termination_reason": (
            info["termination_reason"] if done else None
        ),
    })
    history.extend([action, observation])

turns[-1]["reward"] += verifier(turns)

G = 0.0
for turn in reversed(turns):
    G = turn["reward"] + gamma * G
    turn["return"] = G
数学对象代码变量容易犯的错
$h_t$history_before保存动作之后的历史，造成信息泄漏
$a_t$action只存自然语言，不存可执行的结构化参数
$o_{t+1}$observation把失败改写成看似成功的摘要
$r_t$reward把最终结果复制成每轮即时奖励却不说明
$G_t$return从前往后累加，错过 $G_t=r_t+\gamma G_{t+1}$
$m_i$action_mask让 observation token 也参与策略梯度

上游 generate_synthetic_data.py 负责产生候选过程，multi_turn_rl.py 对比结果与逐步奖励，tool_use_agent.py 展示单步工具选择。它们分别对应“数据从哪里来”“奖励怎样跨轮传播”“动作空间如何定义”，不能把单步工具分类误当成完整 Agentic RL。

11理解检查：你能把一段工具日志变成训练对象了吗？

1. 工具 observation 不参与策略损失，为什么还必须保留在上下文？
因为下一动作以历史 $h_{t+1}$ 为条件，而 observation 是这段历史中新获得的环境证据。$m_i=0$ 只排除该 token 自身的策略梯度，不是让模型看不见它。
2. 四轮轨迹只有最后奖励 1，$\gamma=0.5$ 时第一轮的 $G_0$ 是多少？
即时奖励为 $[0,0,0,1]$，所以 $G_0=0.5^3\times1=0.125$。折扣传播了最终信号，但没有告诉我们第一轮在两条同样成功的轨迹中哪一个更好。
3. 两条轨迹最终都成功，为什么纯结果奖励可能无法改进第一步？
若两条从同一历史出发且最终奖励相同，它们的第一轮 reward-to-go 也相同；减去同一基线后没有相对优势，策略看不到“精确搜索”和“模糊后补救”的差别。
4. 为什么轨迹合成不能只让语言模型编写工具返回？
工具返回应来自环境执行。编写出来的日志可能参数不合法、数据接续不成立或把失败伪装成成功，无法证明这条路径在任务环境中可到达。
5. 模型收到 permission_denied 后，安全的下一步是什么？
停止受限操作，向用户说明需要的权限或安全终止。不能换一个未授权接口绕过限制；权限检查属于 harness 的强制边界，而不是可被策略谈判掉的提示。
6. Chapter 13 的多智能体 credit 与本章跨轮 credit 有什么联系和区别？
二者都问“共享结果该归因给谁”。Chapter 13 重点区分多个 Agent 的贡献；本章重点区分工具轨迹中不同轮次动作的贡献。协作工具系统会同时面对角色维度和时间维度。

本章带走五件事

  1. Agentic RL 优化的是与环境交替产生的完整轨迹，不是单段 completion。
  2. tool action 由策略产生，tool observation 由环境产生；它们都进入历史，只有前者进入策略梯度。
  3. 跨轮信用分配用 $G_t$ 和 $A_t$ 把结果传回动作；过程信号能增加区分度，也会传播放大评分偏差。
  4. 轨迹合成必须经过真实执行与质量控制，成功、效率、错误恢复和安全都属于数据质量。
  5. harness 把模型候选动作变成受控交互，并用权限、预算和错误观测守住环境边界。
