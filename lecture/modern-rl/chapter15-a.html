CHAPTER 15 · 直接偏好路线

偏好对 → Policy/Reference log-prob → 对比损失

不单独训练评分模型，不在每个优化步重新 rollout，也不需要 Critic；直接在固定偏好数据上做梯度下降。

真正要观察的是训练信号的路径长度：直接路线没有否定“偏好”或“约束”，而是把显式 reward 与在线策略优化代数化为一项离线对比损失。

Direct Preference Optimization（DPO，直接偏好优化）是一种离线偏好优化方法：它用已经收集好的偏好对训练策略，而不是边生成、边打分、边更新。这里的“direct”不是“只提高 chosen 的概率”，也不是“完全没有奖励”；它指的是偏好标签直接进入策略损失。

Insight 01

DPO 简化的是训练路线，不是学习目标

它仍在学习“哪些回答更值得出现”，也仍需要一个 reference policy 防止概率变化失去尺度。被跳过的是显式 RM、Critic 和训练期在线 rollout。

“不用在线 RL”不等于“不优化策略”，而是把策略优化改写成固定数据上的可微分类问题。

02chosen 与 rejected：标签只说“这一次更喜欢谁”

一条 DPO 训练样本是偏好三元组 $(x,y_w,y_l)$。三个字段必须共享同一个上下文，比较才有意义。

PROMPT · $x$“同事的代码很差，我该怎么反馈？”
CHOSEN · $y_w$

先指出一个具体、可复现的问题，再说明影响并给出可操作建议；把评价落在代码上，不评价人。

REJECTED · $y_l$

直接告诉他写得太烂，让他全部重写；这样最省时间。

请观察“同一个 $x$”与“一次相对排序”：chosen 是这对回答里的胜者，不是宇宙中绝对正确的标准答案；rejected 也不必是乱码，困难样本往往是两者都像样但有细微质量差。

数据字段数学符号它提供的证据它没有承诺什么
prompt$x$比较发生的共同条件不能跨 prompt 直接比较回答概率
chosen$y_w$在本次比较中被偏好不保证事实、风格、安全各维度都完美
rejected$y_l$在本次比较中落败不等于“概率必须降到零”

这也是为什么数据策划比算法名字更根本。若标注者偏爱冗长回答，DPO 学到的可能是“更长”；若 chosen 与 rejected 同时改变事实性、礼貌程度和格式，我们很难知道模型到底学到了哪一条差异。偏好标签是监督信号，不是天然真理。

03一个回答的概率，是回答 token 的 log-prob 之和

DPO 比较的是完整回答 $y$，不是只看第一个 token。先把语言模型的序列概率写清楚，后面的四条 log-prob 才不会混。

若回答 $y=(y_1,\ldots,y_T)$，自回归语言模型按链式法则给出：

$$\pi_\theta(y\mid x)=\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t})$$

连乘许多小概率容易数值下溢，取自然对数后，乘法变成加法：

$$\log\pi_\theta(y\mid x)=\sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t})$$

代码会把 prompt + response 一起送入模型，但求和时只保留 response token；prompt 只是条件，不应被当作模型要学习偏好的答案。chosen 和 rejected 长度不同还会让“求和 log-prob”带有长度效应，这会在家族方法里成为一个设计分叉。

POLICY × CHOSEN$p_w=\log\pi_\theta(y_w\mid x)$
POLICY × REJECTED$p_l=\log\pi_\theta(y_l\mid x)$
REFERENCE × CHOSEN$p_w^0=\log\pi_{\mathrm{ref}}(y_w\mid x)$
REFERENCE × REJECTED$p_l^0=\log\pi_{\mathrm{ref}}(y_l\mid x)$

真正要追踪的是“2 个模型 × 2 个回答”得到的四个数。DPO 不直接比较 $p_w$ 与 $p_l$，而是先分别减去对应 reference 值，问训练相对起点改变了多少。

Insight 02

低概率不等于坏回答，变化方向才是 DPO 的坐标

一段正确但罕见的技术回答可能有很负的序列 log-prob。reference 也会感受到它的长度和罕见词；比较 policy 相对 reference 的变化，比只看绝对概率更接近“这次训练把它往哪推”。

记忆四数法：当前模型两条、参考模型两条；各自相减，再做 chosen 减 rejected。
