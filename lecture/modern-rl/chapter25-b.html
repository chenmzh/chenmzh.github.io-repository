05具身 RL：摄像头看到的是 observation，不是完整 state

机械臂仿真可以直接给关节与物体位姿；第一人称智能体通常只有眼前一帧。两者都在“环境中行动”，信息条件却不同。

在完全可观测的 MDP 中，策略可以写成 $\pi(a_t\mid s_t)$。若真实世界状态 $s_t$ 只通过观测模型产生画面 $o_t$，问题更接近 POMDP（部分可观测马尔可夫决策过程）：

$$o_t\sim O(\cdot\mid s_t),\qquad h_t=(o_0,a_0,\ldots,o_t),\qquad a_t\sim\pi_\theta(\cdot\mid h_t).$$

$s_t$ 可含场景几何、目标位置与智能体姿态；$o_t$ 只是当前 RGB、深度或本体感觉；$h_t$ 是到此刻的观察—动作历史。策略用循环状态、记忆模块或 frame stack 压缩 $h_t$，本质是在补足单帧没有透露的信息。

AI2-THOR 教学环境的策略输入只有第一人称 RGB；目标距离来自环境 metadata，只用于奖励塑形与成功判定，不能误写成策略直接看到的状态变量。

先从一条可核对的导航奖励看“环境知道、策略不知道”

上游 AI2-THOR 包装器用距离变化鼓励接近目标，每步另扣时间成本，动作失败再扣分，满足可见且距离不超过 1.25 时给成功奖励：

$$r_t=0.3(d_{t-1}-d_t)-0.005-0.02\,\mathbf 1[\text{action failed}]+5\,\mathbf 1[\text{success}].$$

若杯子距离由 $3.0$ 降到 $2.5$，动作成功但尚未到达，$r=0.3(3.0-2.5)-0.005=0.145$；若动作失败且距离不变，则 $r=0-0.005-0.02=-0.025$。成功时若距离再缩短 $0.2$，则 $r=0.3\times0.2-0.005+5=5.055$。奖励函数能读取距离，不代表策略的 RGB 输入包含这项数值。

Insight 03

奖励的“上帝视角”不能偷偷变成策略的特权信息

仿真器可以知道目标在墙后两米，并据此给塑形奖励；第一人称策略仍要靠转头、移动与记忆推断方向。把 metadata 拼进 observation，会把一个 POMDP 悄悄改成更容易的 MDP。

报告结果前先列 observation contract：训练时谁能看见什么，比算法名称更能解释难度。

06四个具身实验不是排行榜，而是四种建模角色

固定上游把 PPO 接到四套环境。真正有教学价值的不是重复“都能训练”，而是用它们覆盖连续控制、离散第一人称动作、长任务与多样仿真接口。

Question
都套着 PPO 的实验，是否就拥有相同的 state、action、horizon 与奖励难题？
Prediction
不会。算法外壳相同，环境契约仍决定探索空间、部分可观测程度和成功信号离当前动作多远。
Experiment
逐一读取固定提交中的环境包装器、默认任务与动作定义，把四套实验按“策略看什么、怎样行动、任务为何难”对齐，而不比较未经统一协议的回报数值。
Observation
ManiSkill 给状态向量与连续机械臂控制；MineStudio 给第一人称 RGB 和压缩后的离散键鼠动作；Unity ML-Agents 覆盖短离散控制到长程连续关节控制；AI2-THOR 给第一人称 RGB 与六个离散导航动作。
Interpretation
“具身 RL”至少横跨本体状态控制、视觉导航、开放世界事件与多任务物理仿真。一个平均 reward 无法说明智能体究竟解决了哪类闭环。
Limitation
这是代码契约的静态对照，不是同预算、同观测、同奖励下的基准测试；四组训练曲线不能直接横向排名。

07视觉生成：最终画面之前，策略已经走完一条去噪轨迹

扩散模型从噪声 $x_T$ 出发，逐步采样更干净的潜变量。若只把最终图片当作一个 action，就看不见 RL 真正需要更新的转移概率。

reward vector（奖励向量）把提示词对齐、画面质量、时序一致性与物理可信度等互不等价的终点评分分别保留；后续若要得到标量训练信号，必须显式声明各分量的尺度与权重。

$s_t$潜变量 $x_t$$p_\theta(x_{t-1}\mid x_t,t,c)$
重复去噪
$s_0$潜变量 $x_0$解码为图像 / 视频

REWARD VECTOR对齐 · 质量 · 时序 · 物理通常到终点才完整可测

这里的 action 不是“向左走”，而是下一潜变量样本。视频还多一条帧间时间轴，因此画面质量高不等于运动连续、物理可信。

令状态、动作与整条轨迹分别为：

$$s_t=(x_t,t,c),\qquad a_t=x_{t-1},\qquad \tau=(x_T,x_{T-1},\ldots,x_0).$$

给定初始噪声与条件，轨迹概率由每一步反向转移相乘：

$$p_\theta(\tau\mid c)=p(x_T)\prod_{t=1}^{T}p_\theta(x_{t-1}\mid x_t,t,c).$$

若最终解码结果得到标量化奖励 $R_{\mathbf w}=\mathbf w^\top\mathbf r$，最大化 $J(\theta)=\mathbb E[R_{\mathbf w}]$。用 log-derivative trick 展开轨迹概率，并减去不改变期望梯度的 baseline $b$：

$$\begin{aligned} \nabla_\theta J &=\mathbb E_\tau\!\left[(R_{\mathbf w}-b)\nabla_\theta\log p_\theta(\tau\mid c)\right]\\ &=\mathbb E_\tau\!\left[(R_{\mathbf w}-b)\sum_{t=1}^{T}\nabla_\theta\log p_\theta(x_{t-1}\mid x_t,t,c)\right]. \end{aligned}$$

第一行说明“高于 baseline 的样本应更可能出现”；第二行把整条轨迹的 log-prob 拆回每次去噪。于是终点评分能够训练所有步骤，但也把同一个 advantage 广播给整条链——奖励仍然延迟，精确归因仍然困难。

Insight 04

扩散 RL 的 action 是“下一潜变量”，不是最终图片

图片只是轨迹的可见终点。Denoising Diffusion Policy Optimization（DDPO，去噪扩散策略优化）把每次去噪视为策略动作；它与一般 policy-gradient 式更新之所以能工作，是因为每一步都有可计算的 transition log-prob，终点 advantage 才能回乘到整条链。

先写轨迹概率的乘积，再谈 PPO、GRPO 或 importance ratio；否则算法名会遮住被优化的随机过程。
