Chapter 23 · Pixels become actions with consequences

像素、鼠标与不可逆操作如何训练？

上一章的浏览器实验台还能告诉 Agent“这是搜索结果”“这是正文”“这条引用来自哪个 URL”。直接操作软件界面更接近人在电脑前看到的世界：模型得到一张截图，只能输出鼠标、键盘、滚动或等待。一个坐标偏差可能只是点空，也可能把“保存草稿”变成“立即发送”。

本章核心问题：怎样把像素观察与带坐标、文字等参数的界面动作写成可训练轨迹？当动作会发信、删文件或转账时，为什么普通探索奖励不够，还必须加入授权检查、安全中止和高风险确认？

01工具名消失以后，Agent 先要从像素里找出“什么能做”

Chapter 22 的 open(url) 已经声明动作语义；图形界面里没有 submit_form()，只有一张图和可以注入系统的鼠标键盘事件。

Graphical User Interface（GUI，图形用户界面）把软件能力放在窗口、按钮、菜单和画布里；策略没有结构化 API 时，只能通过人类也能使用的可视界面行动。

真正的闭环不是“看见按钮 → 点击”，而是“识别目标 → 定位 → 执行动作 → 验证界面是否按预期变化”；缺少最后一步会把误点继续传播。

Computer Use（计算机操作）把操作系统或应用界面当作 Agent 环境。最基本的视觉观察是一张截图：

$$o_t\in[0,255]^{H\times W\times 3}.$$

$H,W$ 是画面高宽，3 表示红、绿、蓝三个颜色通道。这个矩阵能保留按钮颜色和文字形状，却没有直接告诉策略哪个矩形可以点击、哪个文本来自用户、哪个弹窗遮住了底层控件。Vision-Language Model（VLM，视觉语言模型）必须把视觉理解、任务规划和动作生成接到同一条轨迹里。

02同一张截图，背后可能是两个不同状态

截图只记录采样瞬间。网络请求、焦点、剪贴板、后台上传与权限状态可能不可见，因此 GUI 更像 Partially Observable Markov Decision Process（POMDP，部分可观测马尔可夫决策过程）。

VISIBLE PIXELS

按钮灰色、页面未跳转

两张截图肉眼几乎相同。

HIDDEN STATE A

请求仍在发送

正确动作是 wait；再次点击可能重复提交。

HIDDEN STATE B

点击没有命中

正确动作可能是重新定位并点击。

相同像素不保证相同系统状态；上一动作、等待时间和后续观察能帮助区分“正在处理”与“根本没点中”。

策略因而不应只条件化在当前单帧，而要利用有限历史：

$$a_t\sim\pi_\theta(a_t\mid q,o_{1:t},a_{1:t-1}).$$

$q$ 是用户目标，$o_{1:t}$ 与 $a_{1:t-1}$ 共同提供状态线索。工程上可以保留最近几张截图、动作后的预期变化和结构化工作记忆。历史越长并非越好：视觉 token 很快挤满上下文，所以要保留对后续判断真正有用的变化。

Insight 01

截图是 observation，不是完整 state

“页面看起来没变”可能对应等待、误点、网络失败或弹窗遮挡。策略要用动作历史和下一帧变化更新自己对隐藏状态的判断。

GUI Agent 的记忆首先服务于状态判断，而不只是保存更长的自然语言思考。

03GUI 动作不是一个标签，而是“动作类型 + 参数”

click 是离散选择，坐标却是连续或高基数参数；type 还要生成字符串，drag 要同时给出起点和终点。

$$a_t=(k_t,\eta_t),\qquad k_t\in\{\text{click,type,scroll,key,wait,done}\}.$$

$k_t$ 是动作类型，$\eta_t$ 是该类型所需参数。不同类型的参数空间不同：点击需要 $(x,y)$，输入需要文本，等待需要时长。最小公共动作空间可以写成：

ACTIONS = {
    "click":  {"x": int, "y": int, "button": "left|right"},
    "drag":   {"start": [x, y], "end": [x, y]},
    "type":   {"text": str},
    "key":    {"keys": "cmd+c|enter|tab"},
    "scroll": {"x": int, "y": int, "dy": int},
    "wait":   {"ms": int},
    "done":   {"summary": str},
}

一个坐标换算

模型常输出归一化坐标 $(u,v)\in[0,1]^2$，执行器再按当前截图尺寸换成像素。因为像素下标分别只到 $W-1$ 与 $H-1$，端点必须映射到最后一个有效像素：

$$x=\operatorname{round}\!\big(u(W-1)\big),\qquad y=\operatorname{round}\!\big(v(H-1)\big).$$

若模型预测 $(u,v)=(0.65,0.72)$，截图为 $1440\times900$，那么：

$$x=\operatorname{round}(0.65\times1439)=935,\qquad y=\operatorname{round}(0.72\times899)=647.$$

如果部署时窗口缩放了，却把训练分辨率下的绝对坐标原样执行，动作会系统性偏移。轨迹必须保存原始截图尺寸、归一化坐标与最终执行坐标。

Insight 02

“动作格式正确”与“动作落点正确”是两道验证

click(935,647) 可以完全合法，却点到错误元素；坐标正确也可能在不该提交的时机执行。

定位误差、规划误差和时机误差必须分开记录，否则一个零奖励无法告诉我们该补哪种数据。

04把“点击提交”落到一个可执行区域

visual grounding（视觉定位）把语言提到的界面对象映射为区域或坐标。它解决“在哪里”，但不单独解决“现在是否该做”。

Set-of-Mark（SoM，标记集）先由检测器给可交互元素编号，再让策略选择编号；direct coordinate（直接坐标）则让策略直接预测归一化位置。两者都在回答“目标在哪里”，只是把定位误差放在不同模块。

SET-OF-MARK

先给元素编号，再选择编号

检测器把输入框、按钮和图标标成 1、2、3；策略输出 click(3)。动作更离散，但检测器漏标后策略无从引用。

DIRECT COORDINATE

视觉语言模型直接生成坐标

模型联合生成思考、动作类型与 $(u,v)$。接口更统一，却需要大量跨分辨率、遮挡和小元素定位数据。

两条路线真正比较的是误差放在哪里：Set-of-Mark 把一部分定位交给外部检测器；端到端坐标把误差留在策略模型内部。二者都需要任务级反馈判断“该不该点”。

若标注点为 $p_i$、模型预测为 $\hat p_\theta(o_i)$，最简单的坐标监督损失是：

$$\mathcal L_{\mathrm{ground}}=\frac1N\sum_{i=1}^N\left\lVert\hat p_\theta(o_i)-p_i\right\rVert_2^2.$$

这一步适合 Supervised Fine-Tuning（SFT，监督微调），能建立基本点击能力；完整任务仍要在可重置环境中学习动作怎样改变下一张截图。否则模型可能非常准确地点击一个与当前子目标无关的按钮。
