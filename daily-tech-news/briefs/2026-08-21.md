# 每日科技新闻简报｜2026-08-21

## 今日最重要的 3 条

### 1. Anthropic 将 Computer Use、Skills API 和 Files API 正式推向 Claude Platform

Anthropic 8 月 20 日宣布，Computer Use、Skills API 和 Files API 在 Claude Platform 正式可用；Computer Use 还增加了 Browser Use 工具，让代理读取网页结构并执行点击、输入和滚动。Skills API 可以上传并版本化团队自己的指令、脚本和模板，在 Claude 的代码执行沙箱中按需加载；Files API 则让代理把文件上传一次、后续通过 ID 反复读写。Skills/Files API 也已通过 Microsoft Foundry 提供，更新后的 Computer Use 和 Browser Use 将陆续进入 Google Cloud Vertex AI。

**重要性：** 这次发布把“看见软件并操作它”“加载组织知识”“读写工作文件”组合成一套更完整的生产代理栈。代理落地的竞争焦点将从模型回答质量，进一步转向浏览器操作可靠性、权限边界、文件生命周期、审计和能否接入没有 API 的旧系统；Anthropic 披露的 HIPAA 资格、5 倍 Files API 限流和每组织 1 TB 存储等能力，说明其目标已从演示转向受监管的企业工作流。

来源：[Anthropic 官方公告](https://claude.com/blog/computer-use-skills-api-files-api)

### 2. 阿里巴巴 AI 云与计算业务加速增长，但 AI 基础设施投入显著挤压现金流

阿里巴巴 8 月 20 日公布截至 6 月 30 日的季度业绩：AI Cloud and Compute Services 收入为 484.37 亿元人民币，同比增长 45%；AI 相关产品收入为 123.76 亿元，连续第 12 个季度保持三位数同比增长。集团总收入同比增长 9% 至 2689.53 亿元，但净利润降至 104.44 亿元、同比下降 75%；季度资本开支为 676.78 亿元、同比增加 75%，自由现金流为净流出 446.70 亿元，主要与云基础设施投入有关。公司同时披露自研芯片、异构芯片集群、Qwen 模型和 QwenWork 等业务正在被纳入同一 AI 基础设施与应用体系。

**重要性：** 这组数据把 AI 云业务的高增长与算力建设的高资本消耗放在了同一张财务报表上。AI 基础设施仍可能是收入增长最快的部分，但短期盈利、现金流和产能采购会承受更大压力；接下来应关注 AI 相关收入能否持续覆盖折旧、芯片采购、数据中心建设和模型服务成本，而不能只看收入增速。

来源：[阿里巴巴官方业绩公告](https://www.alibabagroup.com/en-US/document-2026456290057781248) · [官方业绩 PDF](https://data.alibabagroup.com/ecms-files/1532295521/fa5d65fc-9b3e-4e82-a8fc-4ce1c3e2c407/Alibaba%20Group%20Announces%20June%20Quarter%202026%20Results.pdf) · [Reuters 转载报道](https://ae.marketscreener.com/news/alibaba-profit-falls-75-after-ramping-up-ai-infrastructure-spending-ce7859d3d98eff26)

### 3. 美方联合通告称，攻击者正用 AI 辅助脚本测试暴露的 Siemens S7 PLC

美国联邦调查局 IC3 页面发布的联合网络安全通告称，攻击者使用 Censys、ZoomEye 等互联网扫描服务寻找暴露或分段不足的 Siemens S7 系列可编程逻辑控制器，并用 AI 生成的 Python 脚本与 `snap7.dll`/`python-snap7` 伪装成合法监控工具。通告称这些工具可通过 S7comm 读取或写入 PLC 内存、配置和梯形图逻辑，相关活动重点涉及关键制造、能源、水务、化工、食品农业和商业设施。通告建议立即盘点 S7-200/300/400/1200/1500 设备、安装关键补丁、移除互联网暴露、强化密码与访问控制并监测异常写入；官方文件编号为 260819、正文标注 2026 年 8 月，但未给出具体发布时间，8 月 20 日已有媒体继续跟进。

**重要性：** 这表明生成式 AI 对网络攻击的影响正在从生成钓鱼文本，扩展到面向工业协议和 OT 设备的可执行工具开发。即使攻击者仍需要真实的 PLC 暴露面、凭据和工艺知识，AI 已经降低了定制化扫描、读写测试和伪装工具的门槛；工业网络隔离、默认凭据清理、工程工作站管控和梯形图完整性需要与传统 IT 防御同等优先。

来源：[IC3/NSA/CISA/FBI/DOE/EPA 联合网络安全通告](https://www.ic3.gov/CSA/2026/260819.pdf)

### 软件 / 云 / 开发者工具

**Rust 官方确认 crates.io 出现短时供应链攻击，涉及 `arrayref` 等常用 crate。** Rust 安全响应团队称，恶意 `proc-macro1` crate 的构建脚本会下载恶意载荷；被重新发布并依赖该 crate 的 `arrayref@0.3.10` 在线约 86 分钟，`append-only-vec@0.1.9` 和 `internment@0.8.7` 也受到影响，相关版本随后被删除。Rust 官方建议开发者检查本地依赖缓存，尤其是 8 月 20 日 07:15 UTC 之后获取的相关版本；LWN 的跟进报道也称 Rust 已删除恶意版本并锁定疑似受影响的账号。

来源：[Rust 官方安全通告](https://blog.rust-lang.org/2026/08/20/supply-chain-attack-on-arrayref/) · [LWN 跟进报道](https://lwn.net/Articles/1089720/)

**Cloudflare 同日提高 Browser Run 并发上限，并增加 OAuth 最小权限与 Basic Auth 泄露检测。** Cloudflare 的 8 月 20 日更新把 Browser Run 并发浏览器数从 120 提高到 200，把新浏览器实例速率从每秒 1 个提高到 3 个，并把 Quick Actions 速率从每秒 10 次提高到 30 次。其 OAuth 客户端现在可把配置的 scope 标为必需或可选，WAF 的泄露凭据检测也默认检查 HTTP Basic Authentication 的 `Authorization` 头；后两项变化分别面向代理/CLI 的最小权限和凭据暴露面。

来源：[Cloudflare 官方 Changelog](https://developers.cloudflare.com/changelog/)

### 科研 / AI for Science

**Nature 报道 AI 工具尝试提前识别更可能走向专利的科研论文。** Nature 介绍的 Translation Readiness Index 用论文标题和摘要的语言特征，与既往“论文—专利”配对数据比较，训练集包含 20,610 篇论文，其中 9,431 篇与专利匹配；文章称最佳分类器在排序任务中的概率约为 78%。该方法的原始工作仍是尚未同行评审的 arXiv 预印本，而且“更像专利”不等于技术已经可商业化，因此更适合作为科研转化筛选信号，而不是投资或专利价值的确定性预测器。

来源：[Nature 报道](https://www.nature.com/articles/d41586-026-02549-7) · [相关 arXiv 预印本](https://arxiv.org/abs/2606.31102)

## 今日趋势

- **代理产品正在从聊天界面进入执行层。** Computer Use、Browser Use、Skills、Files 和异构推理编排分别覆盖操作、知识、文件与算力调度，代理的核心竞争开始转向可靠执行、权限治理和可观测性。
- **AI 云增长与基础设施现金消耗同时加速。** 阿里巴巴的 AI 云收入增长与资本开支、自由现金流变化并存，说明模型服务商业化的下一阶段要回答的是单位经济性和回本周期，而不仅是客户数量或调用量。
- **AI 辅助攻击正在触及工业控制和真实设备。** Siemens S7 通告说明，模型生成能力与互联网暴露的 OT 资产、默认凭据和工程工具结合后，会把传统工业网络的防护短板转化为更快的攻击迭代。
- **软件供应链和身份权限仍是代理基础设施的共同底座。** Rust crate 攻击利用构建阶段执行代码，Cloudflare 则从 OAuth scope 和 Basic Auth 头部收紧权限与检测；依赖来源、构建隔离、密钥暴露和最小权限会一起决定 AI 工具链的安全边界。
- **AI for Science 的价值评估从“能不能生成”转向“能不能转化并复现”。** Nature 报道的专利潜力评分可以帮助筛选，但未同行评审和“专利相关性不等于商业可行性”两点，提醒人们不要把模型排名直接当作科研质量或投资回报。
